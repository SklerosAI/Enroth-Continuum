Status: **retained-data/owned-guide/source audit, not a working hireling claim** (2026-11-05). ## Denominator and join

The owned Prima NPC chapter's **four relevant PDF pages, 250–253, were directly rendered and visually checked**. It names **51** benefit-bearing hireling professions. All 51 names join exactly and in order to the first 51 retained `npcprof.txt` rows. The guide's up-front costs match the retained fee field for **50/50** ordinary-cost rows. The final guide entry explicitly has no up-front cost but takes a gold share; the retained fee field supplies the share basis and [NPCTopics.cpp](../src/GUI/UI/NPCTopics.cpp) skips the up-front charge. That is a resolved representation difference, not an implementation defect.

The retained table has **77/77 numeric profession rows**. Its remaining **26** rows do not occur in the guide's 51-name list and have no action or benefit text, but all have join text. The retained `npcdata.txt` copy contains **70** NPC records referencing this range, of which **40** carry a `canJoin` flag across **20** IDs. A flag alone does not prove these NPCs reach a paid-hire dialogue: scripted versus generated NPC dispatch and quest-following need separate joins. These rows are **generic/guide-unlisted**, not safely “nonhireable.” The ignored ledger records every row and every observed NPC reference without exposing that mapping in Git.

Separately, event-variable code can set hired flags and the new-party path copies original NPC data into mutable state, so quest-following and later topic/house changes remain open. ## High-priority mismatches and uncertain claims

1. **Numeric aliasing beyond the guide range.** Seven generic MM6 rows occupy numeric IDs that the inherited MM7 enum treats as special professions. Current [NPC.cpp](../src/Engine/Objects/NPC.cpp), [Character.cpp](../src/Engine/Objects/Character.cpp), [Party.cpp](../src/Engine/Party.cpp), and [UIDialogue.cpp](../src/GUI/UI/UIDialogue.cpp) can interpret those IDs as spell, skill, or reputation effects. This is a source-level title collision; actual reachability still depends on hiring/dialogue. The other generic IDs have no matching named enum/effect and need bounded, display-safe handling.
2. **Guide versus retained data.** The guide's Navigator boat reduction and Scout perception bonus each differ from the retained benefit text and inherited C++ consumer. The retained values and source agree with each other, but the guide disagreement is unresolved; do not silently choose either as original behavior. The guide describes the Enchanter's elemental protection as a percentage while retained text and source use an unqualified 20-point bonus, so the unit needs observation or an independent primary rule source.
3. **Guide/data versus inherited effects.** The guide and retained text describe Arms Master and Weapons Master as boosting weapon skills; inherited [Character.cpp](../src/Engine/Objects/Character.cpp) boosts the MM7 Armsmaster skill. The guide/data magic apprentices affect spell skills broadly, while that consumer covers only elemental schools. The Master Healer guide/data describe all conditions, while [NPC.cpp](../src/Engine/Objects/NPC.cpp) excludes eradication. Bard, Squire, and Negotiator have guide/data benefits absent from corresponding inherited effect paths. Two guide/data Diplomacy professions are interpreted as different MM7 professions and receive Alchemy bonuses in the inherited skill consumer. The Acolyte's numeric alias has a similar active spell but needs MM6 display and duration validation.
4. **Reputation, commission, and item interaction.** The inherited code has some reputation and gold-share paths, but MM6 reputation categories, discount consequences, fee rounding, special free-entry share, item repair/identification eligibility and every once-per-day reset have not been verified against a running MM6 title.
