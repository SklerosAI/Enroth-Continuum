# MM6 chest live-owner adapter — guarded F4 seam

Status: **opt-in adapter staged and native-tested; the global MM6 load guard remains closed** (2026-11-06). `Engine::_461103_load_level_sub()` still invokes `mm6::generateChestItemsForTitle(gameTitle())`, which rejects MM6 before inherited chest, RNG or artifact mutation. No installed MM7/MM8 runtime or `SaveLoad` path changed.

## Title-local state and active map owners

`mm6::ChestTitleState` owns the original chest generator's 32-bit LCG state and thirty generated flags for IDs 400–429, separate from the current Mersenne Twister `grng` and MM7-indexed `Party::isArtifactGenerated`. Its process accessor starts **unready**. `restoreChestTitleState` validates an MM6 title and binary flags before setting it; `resetChestTitleState` clears it. Neither new-game initialization nor `.ec6` restore currently calls these APIs, so the active adapter fails closed by default. The caller must also supply party-owned 400–429 flags from an MM6-validated source.

The opt-in `initializeNewGameChestTitleState` accepts an explicit 32-bit deterministic seed, clears generated flags and rejects a foreign title, missing/already-ready owner or unverified seed source without mutation. Zero is a valid LCG state. Retained generator and picker traces establish the LCG **step**, but contain no proved new-game seed source. For this personal port, `initializePortNewGameChestTitleState` now supplies a clearly labelled **port-specific policy**: draw one 32-bit value from local `std::random_device` at new-game start, initialize only an unready MM6 owner, then rely on `.ec6` CHST to persist the evolving state. It accepts an injected entropy provider for deterministic tests; missing/throwing entropy leaves the owner unchanged, and an already-ready owner never draws again. This helper has no live new-game caller yet and never reseeds on map load or save restore. The original initial seed remains unknown; no value is inferred from `grng` or platform time. `scanPartyOwnedChestArtifacts` visits each occupied item record in all four live character inventories, including equipment, and the held cursor item. It marks only IDs 400–429, rejects MM7, and avoids the original unsafe raw-memory scan and non-artifact ID 430. The explicit flag argument of the live adapter is not yet automatically supplied by this helper.

`mm6::applyActiveChestLiveOwnerHandoff` is an opt-in bridge to actual `vChests` and the currently loaded `pIndoor->mm6DeltaBytes` or `pOutdoor->mm6DeltaBytes`. For indoor maps it builds the bounded base shape from the current door-data size. The reusable binding form accepts the same owners explicitly for offline tests. It parses the current decoded DLV/DDM sidecar, requires exactly twenty 4,204-byte chests and checks that the existing runtime chest snapshots match each raw record's header, first 24 item bytes and all 140 grid cells. This rejects a stale or diverged runtime before generation.

The adapter then runs the [atomic twenty-record handoff](MM6_F4_CHEST_MAP_LOAD_HANDOFF.md), patches only chest records in a copied delta sidecar and revalidates its full layout. Indoor and outdoor opaque sections remain byte-preserved. Only after generation, all twenty `Item`/`ChestInventory` projections and sidecar encoding succeed does it swap the new `vChests` vector and map sidecar into place and copy the LCG/artifact state. All mutating swaps are compile-time `noexcept`; a malformed last chest, unready/foreign title, bad flags, stale runtime or failed decode leaves every bound owner untouched. The adapter is not called from the guarded load path.

## Verification and limits

Focused arm64 native tests cover indoor and outdoor commits, opaque-sidecar preservation, artifact publication, failure after a late chest projection, stale-runtime rejection, unready/MM7 rejection and state restoration bounds. An optional retained-data case read only the ignored decoded F3-backed map baselines and staged all **52 indoor and 15 outdoor** sidecars after reconstructing their baseline runtime chest vectors. It uses a synthetic item table and one-cell footprints, so it proves record shape and owner matching, not exact original loot or real item dimensions. No MM6 game process or original GOG installation was opened.

The `.ec6` owner contract remains open: its save/new-game transaction must call the port-specific initializer once, capture/restore/reset `ChestTitleState`, including `ready`, LCG state and thirty generated flags, together with the changed active-map sidecar and `vChests`. It must supply validated party-owned flags to the adapter at map entry. On save–quit–relaunch–load, generated contents must not reroll or lose placement, loot pickup or flags. Until that whole transaction is proved, leave `generateChestItemsForTitle` closed. First-open `Chest::open`/`PlaceItems`, title-specific icon sizing, traps, gold/cursor pickup and GUI presentation are separate blockers; see the [interaction gate](MM6_F4_CHEST_INTERACTION_GATE.md) and [save checklist](../.llm-wiki/MM6-F4-Save-Transaction-Checklist.md).
