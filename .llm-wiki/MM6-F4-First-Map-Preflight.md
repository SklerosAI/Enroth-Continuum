# MM6 F4 First Map Preflight

The [public packet](../project/MM6_F4_FIRST_MAP_PREFLIGHT.md) traces new-game startup through the first outdoor loader and records a read-only headless resource preflight.

`Game::loop()` sets `oute3.odm` as the MM6 pending transition and calls guarded `saveNewGame()` before `gameLoop()`. The later `DoPrepareWorld()` path reads map events/strings, dispatches to the outdoor loader, reconstructs the base and a `.ddm` from `pMapDeltas`, and then reaches the still-guarded MM6 chest generator. The test checks the map-table dispatch, base/delta and event resources, the parsed reload-trigger count, minimap icon, one MM6 loading background, and a detached base-map sky field and bitmap. It does not enter the map, execute events or write a save.

The retained MM6 archive has a single full-screen loading background. `fullscreenLoadingResources` selects it only for MM6 and omits MM7's absent progress-strip texture; the MM7 variation and progress lookup remain exact. MM6's later boxed loading view has its background but no `turnhour` animation, so it skips that image rather than indexing an invalid animation ID. The first outdoor base map names an available sky bitmap. `OutdoorLocation::Load` now preserves a nonempty MM6 base sky name instead of replacing it with the unavailable MM7 default; the later outdoor setup and weather initialization do not overwrite its loaded pointer. This is proved for the first map only; other outdoor maps may need a title-specific sky fallback.

The first MM6 map's numeric ID aliases MM7 `MAP_SHOALS`. The inherited MM7 hireling block incorrectly hid follower UI and stopped dialogue, specialties and a spell route. All five consumers now use a title-aware helper: MM6 avoids this MM7 restriction, and MM7 retains it. Any genuine MM6-only restriction needs separate evidence.

The first-map reload program contains sprite changes. MM6 `SetSprite` addresses a zero-based decoration index, while MM7 resolves `uCog`. The MM6 MapSprite record has no MM7 cog field; the inherited setter silently missed its targets. `EvtInterpreter` now applies a bounded index change for MM6 and leaves MM7's cog route intact. The detached preflight checks original reload sprite targets against decoded map-decoration count, and a pure test checks index, visibility, replacement and title isolation. Source: [pinned GrayFace MMExtension MM6 MapSprite and `evt.SetSprite` definition](https://github.com/GrayFace/MMExtension/blob/9d73c0ff0482bd231ea522f752f4fe9b26640925/Scripts/Structs/01%20common%20structs.lua#L1943-L1981). Execution and appearance remain unaccepted until the live map gate opens.

Each reload entry compares a supported MM6 map byte or quest bit before branching to a sprite or facet change. The other reload branch uses MM6 opcode 12 as an outdoor facet texture operation. Current MM6 parsing and interpretation already use model/facet operands and a checked outdoor-face lookup; the MM7 movie path is retained only for MM7. A detached preflight checks branch shape, operand classes, target bounds in decoded first-map models/faces, and bitmap availability. It does not establish which branch fires on a fresh save or how the replacement looks.

A monitored headless map-load attempt reached `SpawnEncounter` and found an MM7-spaced name instead of an MM6 monster identity. MM6 map encounter cells can identify an internal family stem or a variant's displayed name; the retained MM6 text and binary descriptor tables use compact internal rank suffixes and aligned row IDs. `resolveEncounterMonster` now matches a compact internal rank first, then a unique displayed family, and rejects missing/ambiguous identities. `SpawnEncounter` preflights the MM6 descriptor before actor allocation; MM7's string lookup stays intact. The detached first-map test checks both encounter families and all three ranks against loaded stats/descriptors. A later retained map label differs from its unique display-family name only by word spacing; the MM6 display comparison now ignores spaces, with a detached source check. A private full-map label sweep leaves five distinct later-map labels unresolved or ambiguous, so broader encounter acceptance remains gated. No original monster roster is published here.

Two of the five later-map labels collide across multiple displayed monster families; three have no unique internal or display-table match. Fail closed on all five until their original identities are established. The explicit in-memory first-map `loadAndPrepareODM()` headless scenario now passes in the linked arm64 GameTest. It supplies `DoPrepareWorld`'s AI scratch-array precondition, drains nested loading-progress presents with a bounded test-only tick loop, and asserts the outdoor map ID/type, faces and spawnpoints. The host focus/window monitor observed 135 samples with no focus change and no on-screen process window. It does not call the guarded chest generator, execute reload events, render a graphical world frame or write a durable save. One MM6 voice-index warning was nonfatal. A broader `DoPrepareWorld()` scenario remains the next gate.

An isolated full-world GameTest is staged with a first-map pending transition, ready in-memory CHST state and `ScopedChestMapLoadOptIn` around `DoPrepareWorld()`. It checks the single GUI-window precondition and actor/chest/map state after a bounded loading-present drain. Linked monitored execution is pending. Normal chest and save guards stay closed; this test does not make all world globals transactionally rollback-safe.

The save transaction must populate `pMapDeltas` before load; the guarded chest generator then must finish. Reload-event execution, actor/item spawns, HUD, music, first frame and durable save/reload remain unaccepted. The linked headless preflight checks resources, the detached event parse and sprite-index bounds; graphical play needs the later F5 pass.
