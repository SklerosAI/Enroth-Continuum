# MM6 detached known-save stage coordinator — F4

Status: **offline partial owner stage; no live SaveLoad entry or commit** (2026-11-06).

`stageKnownWorldAndVisuals()` accepts a title-specific `.ec6` byte candidate, the locally verified 67-name manifest, a trusted MM6 base-map reader, a loaded MM6 item-template verifier, current NPC/timer/overlay owners, and the loaded overlay-table size. It first decodes all eighteen currently required sections and checks their cross-field clocks, active-character selection and active map companion. It then decodes every MM6 base/delta pair and verifies nonempty ground and positive chest item template references; the six chest random-item markers remain a separate accepted identity class. The active map's decoded base and delta are retained as an owned, typed indoor or outdoor candidate from that same pass. Only after all 67 pass does it copy-stage NPC records/groups and map buffers, followed by a paused simulation timer and 50 overlays. A failure at any point returns no staged result and assigns no caller-owned state. The caller supplies a trusted source; this function does not read files or select a save slot.

`stageKnownSession()` wraps that boundary and composes the seven existing Party-family adapters on one detached Party in core, durable, resistance, buff, hireling, held-item and recovery order. `captureKnownPartyFields()` likewise merges their existing live capture adapters into a complete known-section seed, then validates the current manifest. Captures still require an initialized MM6 engine. Detached stage adapters accept an explicit MM6 title without a live engine for offline verification; if an engine exists it must be MM6, and nonempty `ITEM`/`HELD` still need loaded item templates. A Party constructed without an engine now uses the gameplay config defaults and clears the held item without a UI cursor. This does not change initialized-runtime behavior.

After all represented Party adapters and SCLK validation succeed, the MM6-only detached session stage clears four inherited live-frame values: `_roundingDt` becomes zero, and the delayed-reaction timer, speech and character ID become zero/`SPEECH_NONE`/`-1`. `_roundingDt` is the one-tick half-speed recovery remainder consumed and recomputed by the next simulation frame; carrying the prior process's remainder would change saved character recovery by a tick. Indoor and outdoor map entry already cancel the delayed reaction timer, and its remaining speech/character fields have no reader while that timer is zero. Clearing the complete tuple on the detached candidate makes the reset policy explicit before map entry. The saved recovery durations, daily counters and RCVR v3 Armageddon tuple remain intact. This does not clear a live Party, permit queued actions, or supply a no-reentry commit boundary.

The result contains the validated `KnownSaveFields` value, an owned typed active-map candidate, staged Party and SCLK clocks, NPC/map and timer/overlay copies. This is an intermediate transaction boundary, not a complete session. It does **not** check the `HEAD` map against a loaded MM6 table/archive, instantiate the active indoor/outdoor world, rebind overlay PIDs to reconstructed actors/objects, re-create the held-item cursor, clear pending actions, or perform a no-throw global swap. `CHAR` v4 preserves the eight current-runtime bonus bytes verbatim; their native MM6 meaning and reset policy remain unproved. Active Lloyd beacons now reject capture and stage until map identity and image restoration are defined. The inherited MM7-indexed shop/guild/bounty arrays also reject capture and stage when their clocks, stocks, targets, flags or zero-ID slot payloads are nonempty. This is a fail-closed preservation boundary, **not** a title-specific SHOP/bounty codec. **Unrepresented durable fields** include MM6-keyed shop/guild stock and ban state, house-keyed bounty state and alignment. SCLK preserves the source-proven refresh clocks, PART v3 preserves movement/flight/fall and current-runtime fine/death/prison/bounty counters, RCVR v3 preserves recovery and current-runtime Armageddon state, and CHST preserves the title-local chest generator ledger. Character previous face/voice are a future fidelity question because current condition consumers are inactive for MM6. Pending turn/rest/action queues and cursor image/offset still lack a restore or reset policy. Live changed-chest-grid projection remains outside this transaction. Live `SaveLoad.cpp` must keep rejecting MM6.
