# MM6 item event transaction from original PE

Status: F4 bounded raw ID-17 write path, 2026-11-06. The owner-local MM6 executable was inspected read-only and matched the accepted F3 PE SHA-256. Exact code bytes, offsets and disassembly remain in ignored `local-game-data/mm6/research-2026-11-05`. No MM6 process was launched.

The [tracked PE checker](../scripts/mm6_f4_check_item_event_pe.py) validates the owner-local executable against the accepted F3 report, then follows the original opcode and variable jump tables to Compare, Add and Subtract and checks their cursor/grid helper calls. The original Add initializes a 28-byte item to zero, sets the requested ID and identified flag, invokes the cursor setter, and marks the generated-artifact flag for MM6 IDs **400–429**. It does not call the inherited MM7 `Item::postGenerate`, so that path's random potion power and wand charges would be incorrect here. The cursor setter relocates a prior held item through active-character inventory, a four-character fallback, then a ground drop. The existing `Party::setHoldingItem` shares the empty-cursor result; its occupied-cursor fallback order differs, so that case stays guarded. The generated-artifact band is not represented by the current MM7-only flag array or durable `.ec6` state, so those grants stay guarded too.

The original Subtract dispatcher invokes the item removal for the selected character; party selection invokes it for all four characters. Within one character, it scans the **126 backpack grid cells** in linear order from 0 through 125 and immediately removes the first matching item. The current 14 × 9 inventory maps this to row-major order: top row before lower rows, left to right within a row. This priority follows the grid cell, not item-record creation order. If there is no grid match, the original removes a matching held cursor item; otherwise it leaves state unchanged. It does not stop the event on a miss. This differs from the inherited MM7 party-wide workaround, which ignores the selector. The MM6 implementation preflights selected characters, chooses each first grid match before cursor, and applies those removals after the selection is valid. Equipped items are not a Subtract source. For party selection, a held item can be consumed only once, while each character may independently lose one backpack item.

The bounded Add uses a zeroed identified item if the event targets one character and the ID is outside 400–429. With an occupied cursor, it preflights the held item's MM6 ID and size, tries the active character first, then characters 0–3 in order, and inserts an exact copy into the selected inventory before replacing the cursor. If no inventory has space, it rejects before mutation. The retained 290 Add instructions include **one generated-artifact-band operand** and **one explicit party-selected Add**; these are distinct sites. Thus 288 retained Add sites have eligible static operands/selector, subject to runtime inventory capacity if the cursor is occupied. All 156 retained Subtract sites have eligible static operands, including duplicate backpack states under the proven grid priority. MM6 Set ID 17 remains guarded because it has no active retained use. MM7 retains its original executor.
