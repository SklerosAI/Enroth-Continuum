## Evidence and coverage

The retained `spell-effect-probe.json` and private guide matrix each cover IDs 1–99; the probe's `items.txt` and `spells.txt` hashes match the accepted F3 original-file reconciliation. The inherited player effect path has a numeric case or direct branch for all 99 IDs, but case presence does not prove MM6 behavior. At the same numeric ID, 50 spell labels match, 21 occur at another ID and 28 are absent or renamed. The guide comparison marks 58 inherited same-ID implementations as conflicting and 41 as not demonstrated; none is verified as an MM6 effect. All 99 require title-specific target and Normal/Expert/Master behavior checks. The active retained scripts contain 129 spell-cast records using 15 IDs; the monster table has 55 populated spell cells, including 13 labels the inherited parser does not recognize. These counts are structural, not reachability or live-effect proof.

The guard is title-scoped: MM7 keeps its inherited behavior. Rejection currently raises a runtime error; it deliberately does not present a playable MM6 cast UI. An MM6 prequeue UI may still close or change selection before calling the queue, and ambient AI or attack state can change before a rejected cast is attempted. Those outer flows need explicit title-specific user-facing handling when spell effects are implemented. Sound/sprite mappings, projectile impact, quick-cast predicates, spellbook icons, portal/beacon, scroll and monster casting are not established by these guard tests. No graphical or audio cast was observed.

## Verification and exit criteria

The focused native tests assert rejection of IDs 1–99 from player, event, monster and damage sources, MM7 pass-through, and only the non-spell player pseudo actions. The private handoff script checks both F3 table hashes, writes all 99 ID rows and fingerprints its current source files without publishing proprietary rows. Before enabling any ID, establish its MM6 target, rank-specific effect, cost/recovery and failure timing, damage/resistance, audiovisual resources and persistence; add offline state tests for every source that can invoke it. F5 then requires visible cast/impact and save/quit/relaunch/load checks in an authorized complete game.
