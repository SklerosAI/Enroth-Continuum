# MM6 `.ec6` known-field assembly — F4 offline progress

Status: **revised partial candidate for eighteen required sections, not a final whole-save manifest or live save path** (2026-11-06). `CHST` and `SCLK` are provisional schema revisions; old seventeen/sixteen-section candidates reject before mutation. See [CHST transaction](MM6_F4_CHEST_EC6_TRANSACTION.md) and [SCLK clocks](MM6_F4_SHOP_GUILD_CLOCK_SAVE.md).

`MM6KnownSaveFields` assembles required `PART`, `CHAR`, `QEST`, `EFFT`, `ITEM`, `HEAD`, `TIME`, `UIST`, `VISU`, `MAPS`, `RESC`, `RSTS`, `HELD`, `BUFF`, `HIRE`, `RCVR`, `CHST` and `SCLK` sections in the title-tagged, CRC-checked `.ec6` container. Decode requires exactly these eighteen distinct required tags. It rejects optional extensions, including optional `META` and unknown tags, until there is an explicit preservation policy and a new manifest review. Each existing field codec validates its own version, length and range; the assembly decoder runs all eighteen before returning any state, and `loadKnownSaveBeforeMutation` assigns only after successful full decode.

Cross-field checks require `HEAD.playingTicks == PART.playingTicks == RCVR.playingTicks` and `UIST.activeCharacter == PART.activeCharacter`. `TIME.elapsedTicks` is a separate event/simulation clock and is deliberately not equated to party playing time. `MAPS` must contain exactly 67 unique bounded deltas and a `.dlv` or `.ddm` companion for the active `.blv` or `.odm` named by `HEAD`. `CHST.activeDeltaName` must identify the same companion, with a bounded decoded raw sidecar; later 67-map preflight validates its wire structure and item IDs against the active MM6 base. These checks apply on both encode and decode. The map codec checks names and payload bounds, but this assembly does **not** know the expected 67-name set or validate each delta against its base map; the later world staging transaction must do both before any global mutation.

This candidate remains partial. Raw resistance, cursor-held item, timed buff, hireling copies and recovery/rest fields are included. MM6 combat/buff meanings, shop/map items, buff-overlay joins, HIRE/RESC identity, active rest and turn state, generated NPC state, transient/UI policy and other runtime state still need disposition. A later manifest revision must reconcile any new required section. `SaveLoad.cpp`, slots, GUI and atomic file integration remain disabled for MM6; no claim of playable or durable save/relaunch follows from these tests.

The original focused synthetic C++ tests covered full sixteen-section round-trip; the provisional CHST/SCLK revisions extend the required-section and late-failure fixtures. Tests cover full eighteen-section round-trip, arbitrary section order, every missing/optional tag, optional `META` and unknown extra rejection, 66/67 and duplicate map cases, active indoor/outdoor companion checks, cross-clock/selection mismatches, wrong title/checksum, and late `SCLK` failure without destination mutation. No original GOG files or partial MM6 launch were used.
