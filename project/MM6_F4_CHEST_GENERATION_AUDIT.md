# MM6 F4 chest random-item generation audit

Status: **live MM6 chest generation remains blocked before mutation** (2026-11-06). After the initial retained-data audit, a bounded read-only trace of the owner-local executable matched the accepted F3 SHA-256 identity before disassembly. No game was launched. Exact disassembly and data locators remain in the ignored private companion.

## Established inputs and current call

The F3-backed 67-map known-save check found 1,223 nonempty fixed chest item slots: 280 positive template IDs and **943 negative random-item markers**, all within the six MM6 values `-1` through `-6`. The map validator accepts those six values as chest markers only; it does not generate items. A later [save-path trace](MM6_F4_CHEST_GRID_WIRE.md) proves the following 280 bytes are 140 signed grid cells, while live projection remains gated. Ground objects reject negative item IDs. MM6 `items.txt` has IDs 0–580; `MM6ItemTable::InitializeMm6` loads item weights for IDs 1–399 from `rnditems.txt` and three treasure-level enchantment chance rows, plus standard and special enchantment tables. `mapstats.txt` has a title-specific map treasure-level column. These are parsed inputs, not a verified generation algorithm.

Previously `Engine::_461103_load_level_sub()` called `GenerateItemsInChest()` without a title check after map loading. That shared function recognizes the negative IDs, remaps marker and map treasure levels through a fixed inherited matrix, optionally generates an artifact at the remapped top level, otherwise rolls 1–5 attempts per marker and chooses nothing, gold or an item by inherited thresholds. It mutates chest inventory, consumes the global RNG and can touch artifact state. Later `Chest::PlaceItems` uses the inherited chest table and `Item::postGenerate(ITEM_SOURCE_CHEST)` to lay out and finish items. Thus a successful MM6 map decode does not imply its chests have MM6 contents.

## New primary executable findings

The MM6 generator walks 20 fixed chests with a 4,204-byte stride and 140 item records per chest. It consumes one RNG draw before scanning any marker. A marker then rolls 1–5 attempts and remaps its tier with a **different MM6 7 × 7 table**. The first attempt uses the saved probability from the generator entry or the last additional attempt of an earlier marker; only additional attempts draw a fresh probability. Each selects nothing below 20%, gold from 20% to below 60%, or an item from 60% upward. The gold branches match the six small/medium/large amount bands already present in `Item::generateGold`. A top-tier branch calls a separate MM6 artifact picker. The [direct-picker follow-up](MM6_F4_CHEST_DIRECT_ARTIFACT.md) supersedes the earlier simple party-ownership reading: its scan windows overlap and its local mask is indexed by scan slot, while its candidate list extends through ID **430**. These findings establish the generator's outer control flow, not a safe complete item transaction.

The exact remap pairs for the retained marker band are captured as a **detached**, bounds-checked `mm6::chestTreasureLevelRangeForMarker` rule with focused native tests. It does not run from the live load path. The original MM6 table has a seventh row that always selects artifact tier 7, although none of the 943 retained markers use `-7`. All 67 retained `mapstats.txt` rows carry zero-based map treasure level 6. The helper still preserves all seven map columns for altered maps. In particular, tier-4/map-level-1 maps to 2–3, tier-5/map-level-0 maps to 2–3, and tier-6/map-level-0 maps to 3–3; inherited MM7 remapping differs in those cells.

The MM6 random-item picker searches weighted regular templates **1–399**, then handles potion, wand and enchantment branches. At treasure tier 6 it also has a separate artifact trial over a 30-ID MM6 band with a 5% roll and a hard cap of 13 generated artifacts. This is distinct from the direct tier-7 artifact picker. A [placement follow-up](MM6_F4_CHEST_PLACEMENT.md) now establishes the original 140-cell **in-memory** signed grid, shuffled fit order, no-fit behavior and conditional wand charge fallback in a detached tested model. Its changed-state save encoding, original chest-type/icon adapter and live transaction are not yet reconciled with `ChestInventory` and `.ec6`.

### Bounded MM6 random-item picker contract

A branch-complete read-only pass over the original picker established its `RANDOM_ITEM_ANY` base-ID order. Its 15-bit RNG advances a 32-bit state with the original multiplier and addend. Every ANY call draws an artifact candidate from 30 IDs, even at tiers 1–5. Only tier 6 then draws a 0–99 chance: below 5, an ungenerated candidate under the fixed 13-artifact cap is marked generated and returned as ID 400–429. Other outcomes draw a zero-based remainder against the sum of 399 regular template weights. Remainder zero returns item **1** directly, even when its weight is zero; positive remainders scan IDs 1–399 until cumulative weight reaches the remainder. That differs from the inherited MM7 selector's `+1` weighted roll. The retained six weight-column sums are 437, 827, 959, 970, 928 and 805. Item 1 has zero weight at tiers 4–6, making the zero-remainder branch observable with those tables.

The new `mm6::pickChestBaseItemId` is a **detached** preflighted model of this ID/artifact stage. It takes caller-owned 399 weights, 30 artifact flags and an RNG seed; returns the selected ID, staged flags, next RNG state and draw count; and rejects foreign titles, invalid tiers, empty/negative/overflowing weights and nonbinary flags before any result. Seeded native tests exercise the zero-remainder quirk, a later weighted ID, a tier-6 artifact, duplicate and cap fallback, and MM7 isolation. It does not construct an `Item` or run from the live chest path.

### Detached ANY item field finalization

A follow-up branch trace establishes the picker writes after a regular ANY base ID. Template identification difficulty sets the item flag word to zero when nonzero, or one when zero. Type codes 0–2 draw a weapon special-enchantment chance only when that tier chance is nonzero. Codes 3–11 draw the equipment standard chance only when nonzero; the same roll chooses a standard attribute, a special enchantment or no enchantment. Code 12 draws a wand current charge count as template charge base plus `RNG % 6`. Higher type codes return immediately from this picker, including potion type 14: **there is no potion-power write in the ANY picker**. Other item sources and later chest placement may have distinct field writes.

The standard branch draws one attribute against the selected type's 14 weights and then an inclusive tier strength. Its cumulative comparison preserves the original zero-remainder bias: first attribute can win despite zero weight. The special branch filters level codes by tier (3: 0/1; 4: 0/1/2; 5: 1/2/3; 6: 3), then selects one of 59 one-based IDs from type-specific weights. Artifact success exits before all regular field writes and adds no finalization draw. The detached `mm6::finalizeChestAnyItem` takes the previous base result and caller-supplied template/rule rows, validates bounds and malformed rows, and returns only copied field values, staged flags and next RNG state. It rejects foreign titles and does not touch the global RNG or live chest. Seeded native tests cover plain potion, wand, standard zero remainder, weapon/equipment special selection, artifact return and malformed table rejection. The ignored private packet holds exact instruction evidence and retained-table joins.

The retained enchantment-chance rows are parsed by `MM6ItemTable`. A later [detached record transaction](MM6_F4_CHEST_RECORD_TRANSACTION.md) joins the accepted outer plan, table-backed ANY fields, gold, safe direct artifacts and first-open placement into copied 4,204-byte records. It is not wired to live `Item`/`ChestInventory` or persistence. MM7 `Item::postGenerate` writes potion power on chest placement and must not be assumed for MM6 without tracing that separate stage. Requested-type modes are outside the chest ANY call. The ignored private trace records branch addresses and per-draw order without publishing executable bytes.

### Retained-table caller adapter and source routing

The detached [MM6 chest caller adapter](../src/Engine/MM6/MM6ChestCallerAdapter.h) now supplies the ANY picker and finalizer from an MM6-initialized `ItemTable`: the selected tier's 399 regular weights, the selected template's type/identification difficulty/wand base, six chance and strength rows, fourteen type-specific standard weights and fifty-nine type-specific special rows. It keeps the retained second equipment chance as a separate MM6 probability, despite the shared table field's MM7 cumulative-chance comment. It rejects foreign titles, invalid tiers and malformed selected rows without changing `ItemTable`, RNG or artifact flags. The result is still detached field data, not a live `Item` or chest mutation.

An outer-source selector encodes the original first/additional attempt probability bands for empty, gold and ANY item outcomes; the caller must supply the saved first-attempt probability in the original order. Gold has a separate six-tier amount/ID helper with one staged RNG draw. Tier seven is classified as a **direct artifact source**, separate from the tier-six ANY artifact trial. The personal fork explicitly chooses a safe direct policy: IDs 400–429 only, no party-owned/generated duplicates, a combined cap of thirteen, and a cleared marker when no candidate remains. This intentionally excludes original candidate 430 and avoids the original out-of-bounds mark write. The adapter and detached transaction do not bypass the global MM6 chest guard.

An ignored owner-only numeric profile was generated only from the F3-hash-matched retained `items`, random, standard and special tables. Five focused native tests passed: source bands, all six gold bands and ID bounds, synthetic standard/special/wand mapping and malformed-row rejection, plus 192 seeded ANY stages over the retained 399-template profile. The retained profile contains exact table values and stays outside Git. No MM6 process or original installation was opened. The remaining 28-byte item, direct-artifact, placement/grid and durable-save gates below still apply.

## Proven mismatch and missing contract

- The inherited artifact picker and level-six random-item branch use `allSpawnableArtifacts()` and `Party::isArtifactGenerated` in the MM7 ID band **500–528**. Retained MM6 item roles put **message scrolls** in that band; MM6 artifacts/relics occupy **400–429**. The inherited artifact result is therefore title-wrong, irrespective of whether a particular roll occurs in a short test.
- The inherited remap matrix differs from MM6 for several marker/map-level pairs. `isRandomItem()` also accepts `-7`, while the retained MM6 map set and bounded save validator establish only `-1` through `-6` as active data. A separate seventh remap row exists in the original executable, but its live map use and persistence remain unproved.
- The outer RNG order, attempt count, thresholds and gold dice are located in the MM6 executable; the outer ID plan, ANY base-ID/regular field stages, safe direct-artifact policy and first-placement grid are joined in a detached [28-byte record transaction](MM6_F4_CHEST_RECORD_TRANSACTION.md). This is not yet a live MM6 `Item`, `ChestInventory` or chest/save transaction. The original unsafe direct scan is deliberately excluded, while live changed-grid projection remains a blocker.
- The retained guide describes broad treasure and enchantment families but conflicts with a level-six weapon chance cell. It cannot settle the executable rule. Original MM6 placement and UI use hardcoded 9 × 9 dimensions despite 14 × 10 chest metadata; the in-memory chest carries 140 grid cells. The original save path copies the full 4,204-byte record, proving the 140-cell changed-state wire width. All retained baseline grids are zero, so a nonzero original-save fixture remains unavailable. Random results must survive map reset and `.ec6` save/reload without regeneration or losing original marker state.

## Required title-specific boundary and unlock sequence

The `mm6::generateChestItemsForTitle` boundary runs at `_461103_load_level_sub` before inherited chest/RNG/artifact mutation. It throws for MM6 and unknown titles, while MM7 still calls `GenerateItemsInChest()`. This is **unconditional**: every MM6 level load reaching this call fails, including maps with no random markers. A marker-free skip would omit the original function's entry RNG draw and therefore needs an explicit title-specific policy and seeded proof. The focused native tests check the MM6 block, MM7 selection and divergent MM6 remap cells. A replacement should first validate all 20 chest containers, marker IDs, zero-based map treasure level, MM6 item-table rows and capacity as one transaction. It must then reproduce the original outer draws and all nested item/artifact draws, item field writes, MM6 chest grid placement and deterministic commit/persistence.

Unlock evidence is a live MM6 `Item`/`ChestInventory` transaction for the detached record output and placement helpers, reconciled with map reset, changed-grid projection, the guide disagreement and save ownership. Run seeded synthetic and retained-data cases for all six active markers and all map levels, including a full chest, artifact roll, failed placement and exact RNG position; then inspect chest contents and save–quit–relaunch–load in F5. Until then, leave the live call guarded. See the [map item validation](MM6_EC6_MAP_FIELDS_F4.md) and [item guide audit](MM6_ITEM_MONSTER_GUIDE_CLAIMS_F2.md). The [wiki handoff](../.llm-wiki/MM6-F4-Chest-Generation.md) summarizes this gate for later agents.
