## Preflight and implementation rule

These addresses describe a particular MM6 process image as modeled by MMExtension. F3 must first match the installed executable to the F1 hash/version, parse PE headers and map each candidate virtual address to a file span. A missing or changed span is an explicit version discrepancy, not a reason to scan blindly or substitute MM7 constants. A static table may be initialized or patched at runtime; compare readable file values with the structure, retained text and guide claims before calling any value original-verified. Exact extracted values, pointers, filenames and route rows stay in ignored `local-game-data/mm6/`.

At F4, implement title-specific spell recovery, house descriptors and travel routing only from the F3-reconciled owner snapshot. Check 99 spells × three ranks, all active house room IDs and each transport option offline. F5 must observe casting readiness, house backgrounds/video/NPCs and actual travel timing/destination on screen and after save/reload. Preserve the protected MM7 runtime and profile throughout.
