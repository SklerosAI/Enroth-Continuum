# MM6 v2 fresh-child owner audit

Status, 2026-11-07: read-only audit of the native v2 two-process probe and the test-only `inspectRawChildPublication` seam at integration `b41d19380`. This is an admission checklist, not permission to open normal SaveLoad, the load menu or Atlas Play. No private save or game asset is recorded here.

## Last safe point before input

The current disabled v2 reader test calls `preflightStagedRawSessionFields()` in a second, null-renderer MM6 process and stops at detached state. The v1 control test reaches Main Menu Load → `Game::loop()` → `gameLoop()` using a test callback. In the real order, `gameLoop()` calls `loadGame()` before `GameUI_LoadPlayerPortraitsAndVoices()`, clears the message and party-action queues, ends turn mode, then calls `DoPrepareWorld(true)`. It unpauses `gameTimer`, sets the input-skip flag and enters `MessageLoopWithWait()`, followed by keyboard actions, event/timer work and drawing ([Game.cpp](../src/Application/Game.cpp), [v2 restart packet](MM6_F4_RAW_V2_HEADLESS_RESTART.md)). There is no post-world admission callback between `DoPrepareWorld` and that first message loop. A future test-only loader must install one there, or stop before `gameLoop()`; checking only the detached candidate cannot establish a safe first input frame.

`DoPrepareWorld` starts by resetting the mouse image, visible windows, loaded sprites, palettes and current location. It loads map events, removes actor PIDs from the turn queue, sets the map ID, reconstructs the indoor/outdoor world and then calls `_461103_load_level_sub()` and `onMapLoad()`. The latter may execute EVT code. It clears the pending transition before `onMapLoad` ([Engine.cpp](../src/Engine/Engine.cpp)). A resource or event failure after process-owner assignment leaves a partially changed child; the single-campaign policy must terminate that child before controls. The current `SaveLoad.cpp` MM6 guard remains the correct fallback.

**Test-only hook now implemented:** `Game::gameLoop()` calls `runArmedPostWorldAdmissionForTest(MM6)` immediately after `DoPrepareWorld(bLoading, 1)` when `bLoading` and the title is MM6, before `gameTimer->setPaused(false)` or `MessageLoopWithWait()`. `ScopedPostWorldAdmissionForTest` arms one callback on the game thread in a disposable test load body, consumes it once, rejects a second run while scoped, and clears an unused callback on teardown. Unarmed MM6 v1 and MM7 behavior is unchanged. An armed v2 callback must validate final event sidecar/generic arrays, actor/sprite/chest identities, cursor image and remaining resources/actions or throw; the hook itself does not yet perform those checks. Four linked unit tests passed. A separate disabled headless v1 control compiles and checks the real hook after world build while the timer remains paused and before input, using an unchanged disposable slot; it has not been run in this isolated worktree because its private v1 restart fixture was not present here.

The integrated test-only `inspectRawChildPublication` seam rechecks INVR/Party replay, HELD/SHOP/SCLK, cursor image plan, MAPS, mutable RESC, TIME/VISU fields, CHST, staged persistent bytes and plan/HEAD name. It also checks HEAD/core time consistency, `UIST` active character, the no-beacon policy and inactive VISU even for a later-mutated staged candidate. Its typed blockers now explicitly name unresolved mouse, NPC/static resource, world, chest, object PID, post-world event, BEAC/IFOV, trigger/timer, action/UI and hook gates. `canEnterGameLoop()` remains false by construction. A blocker name is an honest gap marker, not a published owner or a passed live check. The remaining interface gaps are an explicit static resource/RNG policy and a concrete after-world callback carrying the selected candidate and final owners. These are review findings, not claims that a live MM6 load has occurred.
