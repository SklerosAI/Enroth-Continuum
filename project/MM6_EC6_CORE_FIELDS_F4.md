# MM6 `.ec6` core party and character fields — F4 offline progress

Status: **bounded `PART` v3 / `CHAR` v4 codec and staging adapter, 2026-11-06; incomplete save, not wired to the game menu**.

The new `MM6CoreSaveFields` codec adds two required sections inside the existing title-tagged, CRC-checked `.ec6` envelope. Each section has its own version byte and strict length/count validation. `PART` stores gold, food, bank gold, playing-time ticks, three finite position coordinates, view yaw/pitch and active-character index. `PART` v2 added finite bounded vertical velocity, saved flight Z, water/lava timer ticks, bounded fall-start Z, binary flying status and both current-runtime flag words. `PART` v3 adds four signed current-runtime justice counters: fine, deaths, prison terms and bounties collected. Fine must be nonnegative; the other three preserve signed event arithmetic. The provisional 42-byte v1 and 74-byte v2 payloads reject; v3 is exactly 90 bytes. `CHAR` stores exactly four names (1–63 bytes without control bytes), sex, an MM6 class ID in 0–17, a vanilla face ID in 0–11, voice ID, level, experience, HP/SP, skill points, seven base stats, 31 MM6 skill values and 99 spell-known flags. Skill slot 30 maps to the current runtime's `SKILL_LEARNING`, following the MM6 creation path; values with Grandmaster or conflicting mastery bits are rejected. The 99 spell flags are packed into 13 bytes with zero padding required.

`CHAR` v2 appends seven signed 32-bit stat bonuses, signed 16-bit AC/level/age modifiers, a signed 32-bit birth year bounded to 0–10,000 and seven one-time pure-stat-potion flags per character. The potion flags occupy one byte with its unused high bit required zero. These are direct current-runtime `Character` fields consumed by derived stats, event variables and the pure-stat potion limit. `captureCharacterModifiers()` reads them from a real `Character`; `stageCharacterModifiers()` returns a validated, detached copy under an explicit MM6 title. The core party capture and stage paths call these helpers for all four characters. Earlier offline `CHAR` v1 samples are superseded; no live `.ec6` slots exist. The meaning and bounds of MM6 event modifiers still need gameplay proof.

`CHAR` v3 appends the current `Character::uQuickSpell` and `lastOpenedSpellbookPage` as one byte each. Zero means no quick spell; values 1–99 are the 99 regular spell IDs already represented by the known-spell flags. Pages 0–8 match the nine `MagicSchool` values used by the spellbook. The current GUI writes these owners, and the inherited snapshot also preserves them, so this is a current-runtime preference preservation contract, not a claim about native MM6 save offsets. Capture rejects values outside those bounds; detached stage and decode reject malformed values before changing the caller. A quick-spell value is not required to match a learned-spell flag because that lifetime policy has not been proved. `CHAR` v1/v2 offline payloads are superseded, and no live `.ec6` slots exist.

`CHAR` v4 appends the exact eight byte values of the current `Character` attack/damage and health/mana bonus members. This is an explicit **raw current-runtime preservation contract**, not an assertion of native MM6 field identity, signedness or persistence. Capture converts each `char` to its byte value; stage bit-casts it back, preserving high-bit and presently unconsumed `*_related` bytes. Four-character payload bounds and required version are checked before any caller mutation. Offline v1/v2/v3 payloads are superseded; live SaveLoad remains closed.

`PART` v2 follows the current `Party` and movement consumers. `SaveLoad.cpp::saveNewGame()` sets `uFallStartZ=340` for `oute3.odm`; outdoor fall damage reads it. Outdoor gravity reads and updates `velocity.z`, saved flight Z and flying status. Engine water/lava and burning ticks read `_6FC_water_lava_timer` with `uFlags`; running recovery reads `uFlags2`. Indoor landing and pressure-plate logic reads landing/jumping/airborne flags. The inherited snapshot records these owners, but this codec preserves the **current runtime** without claiming native MM6 save offsets or unknown flag meanings. The raw flag words preserve all bits; only flying is constrained to 0 or 1. Capture and stage require explicit MM6 title and work on detached copies. Stage resets X/Y velocity because input derives them each frame, and resets `floor_face_id=-1` and `currentWalkingSound=SOUND_Invalid` because a floor face is map-local and sound depends on current audio. `DoPrepareWorld()` already resets floor face before map load. Re-entry pressure-plate/audio behavior still needs the first-frame test.

`decodeCoreSections` validates both payloads into a temporary value. `loadCoreFieldsBeforeMutation` decodes and checks the entire container before assigning that value to its destination. The runtime adapter checks the game title, captures these fields from a `Party`, and `stageCoreParty` applies a validated container to a **copy** of the live party; it returns the staged copy without changing the caller's party. No SaveLoad or UI path calls this adapter yet. This ordering is the foundation for a later all-family load transaction, not a complete transaction by itself.

A standalone native `PART` v2 probe previously passed nonzero 74-byte round-trip, old-version rejection and late truncation without changing the destination. The new v3 codec and focused unit translation units syntax compiled with integrated arm64 flags; a standalone native v3 probe passed nonzero 90-byte round-trip, old-version and negative-fine rejection with unchanged destination. A linked full build and game-test save/reload check remain for integration. The runtime adapter and new-game suites require a clean integrated rebuild because older static objects carry the smaller `CorePartyFields` layout.

Earlier arm64 MM6/OpenEnroth/unit builds and four focused core tests established `CHAR` v2. The v3 tests add nonzero quick-spell/page capture and detached stage, four-character round-trip, malformed bounds/version rejection and unchanged caller state. This verifies preservation of current runtime fields, not native MM6 rule semantics. No MM6 game or original installation was opened.

**Completeness lock:** This core payload still omits beacons and other Character state. Prior face/voice remain a future fidelity question, not a present MM6 runtime save blocker: current `SetCondition`/`ResetCondition` only use them for non-MM6 titles, and the MM6 zombie branch preserves its vanilla face. Other bounded `.ec6` sections now cover condition times, resistance channels, buffs, inventory/equipment, quest/event/award bits, hirelings, timers, overlays and 67 map deltas, but the whole save still lacks MM6-keyed shops/bounty, the verified chest seed/lifecycle, beacon state and more state listed in the [whole-save field register](MM6_SAVE_FIELD_REGISTER_F2.md). Live SaveLoad and the game menu remain guarded. Further F4 work must finish and test every required section, validate the whole save against a complete field manifest, and only then commit a staged runtime snapshot. F5 must verify graphical save/quit/relaunch/load and MM7 isolation.

## Eight-byte later-`CHAR` decision audit

The eight omitted current-runtime `Character` members are `_some_attack_bonus`, `_melee_dmg_bonus`, `_ranged_atk_bonus`, `_ranged_dmg_bonus`, `uFullHealthBonus`, `_health_related`, `uFullManaBonus` and `_mana_related`. Each is declared as `char`. The first four feed attack/damage calculations, the two `uFull*Bonus` members feed maximum HP/SP, and `resetTempBonuses()` clears all eight. The two `*_related` members have no active non-reset gameplay reader in the current source. The inherited `EntitySnapshots.cpp` maps all eight to and from MM7 snapshot fields; that proves only the fork's current MM7 preservation path.

The accepted ignored F3 logical-field manifest and family signoff explicitly did **not** read a native MM6 whole-save sample and did not assign exact per-field types, offsets or semantics. The accepted PE v2 report establishes creation HP/SP arrays and class rules, not these eight member identities. `CHAR` v4 therefore preserves raw *current-runtime* bytes only. No F3-backed original MM6 identity/signedness or lifetime mapping exists for the two `*_related` bytes, and the reset/commit policy still needs proof. This audit used retained accepted reports and current source only; it did not reopen the original installation or launch MM6.
