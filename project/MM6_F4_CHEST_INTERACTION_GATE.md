## Detached first-open and one-item transaction

`mm6::stageChestFirstOpenInteraction` composes the retained 9×9 first-placement model with a bounded `ChestInventory` projection. It stages either open-only or one visible-grid pickup on copies of the MM6 raw record, LCG state, held item and party gold. For ordinary items, it removes the selected inventory entry and returns that item as held. For gold IDs 197–199, it removes the entry and requires a caller-supplied nonnegative **net credit** before staging the gold increase. The exact original MM6 hireling/share result is not yet proved, so the helper will not infer it. It rejects trapped chests, an already held item, invalid grid points, malformed wire, failed icon lookup, foreign titles and gold overflow without changing the caller's owners. An initialized chest reopens without another placement draw. The raw record keeps its opaque item-tail bytes and changed 140-cell grid.

The accepted original-MM6 entry trace proves first placement occurs before active-character/trap checks. The retained placement trace proves the 81-slot 9×9 algorithm and wand-charge fallback. Retained evidence does **not** prove the trap effect, pickup cursor offset, net-gold settlement, hidden-item handling or debug repeat-placement rules. Rejecting trapped chests is a deliberate fail-closed restriction of this detached helper, not a claim about original ordering. Its returned result is not published to `vChests`, the active map sidecar, `.ec6` or the live chest UI. Focused arm64 native tests passed 3/3 for first-open/reopen, ordinary pickup, explicit gold credit, rollback and MM7 isolation; no MM6 game process was launched.

## Original trap decision and remaining effect gap

A read-only pass over the retained, identity-checked PE disassembly confirms the original chest entry tests the placed bit and calls placement **before** checking for an active character, then checks the trap bit and a resolved map. Its disarm helper returns a score that includes title-specific skill/equipment modifiers. If that score is nonzero, the entry draws once from the 32-bit LCG and compares `score + (draw % 10) > 5 × difficulty`; strict greater-than disarms and clears the trap bit before opening. A zero score skips this check and triggers. A triggered trap draws for a four-way variant, creates a sprite, calls audio and reaction paths, clears the trap bit, then returns without opening the chest UI. The entry span has no direct synchronous explosion call. Trap damage/status, positioning, audio and save timing have not all been joined to live MM6 owners.

`mm6::stageChestTrapDecision` implements only that proved RNG/threshold branch. It requires an MM6, already-placed trapped record, active-character confirmation, a nonnegative caller-computed disarm score and a bounded map difficulty. It returns disarmed/triggered, variant, original sprite ID, draw count and next LCG state, but **no mutated chest or effects**. The source variant order is fire (811), cold (813), lightning (812), body (814), unlike the inherited chest source's middle two. Seeded native tests passed 4/4, including all four sprite variants, the zero-score short path, strict threshold and MM7/malformed rollback. The inherited MM7 threshold and sprite order must not be reused for MM6.

### Disarm score owner and triggered effect chain

The retained score callee reads one encoded character skill byte: low six bits are skill level, bit 6 is Expert and bit 7 is Master. It doubles the level for an unbroken raw MM6 item ID 410 in one checked equipment slot, an unbroken ID 415 in either of two checked slots, and one unbroken equipped item with special enchantment ID 35. It then adds +4/+6/+8 if the party has professions 25/26/51 (Tinker/Locksmith/Burglar) and multiplies the sum by 2 for basic, 3 for Expert or 4 for Master. `mm6::stageChestDisarmScore` models exactly that arithmetic from **caller-validated booleans** and the encoded byte, rejects MM7, and does not read the inherited MM7 `GetDisarmTrap` or item enum names. The MM6 character/equipment/hireling owner projection into those fields remains to be proved. Three focused native tests passed for mastery, stacking/order, hireling-only score and title isolation.

In the triggered path the entry selects the source-order sprite, computes a launch position from the chest's face or decoration and party position, adjusts it using sprite-frame dimensions, calls the sprite creation routine, plays a sound, clears the trapped bit, may set a delayed reaction, then returns without opening. The effect's actual damage/status is not computed in the entry span; the sprite lifecycle and impact path need a targeted trace before applying effects or committing cleared flags. Outdoor sector/face lookup and telekinesis reaction differences are also unresolved. The detached score and decision helpers intentionally return no live `Party`, sprite, chest or save mutations.

The retained manual describes disarming as a chance and says telekinesis can avoid traps; it gives no exact damage, status or gold settlement formula. A retained strategy guide lists Factor and Banker gold bonuses, but does not establish bonus stacking, rounding, hireling salary deductions or the chest pickup call chain. The existing first-open transaction therefore still requires an explicit net gold credit. A future targeted PE trace must identify the original gold pickup function and its final party-balance write across no-hireling and mixed-hireling cases before replacing that requirement. No guide prose or executable bytes are copied here.
