# MM6 house entry preflight

Status: F4 title-specific runtime source and nonfatal closed entry, 2026-11-06. No house service, movie, sound or party transaction is enabled.

The MM6 runtime now lazily loads the owner-only `rules/house-rooms.json` and the active title's `2dEvents.txt` through the same resource manager that initialized the house table. The decoded candidate validates all 557 MM6 rows, title-specific types and families, paired hours, bounded values and 119-room joins before it can be used for entry. This source is selected only when the engine title is MM6; MM7 retains its inherited house path.

`planHouseEntry` classifies an event house ID as table-backed, blank/unused, or a 600/601 terminal pseudo-house. The retained F3-matched active EVT inventory yields 671 table-backed instructions, one blank/unused instruction and two terminal instructions. All 21 taverns are table-backed with a room descriptor, numeric `Val` and paired hours. These are source data inputs, not a verified rest/food price or duration.

`enterHouse` invokes this MM6 preflight before it clears messages, touches shop bans, changes NPC flags, indexes `pAnimatedRooms`, opens a movie or creates a service window. For a structurally valid MM6 entry, it reports an unavailable place and returns false, allowing the world event to continue without an exception. Terminal IDs get a distinct unavailable-passage message. A malformed/missing private manifest or title table still rejects before inherited state. MM7's branch is unchanged.

A native private-backed test covers all 674 active `SpeakInHouse` instructions and 21 tavern rows, plus foreign-ID rejection. The arm64 MM6/MM7/unit targets built and eight focused house/transport tests passed without skips. The runtime status and visible response have not been observed. This is an execution boundary, not a playable house. The owner's manual documents tavern room, food and drink and an overnight rest, but the [service claim audit](MM6_MANUAL_SERVICES_CLAIMS_F2.md) leaves exact MM6 prices, status/time effects and tavern ID policy unjoined. Every retained tavern needs MM6 room movie, NPC and sound consumers; full Smacker playback has not been observed. Transport also needs fare, weekday, quest, arrival and `.ec6` autosave semantics. Before narrowing entry for any one house, implement and test those title-specific paths, then verify the visible action and save/reload in F5.
