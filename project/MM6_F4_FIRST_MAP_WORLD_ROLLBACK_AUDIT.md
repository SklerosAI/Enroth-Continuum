# MM6 first-map world rollback audit — F4

Status, 2026-11-06: **test-only bounded collection scratch; full outdoor load and normal SaveLoad remain guarded**.

`saveNewGameMM6ScopedForTest()` proves the first-map `.ec6` preflight, atomic disk write and exact rollback of the slot pair, map-delta cache and CHST title owner. Its callback currently receives a detached Party and published map cache/CHST. The separate monitored private test passed 1/1 without calling `loadAndPrepareODM`. The headless harness independently demonstrated that `loadAndPrepareODM(firstMap, true)` can reach a first-map load. That loader and `DoPrepareWorld` mutate many owners beyond the save callback contract.

| Owner changed during outdoor entry | Source path | Rollback readiness |
| --- | --- | --- |
| `pMapDeltas` and MM6 `ChestTitleState` | Save publication; `Outdoor::Load` reads the active DDM, chest adapter advances title state | Exact prior values are retained and swapped back by the scoped save runner after callback failure. |
| `pActors`, `pSpriteObjects`, `vChests`, `pLevelDecorations` | `OutdoorLocation::Load`, encounter/treasure spawning, decoration preparation | New `ScopedFirstMapWorldCollections` can swap all four prior containers into private storage without throwing, expose empty scratch owners, and restore them on fault. | `pOutdoor` terrain, vertices, faces, models, spawn points, weather, discovery grids, `ddm`, `mm6DeltaBytes`, sky/image pointers | `OutdoorLocation::Initialize/Load`, `loadAndPrepareODMInternal` | No safe detached reconstruction or whole-object swap is proved. No complete snapshot/restore contract exists. Mandatory before treating a failed full map entry as atomic. |

The bounded helper requires explicit MM6 title and four nonnull collection owners. Its constructor swaps all four to empty scratch state only after those checks; `rollback()` and destruction restore the prior containers in reverse order, while `commit()` leaves the new collections. It uses no global engine or private game data and can be embedded in a later test callback. It **does not** make `loadAndPrepareODM` safe by itself. A future experiment must first stage or snapshot every remaining owner above, inject failures after outdoor reconstruction and after map-entry events, and prove rollback of the disk slot and all process state in the monitored headless harness before the normal SaveLoad guard can open.

`ScopedFirstMapPlacementAndEvents` is the next bounded test-only scope. It requires a staged Party at the exact New Sorpigal arrival coordinates, a valid destination and explicit MM6 title before any mutation. It constructs the next transition first, then uses no-throw swaps for the local event program, level strings, last-save selection and pending destination; scalar and fixed-size placement/map/flag fields are copied. A late synthetic fault after changing Party position, map/type, pending transition, event program/strings, transient bytes and engine flags restores the original values. This can be composed with the collection scope, but the remaining outdoor/resource/persistent-event owners in the table still prevent a safe full `loadAndPrepareODM` callback.
