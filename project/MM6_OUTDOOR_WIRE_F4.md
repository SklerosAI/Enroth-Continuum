# MM6 outdoor wire codec — F4 offline progress

Status: **bounded decoded-payload parser, partial runtime projection and changed-state writer, 2026-11-06**. The codec is title-specific and works from the ignored retained F1/F3 map extracts. It never reads the original GOG installation and does not make the outdoor campaign playable.

## Implemented boundary

`MM6OutdoorWire` validates an uncompressed `.odm` payload from its fixed header through model headers and all model vertex/face/legacy BSP spans, decoration records and names, PID list, decoration map and spawn points. It validates an uncompressed `.ddm` payload as reset header, two visibility arrays, counted 548-byte actors, counted 100-byte ground items, counted 4,204-byte chests, 200 persistent bytes and a 56-byte tail. Every count is checked against remaining bytes and a conservative maximum; trailing and truncated bytes are rejected. Both codecs retain the whole decoded byte stream, including unknown fields and the two legacy BSP lists currently skipped by the renderer adapter. The delta API exposes bounded section spans for later state mapping and nonzero mutation.

The base wire view also records each model's contiguous 308-byte face records and 10-byte-per-face texture-name records. `faceBytes(modelIndex, facetIndex)` and `textureNameBytes(...)` require **zero-based** indices and reject missing models/facets before returning mutable or read-only spans. They are a checked lookup primitive for MM6 event opcode 12's outdoor texture and opcode 24's outdoor facet-bit candidate. Event operands must be verified for index base, bit namespace and texture lifetime before calling these accessors; the current parser's four-byte model/facet operands alone do not prove that mapping. A write to the copied base wire is not yet a persistent world change: F4 must apply it to the rendered face, record a title-specific override in `.ec6`/map state, and reapply on map load. The shipped `.ddm` format has no MM7 per-face attribute array to borrow.

`deserializeMM6Outdoor(const Blob &, ...)` runs the base wire validator before allocating its inherited renderer snapshot. This closes unbounded model/decoration count exposure for MM6 base loading without changing MM7's path.

The MM6 branch of `OutdoorLocation::Load` now decodes `.ddm` through the MM6 wire codec and a separate runtime adapter. It projects the two 88×11 visibility arrays, reset count/day, bounded actor records, ground objects and chests into the existing runtime entities. The adapter copies the complete decoded DDM into an MM6-only sidecar, including the 200 persistent bytes, 56-byte tail and every unknown record byte. Actor, ground-item and chest projection helpers require exact 548/100/4,204-byte spans and are available for the indoor adapter. The MM7 load branch is unchanged.

This is **partial runtime reconstruction**. MM6 actor buff/status slots, spell IDs/mastery and some resistance meanings are not yet mapped to their MM7 runtime equivalents. Chest grid width is still ambiguous; the adapter copies the whole 280-byte region and retains the source bytes, while the retained shipped grids are all zero. Active MapVar IDs 105–175 read and change sidecar bytes 0–70; upper persistent bytes and the 56-byte tail remain opaque. MM6 SaveLoad now rejects before the inherited MM7 writer, so map mutation/save/reload is not accepted. Reset uses the inherited first-entry/timed policy provisionally because shipped reset fields are zero; F5 must verify a nonzero original-game or controlled state. No MM6 campaign was launched.

## Bounded changed-state writer

`encodeMM6OutdoorRuntimeDelta` starts from the current decoded DDM sidecar, not a fresh template. It overlays reset count/day, both visibility arrays, actor attributes/HP and established motion/action fields, selected ground-item fields, and chest flags plus the first 26 known bytes of each contained item. It refuses record-count changes, negative actor HP, chest type/grid changes, and changed snapshot fields with no proven MM6 mapping. The 200-byte persistent block, including live MapVar writes, unmapped actor/item/chest bytes and the 56-byte tail are copied unchanged. `encodeMM6OutdoorChangedState` captures those supported fields from the active outdoor runtime and passes them through the same validator; it is an API for a later MM6 save transaction, not a SaveLoad hook. The final two bytes of each 28-byte MM6 item remain opaque; the [pinned editor's field list](https://github.com/angeld29/mm8leveleditor/blob/bf3b8c4a86100635a5fc6ff53fac6e4e0af5cb53/src/org/gamenet/application/mm8leveleditor/data/mm6/Item.java) labels the earlier fields but does not establish those final bytes.

The runtime capture deliberately projects only the supported actor/item fields. It cannot yet detect arbitrary unsupported changes held only in live MM7 objects; the strict snapshot writer does reject them when supplied directly. Save/load must remain gated until that coverage, nonzero changed-state behavior, and chest-grid interpretation are resolved. Spawned actors and ground objects currently fail on count changes. Baseline test coverage uses all 15 original-matched decoded DDMs plus synthetic nonzero actor/item/chest/visibility/reset and MapVar mutations; this establishes byte preservation and our guards, not original-game behavior.

## Offline evidence

A compiled clang C++23 harness used the real codec on all **15 retained outdoor bases and 15 retained deltas** after their existing strict wrapper decode. All 30 decoded payloads re-encoded byte-for-byte; all 15 deltas preserved a synthetic nonzero persistent-byte mutation; and all 60 deliberate truncated/count-overflow cases were rejected. No proprietary bytes or map names were written to Git. The synthetic C++ unit source also covers zero-count base/delta round trips, opaque section mutations, overflow counts, truncation and checked model/facet access. Codec, unit source and the existing MM6 base adapter passed C++23 syntax checks. The full CMake unit binary was not run in this fresh worktree.
