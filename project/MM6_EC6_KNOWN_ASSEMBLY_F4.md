# MM6 `.ec6` known-field assembly — F4 offline progress

Status: **two partial offline candidates, neither a final whole-save manifest or live save path** (2026-11-06). The provisional v1 known assembly has eighteen required sections. The separate v2 raw candidate has nineteen required sections, replacing logical `ITEM` and `HELD` v1 with physical `INVR` and raw `HELD` v2, and adding `SHOP`. `CHST` and `SCLK` remain provisional schema revisions; old seventeen/sixteen-section candidates reject before mutation. See [CHST transaction](MM6_F4_CHEST_EC6_TRANSACTION.md) and [SCLK clocks](MM6_F4_SHOP_GUILD_CLOCK_SAVE.md).

`MM6KnownSaveFields` assembles required `PART`, `CHAR`, `QEST`, `EFFT`, `ITEM`, `HEAD`, `TIME`, `UIST`, `VISU`, `MAPS`, `RESC`, `RSTS`, `HELD`, `BUFF`, `HIRE`, `RCVR`, `CHST` and `SCLK` sections in the title-tagged, CRC-checked v1 `.ec6` container. Decode requires exactly these eighteen distinct required tags and container version 1. It rejects optional extensions, including optional `META` and unknown tags, until there is an explicit preservation policy and a new manifest review. The generic container recognizes standalone `SHOP`, `BEAC` and `INVR` tags and accepts optional `IFOV`, but none is in this v1 known manifest. A focused linked fixture verifies that all four extras reject before destination mutation. Each existing field codec validates its own version, length and range; the assembly decoder runs all eighteen before returning any state, and `loadKnownSaveBeforeMutation` assigns only after successful full decode.

Cross-field checks require `HEAD.playingTicks == PART.playingTicks == RCVR.playingTicks` and `UIST.activeCharacter == PART.activeCharacter`. `TIME.elapsedTicks` is a separate event/simulation clock and is deliberately not equated to party playing time. `MAPS` must contain exactly 67 unique bounded deltas and a `.dlv` or `.ddm` companion for the active `.blv` or `.odm` named by `HEAD`. `CHST.activeDeltaName` must identify the same companion, with a bounded decoded raw sidecar; later 67-map preflight validates its wire structure and item IDs against the active MM6 base. These checks apply on both encode and decode. The map codec checks names and payload bounds, but this assembly does **not** know the expected 67-name set or validate each delta against its base map; the later world staging transaction must do both before any global mutation.

This candidate remains partial. Raw resistance, cursor-held item, timed buff, hireling copies and recovery/rest fields are included. MM6 combat/buff meanings, shop/map items, buff-overlay joins, HIRE/RESC identity, active rest and turn state, generated NPC state, transient/UI policy and other runtime state still need disposition. A later manifest revision must reconcile any new required section. `SaveLoad.cpp`, slots, GUI and atomic file integration remain disabled for MM6; no claim of playable or durable save/relaunch follows from these tests.

## V2 raw candidate

`MM6RawSaveFields` assembles the exact nineteen required sections in EC6 container v2. It uses the existing bounded raw `INVR` image for all four party inventories, 32-byte raw `HELD` v2, and the physical `SHOP` image together with keyed `SCLK` deadlines. `QEST` and `EFFT` are split from the old logical `ITEM` codec so the same progress representation can be retained without a lossy item projection. The `SHOP` and `SCLK` fields form one title-local `ShopTitleState` owner. The raw fields and v1 known fields share cross-field clock, selection, map count and active-delta checks. V2 requires explicit MM6 title selection and rejects all missing/optional/extra sections, v1 containers, old `HELD` shapes and added logical `ITEM` sections. The decoder assigns no destination state until every field and cross-check succeeds.

This is a coordinated **offline candidate**, not a production file migration. `MM6AtomicSaveFile` and the current New Game path continue reading/writing v1; a v2 file is rejected by their known-field gate. The v2 field set still omits beacon state and unresolved owner/runtime fields, expected 67-map name and base validation, and a complete global publication transaction. It has no slot, UI or `SaveLoad.cpp` integration.

The original focused synthetic C++ tests covered full sixteen-section round-trip; the provisional CHST/SCLK revisions extend the required-section and late-failure fixtures. Tests cover full eighteen-section round-trip, arbitrary section order, every missing/optional tag, optional `META` and unknown extra rejection, 66/67 and duplicate map cases, active indoor/outdoor companion checks, cross-clock/selection mismatches, wrong title/checksum, and late `SCLK` failure without destination mutation. No original GOG files or partial MM6 launch were used.

The v2 synthetic fixtures cover nineteen-section byte-stable round-trip with high-slot inventory and raw item tails, rejection of old and mixed shapes, every missing/optional section and extra `BEAC`, late `SHOP`/`HELD`/`INVR` failure without destination mutation, wrong title, owner readiness and cross-field mismatch. A focused Mac build passed the container library and test object; a linked harness passed four v2, nine v1 assembly and three container tests (16 total). No private game file was read.
