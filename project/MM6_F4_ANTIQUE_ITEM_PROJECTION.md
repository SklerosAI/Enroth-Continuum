# MM6 Antique-only native item projection

Status, 2026-11-06: detached, source-bounded and linked-tested. This does not open production MM6 SaveLoad or prove a playable inventory.

The pinned [MMExtension MM6 item layout](https://github.com/GrayFace/MMExtension/blob/9d73c0ff0482bd231ea522f752f4fe9b26640925/Scripts/Structs/01%20common%20structs.lua#L503-L529) places the second bonus in the native 28-byte record at offset 12. The retained original item-picker trace writes a one-based special ID there for eligible weapon/equipment picks. The locally retained MM6 `spcitems.txt` row for ID 58 describes a value-only multiplier; `MM6ItemTable::InitializeMm6` loads it into the shared `ITEM_ENCHANTMENT_ANTIQUE` slot, and `Item::GetValue` applies that slot's multiplier. The inherited special-stat map has no entry for Antique. This establishes a narrow current-runtime representation; an independent original-executable price/effect consumer trace remains an F5 check. The row text and source asset stay ignored locally.

`stageAntiqueItem` accepts only common MM6 special-enchantable item types 0–11 with native second bonus 58, zero standard bonus words, a positive source-table chance for that type, multiplier 10, zero value addition, and a base value whose tenfold result fits signed `int`. It retains all 28 source bytes in `Item::mm6RawRecord`. `captureAntiqueItem` requires the same source record, ID, type, table contract and fixed special ID; it permits only the already-bounded identified/broken flag edit and preserves every other byte. The four-character raw party stage receives this view through `MM6BoundedItemProjection`. Other special IDs, potion-power unions, artifacts/relics, unknown field edits and foreign titles still reject before the Party candidate is returned.

Three focused arm64 linked synthetic tests passed. They exercise tenfold value, exact source-byte round trip with nonzero opaque tail, allowed flag edit, unsupported-field and type rejection, foreign-title rejection, a fresh four-character Party round trip, and a late fourth-character unsupported-special failure without baseline mutation. The object build used current integration compile flags and linked the isolated worktree's stage object against existing libraries; no private game data was linked or committed. No full isolated rebuild was run.

Next gate: trace the original executable's value/effect consumer for ID 58, then inspect one real item and save/reload it under the eventual all-owner MM6 transaction. General special bonuses need a separate per-ID effect table and tests; this bounded case must not be generalized by numeric range.
