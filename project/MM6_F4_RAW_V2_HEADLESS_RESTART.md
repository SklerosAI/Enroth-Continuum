# MM6 raw v2 headless restart handoff

Source checkpoint: integration `03d9ebf4e`. Status: **v2 read-only fresh-process probe added; live reload remains gated**. This packet applies to an explicitly disposable, owner-only system-temp profile and a title-locked MM6 GameTest process. It does not change normal SaveLoad, the load menu or Atlas Play.

## Existing v1 control route

`GameTests_MM6Save.cpp` already has a two-process **v1** proof. `DISABLED_NewGameControlFlowReachesFirstFrame` writes a partial first-map slot through the scoped test callback. `DISABLED_RestartSlotThroughMainMenuGameLoop` starts a fresh process, installs explicit test-only Main Menu QuickLoad and `loadGame` callbacks, selects that v1 slot, assigns its represented owners, and lets the real `Game::loop()` enter `gameLoop()`. The latter calls `loadGame()` before portraits, `DoPrepareWorld(true)`, the first two input/world skip gates and a movement frame (`src/Application/Game.cpp`). That probe proves the control path for its v1 fixture; it does not establish v2 owner completeness or a production MM6 load.

## V2-only read boundary

`DISABLED_RawV2RestartSlotStagesDetachedSession` takes a separately written `autosave.ec6` from `ENROTH_MM6_RESTART_PROFILE`, requires an owner-only `mm6-restart-*` directory immediately under the system temp root, and runs in a fresh null-renderer MM6 process. It calls `preflightStagedRawSessionFields()` with a freshly loaded MM6 NPC table image and the loaded map source, checks the first outdoor plan and represented Party/world/chest/shop/inventory state, and verifies that the slot bytes are unchanged. The preflight API selects only native v2 primary/backup candidates and stages raw fields, Party, NPC/timer/overlay, persistent event bytes, active map and geometry without changing globals (`src/Engine/MM6/MM6RawSessionStage.cpp`, `MM6RawSaveRuntime.cpp`, `MM6AtomicSaveFile.cpp`). A v1 slot must fail this test. The new test is disabled by default and has no valid v2 first-map fixture yet; syntax checking passed, but a linked run awaits a separately admitted v2 writer candidate.

The parallel v2 writer proposes a detached `prepareOfflineRawNewGameAutosave()` from the known New Game seed plus explicit ready raw inventory, held cursor and SHOP/SCLK owners. It can produce bytes without disk or live mutation, then write an admitted disposable slot. It still needs a source-backed way to capture the live starter-item physical inventory and cursor and to prove those owners agree with the Party. A writer that simply fills these structures with synthetic or default values cannot serve as the real New Game fixture for a reload claim.

## Gate to the actual v2 game loop

1. Prove live New Game capture for every required v2 owner, especially raw physical starter items, held cursor and title-local commerce clocks; write and re-read an admitted v2 slot in the disposable profile. The writer must preserve the existing atomic primary/backup contract.
2. Preflight the slot through `preflightStagedRawSessionFields()` in a fresh child and inspect all owner equalities and the detached active map. The new read-only test is this boundary; it must pass before any publication attempt.
3. Add an explicit test-only v2 publication coordinator for the **fresh child only**. It must join raw inventory and cursor with Party/UI image ownership, SHOP/SCLK process state, NPC and event arrays, timer/overlays, map deltas and chest state, then resolve active-world objects/PIDs and renderer resources. `DoPrepareWorld(true)` currently reconstructs and mutates the world after `loadGame()`; a detached stage alone cannot prove that publication succeeds. The existing scoped chest opt-in is a test gate, not a production replacement.
4. Only then repeat the v1 Main Menu QuickLoad → `Game::loop()` → `gameLoop()` probe with the v2 slot. Assert map identity, first two skip gates, one action/movement frame, no slot mutation, and no visible window or focus change under the host monitor. Keep `SaveLoad.cpp`'s normal MM6 rejection and the empty MM6 load menu until full-session and graphical acceptance.

There is no safe current shortcut from the v2 stage directly to `gameLoop()`: its raw cursor/shop, persistent event, resource and world-object owners are detached, and the current v1 callback publishes only its represented v1 fields. Treating a v2 slot as v1 or copying those fields into globals would silently drop required state. A fresh child limits damage to an existing live campaign but does not validate a partial session or protect an autosave written before world entry.
