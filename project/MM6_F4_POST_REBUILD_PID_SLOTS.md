# MM6 post-rebuild PID slot agreement

Status, 2026-11-06: read-only, title-locked refusal gate with two linked synthetic tests. No live loader, SaveLoad or overlay publication calls it yet.

The detached indoor and outdoor v2 plans hold an active saved DLV/DDM projection and a separately decoded CHST sidecar projection. `DoPrepareWorld(true)` reconstructs `pActors` and `pSpriteObjects`, then runs map setup and `OnMapReload`. Actor and sprite PIDs use their array indices; the indoor and outdoor reconstructors assign `Actor.id = index`. Respawn can select a different delta, actors can be cleared or reused, and reload events can add or change objects. A saved count or `Actor.id` alone does not establish a target's post-reload identity. See [the earlier actor PID audit](MM6_F4_SAVED_ACTOR_PID_IDENTITY_GATE.md).

`requirePostRebuildPidSlotAgreement` accepts one detached indoor or outdoor plan, the actually loaded map name, and read-only spans of the final actor and sprite arrays. It requires MM6, exact map-name match, equal saved/CHST/final counts, and equal per-index anchors. Actor anchors are NPC ID, monster ID, embedded monster ID and initial position; the live actor must also carry its array index in `Actor.id`. Sprite anchors are sprite ID, object descriptor ID and initial position. These fields are projected from native MM6 records by `projectMM6ActorRecord` and `projectMM6GroundItemRecord`, then reconstructed into the runtime arrays. They are expected to remain fixed through ordinary map preparation even when current position, HP, generated item, animation and floor placement change. The helper reads no globals and mutates no plan or owner.

The gate may reject a legitimate load if respawn or an `OnMapReload` event changes these anchors or array counts. A matching tuple can also occur after a replacement with the same values, so this is **slot agreement**, not a proof that the loader selected the saved delta. A future loader must record selected-delta provenance and exclude actor slot reuse between reconstruction and overlay publication. The existing `requireNoActiveSavedActorOverlays` policy remains in force; this helper must not be used to admit an active VISU slot. No object PID reference is rebound here.

The two linked synthetic tests cover matching indoor and outdoor plans; wrong title/map; actor index, initial-position and saved/sidecar disagreement; and sprite descriptor, initial-position and count changes. They do not run `DoPrepareWorld(true)` or claim a playable reload. A future fresh-child probe should call this after world preparation, then check a real selected-delta witness and the remaining resource, chest and all-owner gates before controls are enabled. Private game data and captures remain outside Git.
