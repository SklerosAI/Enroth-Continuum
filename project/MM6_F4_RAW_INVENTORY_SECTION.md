# MM6 detached raw inventory section — F4

Status, 2026-11-06: **standalone `INVR` v1 is a byte-preserving structural candidate, outside the required known-save manifest and live SaveLoad**. It does not interpret item categories, validate active placement or import a native MM6 saved game.

The pinned [MMExtension MM6 `Player` layout](https://github.com/GrayFace/MMExtension/blob/9d73c0ff0482bd231ea522f752f4fe9b26640925/Scripts/Structs/00%20structs.lua#L1448-L1450) describes 138 physical `Item` entries followed by a 126-word inventory grid; its [equipment table](https://github.com/GrayFace/MMExtension/blob/9d73c0ff0482bd231ea522f752f4fe9b26640925/Scripts/Structs/00%20structs.lua#L1508-L1508) has 16 words. The pinned [MM6 item structure](https://github.com/GrayFace/MMExtension/blob/9d73c0ff0482bd231ea522f752f4fe9b26640925/Scripts/Structs/01%20common%20structs.lua#L508-L529) is 28 bytes. Its stated `Player.Items` start and `Inventory` start differ by exactly 138 × 28 bytes. These third-party layout declarations support a physical preservation candidate; they do not prove whether slots 127–138 can be active in the original executable or how a native save stores them.

The fork currently gives `CharacterInventory` a 126-record capacity and `DurableItem` source indices 0–125. Its provisional `ITEM` v1 contains semantic `Item` fields rather than all raw bytes. `INVR` v1 instead writes four fixed character regions, each containing all 138 exact `ItemRecord28` values, 126 raw little-endian 32-bit grid words and 16 raw equipment words. A four-byte version/count/reserved header makes the required standalone section exactly 17,732 bytes. It preserves every bit pattern, including unused record tails and signed-looking index words, without treating a structural reference as validated gameplay placement.

The generic `.ec6` container recognizes required `INVR`, but the provisional eighteen-section `KnownSaveFields` decoder rejects it before mutation. `captureRawInventory` requires an explicitly ready MM6 title-local owner; `loadRawInventoryBeforeMutation` decodes the complete container and copies only after version, required flag, exact length and checksum validation. The focused linked tests exercise every physical byte and index word, the final record/equipment slot, foreign title, malformed shape/version/optional flag, checksum failure and the known-save rejection. No live `Party` owner, original save sample or MM6 game process was used.

Integrated checks passed **5/5** focused, **347/347** private-backed MM6/LOD and **437/437** general non-MM6 unit tests after the arm64 unit target rebuilt. These are structural tests, not active inventory use or durable campaign checks.
