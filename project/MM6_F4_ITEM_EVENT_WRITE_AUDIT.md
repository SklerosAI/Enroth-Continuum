# MM6 item event write transaction audit

Status: F4 source and retained-script audit, 2026-11-06. **Raw variable ID 17 Add/Subtract remain guarded.** This packet does not claim a functioning item reward or handoff.

The accepted F3-matched active EVT corpus has 290 item Adds and 156 item Subtracts. The [retained checker](../scripts/mm6_f4_check_item_event_operands.py) now joins the frozen variable and opcode reports, checks their common EVT fingerprints, and asserts operation, same-event comparison and preceding selector aggregates. All 156 Subtract instructions have an earlier same-item Compare in the same event; this is **structural co-occurrence**, not proof that the branch reaches the subtraction only when the item is present. The last preceding selector for Subtract is absent at 29 sites, explicit party (`5`) at 59, or one of four player indexes (`0`–`3`) at 68. For Add, 279 of 290 sites have no earlier explicit selector in their event; the other 11 use player `3` (six), active `4` (three), party `5` (one) or random `6` (one). These are retained byte facts, not a claim about default target state across a caller or dialogue.

[MMExtension's MM6 variable reference](https://grayface.github.io/mm/ext/ref/) names raw ID 17 `Inventory/Items` and [its event command documentation](https://grayface.github.io/mm/ext/ref/) demonstrates an MM6 `evt.Add("Inventory", itemId)` reward and describes `evt.ForPlayer` as setting a command's current player. Those technical sources establish an item reward use and a selector mechanism. They do **not** specify the native MM6 cursor displacement, inventory removal priority, missing-item continuation, artifact uniqueness flag, generated potion/wand parameters or save ordering. The retained scripts likewise do not record dynamic inventory/cursor state.

The inherited C++ Add path calls `Item::postGenerate(ITEM_SOURCE_SCRIPT)`, marks `isArtifactGenerated` for spawnable artifacts, then `Party::setHoldingItem`. That call first tries to put any existing held item into a character inventory, otherwise drops it into the world, then replaces the cursor. The inherited Subtract path searches all four characters regardless of event selection, takes the first matching inventory entry before a matching cursor item, and can report success even when nothing was removed. This is a documented inherited behavior, **not** a verified MM6 rule. The inherited Roland cage special case is MM7-specific. The [save remainder audit](MM6_SAVE_REMAINDER_F4.md) already identifies `HELD` cursor state but still lacks verified MM6 generated-artifact state; live SaveLoad remains guarded.

No write subset is safe to enable from current evidence: even a fixed item Add can overwrite/displace an existing held item, and Subtract needs an exact owner/selection and cursor-versus-backpack rule. A preceding Compare cannot be substituted for a transaction preflight because another command can change state, and the branch target or selected player can differ. The current MM6 guard prevents both write operations before any inherited item mutation; MM7 keeps its existing path.

## Implementation gate

1. Establish MM6 behavior for Add with empty and nonempty cursor, available and full inventory, and a full-world drop path. Include potion/wand generation and artifact-state effects for representative retained operands. Record the original or independent technical evidence used for each rule; keep exact item IDs and script sites in ignored local reports.
2. Establish Subtract outcomes for a selected player's backpack item, another player's item, cursor-only match, duplicate cursor/backpack matches and no match. Check both party and numbered-player selector cases, compare-to-subtract branch flow, and whether failure stops the script.
3. Implement an MM6-only preflight that chooses one source/destination and validates all downstream capacity and IDs before mutating cursor, inventory, artifact flags, ground object or event flow. Test success, ambiguity/failure rollback, duplicate ownership, and MM7 isolation. Complete the missing MM6 artifact save field and `HELD` visual restore before durable reward acceptance.
4. In F5, observe the actual cursor and inventory view after one reward and one quest handoff, then save, quit, relaunch and load. Retained checker and native unit success alone do not establish gameplay correctness.

Verification here: the extended frozen checker passed with 641 ID-17 uses and all 156 same-event Compare/then-Subtract structures; the existing two focused native read-only comparison tests passed. No original installation or MM6 process was opened.
