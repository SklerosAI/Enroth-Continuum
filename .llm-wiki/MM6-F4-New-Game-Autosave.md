# MM6 F4 New Game Autosave

The [first-map packet](../project/MM6_F4_NEW_GAME_AUTOSAVE.md) traces why `Game::loop()` reaches the MM6 `saveNewGame()` guard before its pending `oute3.odm` map can load, and records the offline `.ec6` autosave seam.

`encodeOfflineNewGameAutosave()` replaces MAPS in an already detached known-field seed with 67 title-specific default archive deltas, derives the active CHST raw sidecar from the decoded first-map default delta, then validates the eighteen-section candidate and all 67 base/delta pairs before returning bytes. `writeOfflineNewGameAutosave()` passes those bytes to the native atomic writer at fixed `autosave.ec6` in an explicit MM6 profile. Three synthetic native tests cover nonzero first-map state, wrong-title and wrong-map rejection before reads, malformed final-delta failure before disk mutation, and semantic backup preflight/recovery. The route is offline only; `SaveLoad.cpp` still rejects MM6 before MM7 serialization.

The newer `prepareOfflineNewGameSession()` draws a port-specific chest seed once into a detached owner, builds the default-map candidate, and stages all represented Party/Character, world, visual, CHST and SCLK owners before returning bytes and owned copies. It requires fresh zero refresh clocks and no party-owned chest artifacts. `writeAndStageOfflineNewGameAutosave()` writes the fixed slot only after this preflight. The returned 67 map buffers are ready for a future `pMapDeltas` handoff, but neither helper assigns process globals. Synthetic tests include nonzero staged Party/NPC state and a final Party-adapter failure that preserves the old disk slot and live owners. The live guard remains closed.

`captureFirstMapKnownSeed()` now captures represented Party/NPC/timer/overlay fields with arrival placement on a detached Party copy. `writeAndPublishOfflineNewGameAutosave()` preflights, writes, then publishes the validated 67-map cache and CHST title owner through no-throw swaps. It retains the old values for `rollbackPublishedFirstMapCache()` if map entry fails. This handoff remains an offline helper; it has no Party/world commit or disk-slot rollback, and no MM6 SaveLoad call-site uses it yet.

The separate test-only `saveNewGameMM6ScopedForTest()` checks the current MM6 engine and uses the owner-local F3 manifest, loaded MM6 Games LOD and item table to call `runScopedFirstMapEntryForTest()`. The runner now finishes its bounded observer against the detached Party/map/CHST candidate **before** disk or process publication. The scoped wrapper then rechecks pending actions. A callback failure or new action leaves the prior slot/cache/CHST untouched; a writer failure retains the existing disk rollback path. The callback must not mutate other process globals. Normal `saveNewGame()` and all MM6 SaveLoad guards remain closed; real `DoPrepareWorld` is not yet a detached candidate.

The monitored `GameTests_MM6Save.cpp` exercises this wrapper with loaded private MM6 resources and an ignored F3 map source named by `ENROTH_MM6_MAP_RESEARCH_ROOT`. It writes only into a unique temporary native profile, checks first-map staged Party/cache/CHST state, then tests exact rollback of primary, backup and process cache/title owners after a callback failure. It skips when the private map source is absent. This does not call the full outdoor world loader.

The linked monitored private test passed 1/1 in 21.0 seconds with no focus change or on-screen window across 1,566 samples. The ignored log is `local-game-data/mm6/research-2026-11-05/F4_MM6_SAVE_HEADLESS_TEST_PRIVATE.log`. Full outdoor entry, broader world rollback and normal SaveLoad remain guarded.

A later dedicated `MM6ZSaveHeadless` test drives the real Main Menu → editable Create Party → `saveNewGame()` → `DoPrepareWorld` control flow. A test-only callback redirects the MM6 save to a unique temporary `.ec6` profile; it is absent in a normal user session, where the guard still rejects MM6. The first run exposed inherited MM7 starter books in the MM6 artifact range. After the title-specific creation grant was corrected, the test reached the first outdoor frame with actors and twenty chests, passing 1/1 under a no-window/no-focus monitor. The ordinary MM6 save route, rollback on a late real-world failure, quit/relaunch/load and campaign play remain gated. This supersedes the earlier statement above that no test had entered the full outdoor loader.

The test-only `stageOfflineSaveSlotForTest()` now reads a temporary native EC6 primary/backup pair into fresh, detached Party/NPC/timer/overlay owners. It selects a candidate only after the existing native slot preflight and `stageKnownSession()` validate all represented owner families, 67 map pairs, the typed active map, CHST raw sidecar/LCG and SCLK. The returned bytes, staged session and recovery-needed flag are independent of live globals; the helper never repairs disk. New synthetic cases cover nonzero stage, foreign title, late Party rejection, corrupt primary with intact backup, two corrupt copies and absent slot. The existing private headless GameTest also checks a real first-map slot read with the ignored F3 map source, MM7 rejection and read-only backup selection.

After integration, the linked `MM6NewGameSaveRuntime.*` native suite passed 13/13 in 13.94 seconds, including the two fresh disk-stage cases. The monitored private `MM6ZSaveHeadless.*` test passed 1/1 in 35.248 seconds. The host monitor observed 2,368 samples, no focus change, zero on-screen windows and the same front application before and after. Its ignored log is `local-game-data/mm6/research-2026-11-05/F4_MM6_DISK_STAGE_HEADLESS_PRIVATE.log`.

The [first-map world rollback audit](MM6-F4-First-Map-World-Rollback.md) classifies the outdoor and engine owners changed after the save callback. A bounded scratch owner now protects actor, sprite, chest and decoration collections under late synthetic failure; the outdoor object, Party, transition/events and resource/UI effects still need joined rollback before a full loader can be called atomically.

The seed is only the represented field set. The older byte-builder requires the caller to supply CHST state; the staged new-game helper draws one port-specific seed into a detached owner. Active world reconstruction, native resource identity, MM6-keyed commerce/bounty, beacon images/map identity, persistent event variables, first-frame movement/action policy and the final all-owner reload are not proved. `PART` v2 preserves fall-start Z; the offline builder now requires the source-backed 340 position and fall-start Z before archive reads. The read stage is a same-process test of fresh owners, not a quit/relaunch, live `loadGame()` or rendered-state proof. Keep live first-map autosave guarded until a full `.ec6` capture, atomic write/recovery, quit/relaunch/load and rendered-state scenario succeeds.
