- Byte/pointer proof: captured bytes match the subsequent RAM save bytes when both calls run in one game-thread callback. The decoded active outdoor delta has the intended visit stamp and compacted sprite count. Its raw bytes match the old `serialize(location, tags::via<OutdoorDelta_MM7>)` path after normalizing only reserved `LocationHeader_MM7::field_1C`, `field_20` and `field_24` at offsets 28–39, which the old snapshot does not initialize. The first live `SpriteObject*` remains stable after the successful save because commit uses the original in-place compactor. The compactor copies a no-throw-assignable `SpriteObject` and shrinks the vector; the map cache uses `swap`, so the current commit path allocates no new storage.
- Limits: `ufs->write` can apply bytes and then throw, leaving the disk result uncertain while live capture state stays unchanged. The inherited native writer can still truncate an existing slot; the detached atomic helper and partial validator remain unwired. `saveNewGame` changes map/Party setup before this capture stage. This does not establish disk durability, backup recovery, live graphical behavior or full MM7/MM6 suite status; the integration lead owns the combined gate.
