# MM6 F4 Chest Interaction Gate

The [source audit](../project/MM6_F4_CHEST_INTERACTION_GATE.md) lists the consumers that follow chest item generation and placement before a player can use a chest.

`Chest::open` now selects the [MM6 open-only owner transaction](MM6-F4-Chest-Open-Owner-Transaction.md) after validating the chest index. `GUIWindow_Chest` uses the source-backed hardcoded 9×9 grid despite different `dchest.bin` metadata; headless GUI update has passed, while rendered pixels remain unchecked. Click and Grab Item can mutate items, held cursor and party gold in the inherited path, so MM6 currently returns without mutation. Active-map changed-state encoding and the complete `.ec6` transaction must preserve a nonzero chest across map leave, save and reload.

The [detached placement](MM6-F4-Chest-Placement.md), [caller](MM6-F4-Chest-Generation.md), [bounded runtime projection](MM6-F4-Chest-Runtime-Projection.md) and [live-owner adapter](MM6-F4-Chest-Live-Owner-Adapter.md) pages carry proved subsets. Delta writers can encode a synthetic nonzero chest grid, but trap behavior, interaction cues, rendered UI and durable persistence remain open. A real first-map chest opened and drew through NullRenderer in a monitored headless test; no visible chest pixels have been accepted.

An opt-in [first-open transaction](../project/MM6_F4_CHEST_INTERACTION_GATE.md) now stages original 9×9 placement plus one visible-grid pickup on copied record, RNG, held-item and party-gold values. Ordinary item pickup moves an `Item` into the held slot; gold pickup requires an explicit net credit because original MM6 share/hireling effects remain unproved. Trapped chests, occupied cursor, bad grid references, malformed wire and MM7 reject with no owner mutation. An initialized chest reopens without a second placement draw. The helper does not commit `vChests`, the map sidecar or `.ec6`, and does not reproduce unproved trap, cursor-offset or hidden-item behavior. Focused native tests passed 3/3; the live chest guard remains closed.

The later `stageChestCursorPickup` joins that detached non-gold pickup to the exact 28-byte MM6 raw held-cursor owner. It requires an empty cursor and a source-backed raw record, rejects gold or a foreign/occupied owner, and leaves the original chest/cursor inputs unchanged. The resulting chest record clears the item's supported prefix while preserving its opaque tail, and the cursor receives the complete source record. Focused linked chest/open/cursor checks passed 11/11. This is not yet wired to the live click handler: cursor image creation, Party publication, sidecar publication and v2 save admission still need one failure-safe transaction.

A targeted read of retained original-PE chest entry confirms a different MM6 trap decision from the inherited MM7 threshold. Placement precedes active-character/trap checks; a nonzero disarm score draws `LCG % 10`, and strict `score + roll > 5 × map difficulty` disarms. Zero score skips that draw. A trigger draws `LCG % 4` for a variant, creates a sprite, clears the trap bit after sound, and does not open the UI. Source sprite order is fire, cold, lightning, body; the inherited source swaps the middle two. `stageChestTrapDecision` returns only outcome, original sprite ID and RNG state, with no changed chest, damage or UI state; 4/4 seeded native tests passed.

The original score callee takes low-six-bit skill level, doubles it once for each of three unbroken equipment categories (raw IDs 410, 415 and Thievery enchantment 35), adds Tinker/Locksmith/Burglar +4/+6/+8, then multiplies by 2/3/4 for basic/Expert/Master. Its ID 415 branch joins at one doubling; the 16-slot enchantment scan stops at its first unbroken match, so duplicate items do not stack within a category. `scanChestDisarmEquipment` models the fixed slots and first-match rule on a detached snapshot, and `stageChestDisarmScore` computes the score; 4/4 focused score tests passed. The character/equipment/hireling projection is not live. The entry span has no direct synchronous explosion call, so sprite lifecycle/impact damage and status need a separate original trace. The retained manual's broad chance/telekinesis description and guide gold-bonus notes do not establish damage or net hireling-adjusted chest gold; the explicit net-credit requirement remains.
