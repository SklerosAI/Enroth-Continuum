# MM6 six-table role closure packet (F2)

Status: **source and retained-copy classification, not original-game or live validation** (2026-11-05). The [30-family matrix](MM6_TABLE_SEMANTIC_F2.md) found 24 literal C++ text-table loads and six without one. This packet checks those six against all current `eventsData` call sites, their retained structures, and pinned [GrayFace MMExtension source](https://github.com/GrayFace/MMExtension/tree/9d73c0ff0482bd231ea522f752f4fe9b26640925). A nonliteral filename is not proof of an unused original file. No installed MM6 archive or executable was read and MM6 was not launched. Exact rows and input hashes remain in ignored `local-game-data/mm6/research-2026-11-05/unloaded-table-roles-f2-private.json` and the earlier `unloaded-table-probe.json`.

## Source boundary and finding

The current `ResourceManager::eventsData` is a single named-entry lookup in `src/Engine/Resources/ResourceManager.cpp`; the nonliteral call sites found under `src/` construct map `.evt`/`.str` names and a code-generation `.evt` name. None constructs one of these six table names. `Engine.cpp` loads singular `autonote.txt`; `NPCStats::InitializeMm6` loads `npcprof.txt` but neither `proftext.txt` nor `npcbtb.txt`. `MM6ItemTable.cpp` has no `useitems.txt` path. This is a **current-fork** source result, not a proof about the original binary or external mods.

## Decisions and acceptance

1. **Before F3:** Keep all six in the private file manifest. Treat `npcbtb`, `proftext`, and `useitems` as active implementation leads; treat `passwords` and plural `autonotes` as unassigned provenance/consumer questions; treat `errorlog` as a diagnostic candidate. These are evidence levels, not declarations of original reachability.
2. **F3, one read-only original preflight:** Recheck entry names, sizes, bytes, and archive provenance against the retained hashes. Validate MMExtension's MM6 BTB remap, profession news layout and autonote category index against the owner's executable version and actual table rows. Search original code/data references for `passwords` and `errorlog`, trace opcode-26/27/28 password flows, and settle the two plural-note differences and twelve singular-only rows. Reconcile `useitems` numeric IDs and five markers with original effects without assuming the guide wins either disputed result. Keep executable offsets and exact content private.
3. **F4, offline engine:** Parse and bound every active row/column in the three strong mechanic leads; exercise all 841 item-matrix cells and representative marker outcomes; cover all 13 BTB personality slots, action accept/reject and text selection; cover seven weekday topic/text slots across all 77 profession rows; cover note categories and every script-used note ID. Question correct/incorrect/cancel and any real password-catalog path need separate tests. If F3 proves a table incidental, document the proof rather than adding a loader. Fix `awards.txt` through a title-specific rule in its own work item.
4. **F5, graphical and persistence:** Inspect beg/bribe/threat choices and `%13` substitution; change weekday and inspect profession news; mix safe and failed combinations and verify consumed items, resulting item, damage and note changes; display changed/added autonotes; exercise all relevant Question/password branches; save/reload each stateful case. Confirm MM7 remains isolated while MM6 paths run.

The ignored report retains fingerprints, numeric join details and source addresses. It deliberately contains no claim that F3, F4 or F5 has run.
