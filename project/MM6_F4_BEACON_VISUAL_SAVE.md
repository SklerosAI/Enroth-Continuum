# MM6 beacon and thumbnail save boundary — F4

Status, 2026-11-06: **standalone bounded `BEAC` v1 codec and detached MM6 map-resolution seam; not yet part of the required known-save assembly or live SaveLoad**.

The current `LloydBeacon` contains expiry time, 3D position, yaw/pitch, one opaque 16-bit word, a runtime `MapId` and a 92×68 screenshot. `Character::setBeacon()` assigns those values from the loaded map and renderer. The inherited MM7 snapshot serializes a map ID through a fixed MM7 Games LOD index table, then stores beacon PCX images separately. That index table has no MM6 identity contract. The current save path takes a 150×112 thumbnail. The accepted F3 source gate verifies the MM6 map archive/table family and all 67 map pairs, but its private signoff contains no native whole-save beacon or thumbnail field layout. This section is a **new logical current-runtime format**, not a native MM6 save importer.

`BEAC` v1 stores a version/count header, an optional exact 150×112 RGBA thumbnail, and four characters × five ordered optional beacon slots. Each occupied slot stores a positive bounded expiry tick, lowercase `.blv`/`.odm` base-map filename (5–64 bytes including extension, with no path separators), finite bounded position, signed yaw/pitch, the opaque word, and exact 92×68 RGBA pixels. Channels are copied explicitly in R, G, B, A order, including alpha; no PCX decoder, GPU texture, MM7 Games LOD index or absolute owner path enters the payload. The section is required when used and has a 600,000-byte cap within the `.ec6` container cap. Truncation, bad shape/version/name, wrong title, malformed image length and nonfinite position reject before a caller destination is assigned.

`captureBeaconRecord()` takes one current beacon, its CPU screenshot, the current map table and a caller-supplied F3-verified 67-delta name set. It checks that the beacon's runtime map ID maps uniquely to its base filename and that the corresponding `.dlv`/`.ddm` companion occurs exactly once. `stageBeaconVisuals()` checks the same title and manifest boundary for every saved filename and returns current map IDs plus copied CPU RGBA bytes without changing a Party, renderer or map table. This avoids retaining a numeric MM7 map ID across MM6 saves. A caller must still prove the 67-name set's F3 identity; cardinality alone is not provenance.

The existing 18-section `KnownSaveFields` assembly deliberately rejects `BEAC`, and `requireNoUnrepresentedBeacons()` still rejects active beacons in known-save capture/stage. Before those guards can open, integrate the section into the complete mandatory manifest, capture all 20 Party slots and the save thumbnail under a stable game-thread boundary, cross-check expiry against the core clock, and build renderer-owned `GraphicsImage` objects only after all validation and no-throw world/Party commit are proved. Lloyd spell setting/recall, map transition, image appearance and save–quit–relaunch–load remain separate F5 checks. No MM6 game process, original installation, private image or save was opened or added to Git.

The new codec/runtime/test translation units syntax compiled with integrated arm64 flags. A standalone native probe passed filename-keyed capture, exact RGBA round-trip, detached map resolution and old-version rejection. The focused unit source also covers an empty new-game section, all 20 slots, wrong title, ambiguous/missing map resolution, malformed image/name/CRC-valid payload and unchanged destination. Linked unit execution remains for main integration.
