## Detached first-open and one-item transaction

`mm6::stageChestFirstOpenInteraction` composes the retained 9×9 first-placement model with a bounded `ChestInventory` projection. It stages either open-only or one visible-grid pickup on copies of the MM6 raw record, LCG state, held item and party gold. For ordinary items, it removes the selected inventory entry and returns that item as held. For gold IDs 197–199, it removes the entry and requires a caller-supplied nonnegative **net credit** before staging the gold increase. The exact original MM6 hireling/share result is not yet proved, so the helper will not infer it. It rejects trapped chests, an already held item, invalid grid points, malformed wire, failed icon lookup, foreign titles and gold overflow without changing the caller's owners. An initialized chest reopens without another placement draw. The raw record keeps its opaque item-tail bytes and changed 140-cell grid.

The accepted original-MM6 entry trace proves first placement occurs before active-character/trap checks. The retained placement trace proves the 81-slot 9×9 algorithm and wand-charge fallback. Retained evidence does **not** prove the trap effect, pickup cursor offset, net-gold settlement, hidden-item handling or debug repeat-placement rules. Rejecting trapped chests is a deliberate fail-closed restriction of this detached helper, not a claim about original ordering. Its returned result is not published to `vChests`, the active map sidecar, `.ec6` or the live chest UI. Focused arm64 native tests passed 3/3 for first-open/reopen, ordinary pickup, explicit gold credit, rollback and MM7 isolation; no MM6 game process was launched.
