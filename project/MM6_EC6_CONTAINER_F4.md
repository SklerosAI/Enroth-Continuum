# MM6 `.ec6` container foundation — F4

Status: **offline container and field codecs, 2026-11-06; no complete live MM6 save transaction**. The standalone `engine_mm6_save_container` library writes and validates a title-tagged, versioned byte container and has partial v1/v2 field assemblies for party, character, event and map state. It does not publish the full field set into game globals or provide a live MM6 slot workflow. It is separate from MM7's `SaveGame_MM7` path.

## Versioned envelope

All integers are unsigned little-endian. The fixed 24-byte header has eight signature bytes (`EC6SAVE` followed by NUL), a 16-bit version, zero 16-bit flags, a 16-bit section count, a zero 16-bit reserved field, 32-bit exact total size and CRC-32 of the bytes after the header. A section has a four-character uppercase ASCII/digit/underscore tag, a 16-bit required bit, zero 16-bit reserved field, 32-bit payload length and CRC-32 of its payload, followed by its bytes. CRC-32 uses the standard reflected polynomial. The decoder validates the whole stream before returning a temporary `SaveContainer` value; it has no references to live engine state. The container now accepts versions 1 and 2 and returns the version with the decoded sections; future versions reject. The known-field assemblies impose stricter version-specific manifests: provisional logical v1 requires eighteen tags, while the coordinated raw v2 candidate requires nineteen. Existing atomic slots still require the v1 known-field decoder.

The limits are 64 MiB per file, 32 sections and 32 MiB per section. The codec rejects zero/duplicate sections, malformed tags, unsupported version, wrong title, reserved bits, truncated or trailing data, oversized lengths, checksum mismatches and unknown **required** sections. Unknown optional sections remain opaque at the generic container layer; both known-field assemblies reject optional extras before mutation. The container encoder accepts structurally valid section tags so a later version can preserve optional extensions; the assembly decoder is the current compatibility boundary.

## Validation and next lock

The container unit source covers round-trip with an optional unknown section, wrong title, future version, truncation, corruption, trailing bytes, unknown required section, duplicate tag and empty container. A focused Mac build of the current container library and test object succeeded; a linked harness passed the four v2 raw, nine v1 known assembly and three container cases. These tests use synthetic fields; no private save or game state was written.

Before this becomes a working `.ec6` save, F4 must finish the mandatory field set, including beacon and unresolved runtime owners; validate the expected 67-map names and original base/delta compatibility; stage every owner before one global commit; and connect the v2 candidate to title-specific slots and atomic file policy. F5 must then save, quit, relaunch and inspect state in the graphical game. No native `.mm6` import is implied.
