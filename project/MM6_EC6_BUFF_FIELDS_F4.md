# MM6 `.ec6` timed buff fields — F4 offline progress

Status: **bounded `BUFF` v1 section and MM6-only capture/copy-staging; not wired to live saves** (2026-11-06).

The current runtime holds 20 indexed party `SpellBuff` slots and 24 slots for each of four characters. The inherited MM7 snapshot uses 16-byte wire records, but this `.ec6` section is a new logical runtime format and does not claim to reproduce a native MM6 save. The private F3 logical-field manifest grouped conditions, resistances and buffs as an effect family without proving original buff widths; the existing `EFFT` codec already owns condition clocks, so this implementation uses the separately registered `BUFF` tag. No original GOG installation was reread.

Every one of the 116 fixed slots stores expiration ticks, power, mastery, overlay ID, caster and `isGM`, in index order. `-1` expiration preserves the runtime expired sentinel, zero is inactive, and positive ticks are active; the positive bound avoids overflow in `Time::toSeconds`. Mastery is bounded to MM6's none/novice/expert/master range. `isGM` remains a separate boolean: current [NPC.cpp](../src/Engine/Objects/NPC.cpp) marks Wind Master and Water Master buffs this way at Master mastery to suppress mana drain. Rejecting that flag would lose a distinction present in the current source path, though MM6 gameplay reachability is not yet proven. Caster is limited to `-1` external source or character indexes 0–3, and overlay ID to the 50-slot runtime overlay list. The decoder requires exact version, counts, length, required tag and outer container integrity before assignment.

`captureBuffFields` checks MM6 title and every serialized field; `stageBuffParty` decodes first, copies the live party, and assigns buff members on the copy without invoking `SpellBuff::Reset` or `Apply` (which can mutate global overlays). The caller must commit that copy only after all other `.ec6` sections and world state validate. This adapter does not resolve title-specific spell effects, party/character buff ID semantics, dispel order or overlay-to-`VISU` reference consistency. Those need further offline and F5 tests, including NPC flight/water-walk, a buff expiring across save/relaunch, and a visible overlay. The integrated partial known-save manifest now requires `BUFF`; `SaveLoad.cpp` remains guarded for MM6.

The current `SpellBuff` code treats a nonzero overlay ID as a one-based index into the 50-slot active-overlay list when resetting or replacing a buff. The codec therefore bounds it to 0–50. The overlay animation may finish before the buff expires, and an overlay slot can be reused; a rule requiring `VISU[overlayId-1]` to remain active for every active buff would reject a plausible current-runtime state. Full staging must preserve the bounded ID and test reset/replacement after load, rather than assert a stronger slot-content join without original behavior evidence.

Focused synthetic tests cover all slots, the NPC Master/`isGM` distinction, expired sentinel, malformed counts/length/version, invalid time/mastery/overlay/caster, valid-CRC bad records leaving the destination unchanged, and wrong-title/corrupt-container rejection. Runtime capture/staging still requires an integrated scenario test with an initialized party.
