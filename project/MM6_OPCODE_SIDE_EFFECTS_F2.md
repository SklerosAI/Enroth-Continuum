# MM6 active EVT side-effect contract (F2)

Status: **source-backed implementation contract, original side effects unverified** (2026-11-05). This extends the [43-opcode structural register](MM6_OPCODE_SEMANTICS_F2.md) into target state, control flow, persistence and acceptance obligations. It uses the retained, ignored `opcode-semantics-probe.json` and `event-variable-probe.json`, current [parser](../src/Engine/Evt/EvtInstruction.cpp), [interpreter](../src/Engine/Evt/EvtInterpreter.cpp), [trigger processor](../src/Engine/Evt/Processor.cpp), and [program hint logic](../src/Engine/Evt/EvtProgram.cpp). The [MMExtension command reference](https://grayface.github.io/mm/ext/ref/) and [MM6 editor format source](https://github.com/angeld29/mm8leveleditor/blob/master/src/org/gamenet/application/mm8leveleditor/data/mm6/fileFormat/EventFormatMM6.java) supply independent *leads*. No original archive was reopened and MM6 was not launched for this audit.

The retained index covers **68 active EVT files, 14,477 framed records and all 43 values 1–43**. Widths and active counts are in the structural register; exact operands, offsets and event names stay ignored locally. In the table below, **flow** is the current C++ route where present, followed by the MM6 obligation. **Persist** names state that must be tested across an `.ec6` save or map revisit, not a proven native layout. **Lead** means a retained frame plus an independent command or source-path interpretation; **open** means original meaning, operand order, target or timing is unresolved. A present inherited switch case never proves MM6 behavior.

## High-conflict implementation order

1. Separate MM6 wire decoding and semantics by title before dispatch. Preserve the original MM7 parser/executor path. Validate all 14,477 MM6 frames with exact byte consumption; unknown active commands must fail with a source locator, not become no-ops.
2. Resolve opcodes **12, 19, 20, 24, 26, 27 and 28** at the planned single read-only F3 original-file pass where possible. Until then, the identified current C++ cases are diagnoses, not fallback behavior. The seven opcode-20 records share a single event; the rare 27/28 commands need surrounding event context in the ignored report. Do not build a public implementation from the editor names alone.
3. Implement [typed MM6 variables](MM6_VARIABLE_DISPATCH_F2.md), then branch/selector/wait semantics and title-specific map, actor, item, spell, NPC, house, text and timer state. Treat trigger commands 31/37/38 as registrations, not normal event steps.
4. Tie every written field to a versioned `.ec6` save and negative cross-title load checks. Run offline scenarios for **each active opcode** and each payload variant, then visible F5 checkpoints for texture/facet, spawn, question, travel, combat, NPC, chest, timer and finale effects. Verify save/quit/relaunch/load wherever the table names persistence.

This is an F2 *contract* rather than a claim of original-game equivalence. The [F2 gate review](MM6_F2_GATE_REVIEW.md) remains open. F3 may confirm original data and some executable dispatch, but only F4 code plus F5 graphical campaign play can prove the side effects and reachability.
