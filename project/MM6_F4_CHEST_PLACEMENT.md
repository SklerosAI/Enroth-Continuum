# MM6 F4 chest placement contract

Status: **detached model only; the live MM6 chest generation guard stays closed** (2026-11-06). A bounded read-only trace of the accepted original-MM6 executable was reconciled with the retained 4,204-byte chest record and `dchest.bin` layout metadata. Exact disassembly, addresses, input hashes and per-record details remain in ignored `local-game-data/`. No game was launched or original installation reopened.

## What the original placement pass does

The original runtime chest has a four-byte header, 140 consecutive 28-byte item slots, and 140 signed 16-bit grid cells. The latter start directly after item slot 139, occupying the full final 280 bytes of the 4,204-byte **in-memory** chest. This resolves the in-memory interpretation left open in the F2 baseline audit: those bytes are addressed as a grid, not as 81 cells plus a 118-byte tail. The retained shipped delta records have zeroes throughout this region. A later [original-executable save-path trace](MM6_F4_CHEST_GRID_WIRE.md) proves the serialized delta copies the identical full 4,204-byte record, including all 140 grid cells.

The placement entry takes the chest type's width and height from original hardcoded per-type arrays, observed as 9×9 for all eight types. The [type and entry trace](MM6_F4_CHEST_TYPE_ENTRY.md) establishes that the retained MM6 `dchest.bin` metadata instead describe a 14×10 grid; that metadata must not be substituted for the placement caller's dimensions. The original placement and display paths use the first 81 slots of the larger 140-slot storage. The pass builds a 144-byte ordering buffer for the selected area. For each area index it draws the original 15-bit RNG, masks to eight bits, rejects samples outside the area, and advances circularly to a still-zero buffer cell. The stored order index starts at zero, a zero value also used as the vacant sentinel. That quirk can move the first choice, and the model preserves it. The pass then visits the **first `width × height` item slots**, skipping empty IDs. It tests shuffled grid cells in order, using each item's icon width/height clamped to at least 14 pixels, with footprint `(pixels - 14) / 32 + 1` on each axis. A fit needs the entire rectangle inside the chest and every covered cell zero.

On a successful fit, placement writes the item slot's one-based index to the anchor cell. Other cells of that rectangle receive `-(anchor cell index + 1)`. A zero-charge item with an ID in the MM6 wand band 135–159 draws once and gains `10 + RNG % 21` current charges **only after fit**; an ANY-generated wand normally already has charges from its picker. No potion-power write appears in this placement helper. If no position fits, the item stays in its slot with no grid reference and no wand draw. The outer pass still sets the chest's initialized bit after trying every item. The original chest entry calls placement before active-character and trap checks when the initialized bit is clear; the detached model does not wire that call.

## Detached implementation and tests

`mm6::placeChestItemsDetached` takes a title, explicit dimensions, 140 caller-supplied item IDs/icon sizes/charges, an initially zero 140-cell grid, flags and an RNG seed. It rejects MM7, invalid dimensions, negative marker IDs, malformed item rows, nonempty grids and already-initialized input before returning any state. It copies all fields, reproduces the seeded shuffle, fit, grid writes and conditional wand draw, then returns staged items/grid/flags/RNG and placed/unplaced counts. It does not touch `Chest`, `ChestInventory`, a live RNG, graphics, audio or save files. A one-million-draw safety budget rejects pathological shuffle inputs without publishing state.

Native seeded tests cover a mixed three-item chest and wand, a full chest where an unplaced wand consumes no charge draw, a **synthetic** 14×10 anchor beyond cell 80 to exercise the 140-cell storage bound, malformed/foreign-title rejection, and unchanged caller input. The earlier detached ANY item picker and finalizer are separate; no runtime adapter joins them yet. The public [chest generation audit](MM6_F4_CHEST_GENERATION_AUDIT.md) and [wiki page](../.llm-wiki/MM6-F4-Chest-Placement.md) retain the broader gate.

## Remaining gate

Before a live MM6 generator can run, join the detached [chest-type adapter](MM6_F4_CHEST_TYPE_ENTRY.md) to item generation and rendering; reconcile fixed/ANY items and the direct artifact path with the original 81-slot placement area and 140-slot storage; connect the now-proved signed grid wire to changed live snapshots and unplaced items through `.ec6`; and prove reset, full-chest and save–reload behavior. An initialized nonempty grid and repeated placement are deliberately outside this detached first-placement model. The inherited `Chest::PlaceItems` and `Item::postGenerate(ITEM_SOURCE_CHEST)` remain MM7 behavior despite sharing a 9×9 shape. The unconditional MM6 load guard still blocks all MM6 level loads reaching it, including marker-free maps.
