# MM6 `.ec6` header, time and visual metadata — F4 offline progress

Status: **bounded `HEAD`/`TIME`/`UIST`/`VISU` v1 field codecs and copy-staging adapters, 2026-11-06; no live save/load path**.

`HEAD` stores a bounded display name, lowercase `.blv`/`.odm` map filename and party playing-time ticks. The pure decoder rejects control bytes, path separators, unsupported extensions and negative time. Runtime staging checks the name against the loaded MM6 map table and Games LOD without calling the inherited `GetMapInfo` assertion on untrusted text; it returns the validated header without changing the active engine map. The map is an identity for a later all-family transition, not a transition performed here.

`TIME` stores total event/simulation ticks, not `_lastFrameTime` or `_dt`, which depend on the previous process's OS clock. `Timer::restorePausedSimulationTime` stages a timer paused, out of turn mode, with zero frame delta and the saved total. The next unpause will establish a fresh platform timestamp through the existing `setPaused` path. This method is unused by MM7 and does not change its serializer.

`UIST` records the active-character index and an explicit `resetTransientUi = 1` policy. Active selection already appears in `PART`; `validateMetadataAgainstCore` rejects a disagreement between those two indexes or between `HEAD` and `PART` playing-time ticks. Window, casting and book-flash state remain intentionally transient under the current load behavior; this packet does not add a UI reset call. The full save transaction must run the cross-section validator before committing any globals.

`VISU` stores the current 50 overlay records: table index, animation/frame time, screen position, packed PID, projected size and damage modifier. Runtime staging copies the overlay list and rejects an active record whose table index is absent from loaded MM6 `doverlay.bin`. It does not prove the referenced PID object still exists after map reconstruction or that every visual frame renders correctly; those are all-family/F5 checks. The original MM6 overlay semantics remain more than a byte-layout question.

All four sections are required, versioned and length checked inside the title-tagged CRC container. `loadMetadataBeforeMutation` decodes every section into a temporary value before assigning its destination; runtime header, timer and overlays each stage on copies or immutable fields. No adapter is called by `SaveLoad.cpp`, and `.ec6` slot listing remains disabled. The [whole-save register](MM6_SAVE_FIELD_REGISTER_F2.md) still requires the other state families, atomic writes and all-family load transaction.

Offline evidence: codec, runtime adapter and new unit source passed C++23 syntax checks with project flags. A compiled standalone harness round-tripped nonzero metadata, rejected a valid-CRC negative timer without mutating the destination, rejected cross-section active-character mismatch, and verified the paused-timer reset. Focused C++ unit cases cover the full field round-trip, malformed/wrong-title rejection, required-section and policy checks, cross-section consistency and timer staging. The integrated unit binary has not yet run for this change; no MM6 game or original installation was opened.
