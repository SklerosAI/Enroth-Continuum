# MM6 F4 Quick Start

An identity-matched static MM6 executable trace separates the original Quick Start choice from editable Create Party and identifies the four-character setup without activating it in Enroth Continuum.

The opening buttons lead to distinct state and caller branches after a shared reset. The Quick Start finalizer writes each character's class, face, localized name, seven stats and four skills. The four stat allocations total the documented 50-point pool, satisfy the corrected class bases and bounds, and follow two granted plus two selectable class skills. The exact fixture and code locators are kept in an ignored owner-local audit.

The finalizer generates starting inventory by learned skill, invokes item placement helpers and uses randomness. A second static pass verified all sixteen learned-skill passes: seven equipment grants, six first-spell/book grants, and three bottle-plus-random-herb grants. A separate weighted random item is generated for each character, and one opening letter is added. An ignored local checker matched the dispatches and item categories without exposing exact IDs. The complete random-item outcomes, equipped slots, voice selection and later initialization effects are still unproved. [The public audit](../project/MM6_F4_QUICK_START_AUDIT.md) gives the bounded unlock checklist. The current default party remains provisional; `GameStarterOptions.quickStart` is only an application initialization option.

The [pinned MMExtension player schema](https://github.com/GrayFace/MMExtension/blob/9d73c0ff0482bd231ea522f752f4fe9b26640925/Scripts/Structs/00%20structs.lua#L1390-L1500) confirms the observed MM6 face, spell and inventory offsets. It lists a separate Voice field for MM7/8 only. Face-derived MM6 voice is a **schema inference**, pending a direct original sound-selection trace.

Evidence level: **static source semantics**. There was no MM6 process, rendered opening screen, live item state, or save/reload validation. Do not activate Quick Start until all starting fields, input route and durable save transaction are proved.
