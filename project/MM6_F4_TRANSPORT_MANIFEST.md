# MM6 transport constants — private F4 manifest

Status: **F3-derived private descriptor exported; transport UI and departure remain unimplemented** (2026-11-06). The MM7 `Transport.cpp` static schedule and house-index array are not MM6 rules. Six MM6 stable IDs fall outside that inherited array. Do not use its route-selection path for MM6.

`scripts/mm6_f4_export_transport_rules.py` reads only the ignored, corrected F3 PE v2 report after checking its SHA-256 against the F3 gate hash registry. It writes a mode-0600 `rules/transport.json` under the MM6 user profile and refuses overwrite. No executable bytes, route constants, destination names or asset inventories are copied into Git. The exporter checked **36 travel descriptors**, **21 houses × three slots**, and **37 populated source cells**. It retains original one-based Games LOD destination indices for `MapTable::GetMM6TransportMapInfo`, seven executable weekday flags, duration, arrival position/yaw and quest-bit candidate. Blank slots remain marked blank rather than treated as valid travel just because the executable index table has a value.

The 37 populated cells comprise 34 regular schedule candidates, one weekday-token ambiguity and two opaque specials. The manifest marks these categories explicitly. The static executable mask agrees with the retained regular weekday text in 33 of 34 cases; the remaining regular mismatch and two guide-duration disagreements remain F5 policy checks. The `S` token has a Saturday-consistent static reading, not observed behavior. Fare, quest gating and the one indoor destination need runtime verification. The UI must leave special cells disabled until their original effect is established.
