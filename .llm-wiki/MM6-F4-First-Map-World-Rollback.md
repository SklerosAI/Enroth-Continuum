# MM6 First-Map World Rollback

This page tracks the staged first-map world plan and the owners still missing from a failure-atomic MM6 reload.

The [rollback audit](../project/MM6_F4_FIRST_MAP_WORLD_ROLLBACK_AUDIT.md) enumerates owners changed by `loadAndPrepareODM` and `DoPrepareWorld`. The monitored scoped save observer now runs before any disk/cache/CHST publication, so its failure leaves those owners unchanged. A separate isolated headless check writes a temporary `.ec6`, publishes its 67-map cache and CHST, and then reaches New Sorpigal through `DoPrepareWorld` with actors and twenty chests. This is successful staging plus entry, not a failure-atomic full-world commit or normal SaveLoad.

`ScopedFirstMapWorldCollections` swaps the prior actor, sprite, chest and decoration containers into private storage and exposes empty scratch containers. Its optional `FirstMapOutdoorDeltaOwners` argument joins the MM6 DDM metadata/wire, last-visit time, map weather, discovery grids and actor reuse cursor to the same rollback/commit scope. The binding helper points directly to the corresponding live `OutdoorLocation` fields; it neither copies nor constructs that listener-bearing object. A synthetic late fault now verifies restoration across all eleven owners, and a separate assertion verifies explicit commit. An incomplete binding is rejected before any mutation. The linked save/world suite passed 14/14. `pOutdoor` still owns terrain and image/resource pointers; Party placement, engine transition/event state, global weather/camera/UI/audio and spawn/reload effects also lack a complete rollback. Do not call `loadAndPrepareODM` through the scoped save callback as an atomic transaction until those owners have a staged or snapshot policy and monitored failure tests. Normal MM6 SaveLoad remains guarded.

`ScopedFirstMapPlacementAndEvents` protects the first-map Party placement/movement fields and local engine transition/event owners. It installs the staged New Sorpigal position and a validated pending destination, swaps local EVT program/strings, and snapshots map/type, engine flags, transient bytes and last-save selection. A late fault test restores them exactly. The separate scope below now covers persistent event-variable arrays; other Party actions, event side effects, the outdoor object and resource/UI effects still prevent a full loader callback or opening SaveLoad.

`ScopedFirstMapPersistentEvents` snapshots the initialized `Engine::_persistentVariables` owner: 75 map bytes and 125 decoration bytes. Outdoor delta reconstruction assigns both, decoration respawn can clear/repopulate decoration bytes, and `onMapLoad` interpreter calls can write either array. Foreign-title/null rejection, late-fault restoration of both full arrays and explicit commit are in a three-case synthetic unit test. Its arm64 translation unit passed syntax compilation, and a separate linked assertion probe of late rollback/commit exited 0; the integrated linked test remains to run. This bounded scope is not wired around `DoPrepareWorld`, and it does not cover event-trigger lists or event effects on Party/world/UI.

`ScopedFirstMapCombatTransients` covers pending attacks, the actor-filtered turn queue, nearby-actor targets and nearby-actor IDs. It prepares allocating queue/resize work off-owner, then swaps in the reset state with a no-throw rollback path. The scope also snapshots seven scalar fields of the same turn-engine object and restores them with its queue. The revised integrated linked three-case test passed 3/3 for invalid scope, late-fault restoration of all containers/scalars, and explicit commit. Actor AI after load, outdoor resources and other world owners remain outside this scope. It is not wired into the guarded production loader.

The deeper outdoor-object audit found a hard prerequisite before any whole-object swap. `Engine::_outdoor` owns the object and global `pOutdoor` aliases it; the constructor immediately registers a season listener capturing its address and the destructor removes it. `Initialize/Load` releases renderer terrain and the global minimap, acquires minimap/sky image handles, reconstructs decorations/actors/sprites/chests into global collections, and calls global `pOutdoor` for season change even if a different object receives `Load`. Faces and sky carry raw image handles. Thus a speculative `OutdoorLocation` is observable before commit, and a pointer swap would not roll back resource/global effects. The [audit packet](../project/MM6_F4_FIRST_MAP_WORLD_ROLLBACK_AUDIT.md) names the smallest prerequisite: an MM6-only inert, target-explicit prepare from the validated typed active map and DDM into detached geometry plus world collections, followed by a separately proved no-throw publication/listener/asset ownership step. No whole-object rollback helper was added, and the live guard remains closed.

The first part of that prerequisite is implemented as `prepareDetachedOutdoorWorldPlan()`. Given a staged MM6 outdoor candidate, it owns the decoded base snapshot, saved delta, raw active CHST sidecar projection and flattened model face vertex references. It checks map/sidecar identity, model/decorations/spawn/record counts, face-local vertex bounds and runtime-supported spawn types without constructing an `OutdoorLocation` or touching renderer, assets, listener or globals. A synthetic triangle test injects a late invalid face reference and proves the prior detached plan remains intact; the private headless save test also requests a plan for New Sorpigal. A local aggregate read found no topology violations across the 15 retained outdoor bases. The linked world-save suite passed 8/8 and monitored private save GameTest passed 1/1 after this first plan integration. Terrain normals and seasonal transitions, texture ownership, BSP/decoration/encounter reconstruction, listener publication, collection handoff and rollback remain open.

The next bounded addition prepares flattened runtime vertex positions and `SpawnPoint` values from that same owned snapshot. The actor/sprite spawn type is checked before the target-only conversion; synthetic data now verifies nonzero vertex positions and one actor spawn's position, radius and monster index, with an invalid-type late fault. The private headless save check also requires nonempty vertices and matched spawn counts. Linked `MM6WorldSaveRuntime.*` passed 8/8 and the private GameTest passed 1/1 twice. The host monitor sampled zero game windows and no focus change, but its strict final frontmost-app check exited 1 after the user switched from Skleros Chess to ChatGPT following child exit; this is a monitor caveat, not a GameTest failure. Encounter/treasure execution, decoration descriptors, textures, seasonal terrain behavior and global publication remain outside this pure plan.

The next terrain slice resolves all 127×127 runtime cells from the 128-stride ODM tile map using the four MM6 global tile selectors and an explicit loaded tile-table count. The detached plan rejects absent or out-of-range selectors and IDs before live terrain reconstruction. The live `OutdoorTerrain` reconstruction and detached plan now call one shared local-to-global tile-ID mapping helper, so this preflight cannot drift from the loaded-world mapping. A synthetic boundary case covers all four selector ranges, reserved IDs, an exact upper table bound and a late invalid-selector fault that leaves the prior plan intact. After integration, the combined focused world/item/shop unit suite passed **18/18**; separate hidden MM6 processes wrote the temporary `.ec6` and re-entered the first outdoor world from it (**1/1** each), with no visible window or focus change. The monitored MM7 all-map reconstruction control passed **1/1** with the same no-window/no-focus result. This does not yet prepare normals, seasonal transitions or textures, or provide no-throw outdoor publication.
