`saveNewGameMM6ScopedForTest()` proves the first-map `.ec6` preflight, atomic disk write and exact rollback of the slot pair, map-delta cache and CHST title owner. The bounded helper requires explicit MM6 title and four nonnull collection owners. Its constructor swaps all four to empty scratch state only after those checks; `rollback()` and destruction restore the prior containers in reverse order, while `commit()` leaves the new collections. It uses no global engine or private game data and can be embedded in a later test callback. It **does not** make `loadAndPrepareODM` safe by itself. A future experiment must first stage or snapshot every remaining owner above, inject failures after outdoor reconstruction and after map-entry events, and prove rollback of the disk slot and all process state in the monitored headless harness before the normal SaveLoad guard can open.

`ScopedFirstMapPlacementAndEvents` is the next bounded test-only scope. It requires a staged Party at the exact New Sorpigal arrival coordinates, a valid destination and explicit MM6 title before any mutation. It constructs the next transition first, then uses no-throw swaps for the local event program, level strings, last-save selection and pending destination; scalar and fixed-size placement/map/flag fields are copied. A late synthetic fault after changing Party position, map/type, pending transition, event program/strings, transient bytes and engine flags restores the original values. This can be composed with the collection scope, but the remaining outdoor/resource/persistent-event owners in the table still prevent a safe full `loadAndPrepareODM` callback.

## Outdoor object ownership and the next prerequisite

`Engine::Initialize()` constructs one `std::unique_ptr<OutdoorLocation> _outdoor` and publishes its raw alias as global `pOutdoor` (`Engine.cpp`). Render, collision, Party and map-entry code dereference that alias. `OutdoorLocation` is not a passive value: its constructor resolves decal/spell-renderer pointers and registers a `SeasonsChange` listener capturing `this`; its destructor deregisters that listener (`Outdoor.cpp:970–985`). Constructing a speculative second object would immediately add a live listener. A raw `pOutdoor` or `_outdoor` swap would leave the listener and the global alias to coordinate, and copying the object would duplicate resource pointers and callback-sensitive state.

`OutdoorLocation::Initialize()` calls `Release()` before `Load()`. `Release()` releases renderer terrain, releases the view's minimap image and clears the global minimap pointer. `Load()` acquires another minimap image, reconstructs terrain, faces and models into the target, but reconstructs decorations into global `pLevelDecorations`. Its MM6 delta branch reconstructs global `pActors`, `pSpriteObjects` and `vChests`, changes the global actor-reuse index, and stores `mm6DeltaBytes` on the target. Near the end it acquires a sky bitmap into `sky_texture` and calls `pOutdoor->pTerrain.changeSeason(...)`, even when `this` is a different object. `BLVFace::texture` and `OutdoorLocation::sky_texture` are raw `GraphicsImage*` handles; `decal_builder` and `spell_fx_renderer` are service pointers. `loadAndPrepareODM` then adds spawn/random, weather, camera, music, progress and other global effects. A replacement of `_outdoor` alone cannot restore these effects or the prior resource references after a late fault.

**Decision:** no test-only whole-outdoor swap owner is added yet. Its precondition, a detached construction/load with no observable listener, resource or global writes, is false. The smallest useful code seam is an MM6-only target-explicit *prepare* step that consumes the already validated `StagedActiveMap`/raw DDM and fills an inert outdoor payload plus detached actor/sprite/chest/decoration collections. It must not call `OutdoorLocation::Initialize/Load`, asset lookup, renderer release, season registration, random spawning or any global `pOutdoor` route. A later commit step must prove no-throw publication of that payload together with the global alias and four collections, register exactly one listener at a controlled point, and define ownership/release of sky, face-texture and minimap handles. Only then could a fault-injected test compare object identity, listener count, asset handles, global collections and map cache before/after a failed first-map entry. The current typed active-map stage is a byte/structure validation result, not this inert fully reconstructed outdoor payload.

### First detached preparation slice

`prepareDetachedOutdoorWorldPlan()` now accepts only an explicit MM6 title and a previously staged outdoor world/visual candidate. It checks saved map name and CHST companion identity, decodes the owned MM6 base bytes into the common `OutdoorLocation_MM7` snapshot, independently decodes the raw active DDM sidecar, and compares model, decoration, PID, spawn and saved/sidecar record counts. It validates each model's vertex/face/texture shape, every used face vertex reference against its own model, a flattened vertex-index bound that fits the inherited `int` offsets, and spawn types accepted by the current runtime. The return object owns the base projection, saved delta, active sidecar and flattened face references. It never constructs `OutdoorLocation`, resolves a texture, registers a listener, changes `pOutdoor`, or touches a process collection.

A synthetic unit case uses a one-model triangle and zeroed MM6 DDM to verify owned geometry and both DDM projections; an invalid face reference injected after staging rejects without changing the earlier result. It also covers foreign title and divergent CHST sidecar. The existing private headless save test calls this plan on its validated New Sorpigal disk-stage result, requiring nonempty models/faces and equal active sidecar bytes. A local aggregate read of all 15 retained private MM6 outdoor bases found no face slot overruns, missing local vertex references or unsupported spawn types under these checks; only aggregate outcomes are recorded here. The linked world-save native suite passed 8/8 and the monitored private save GameTest passed 1/1 with no focus/window change after the first plan integration. The vertex/spawn addition below has syntax compilation; its linked run remains pending.

This is a source-data plan, not a live renderer object. It still lacks texture acquisition and ownership, terrain tile-table projection/normals, face normal repair, decoration descriptor lookup, BSP/encounter runtime reconstruction, listener registration and no-throw commit/rollback of `_outdoor`/`pOutdoor`. The saved DDM and active CHST sidecar can differ in contents while sharing record shape. Do not pass the plan through `loadAndPrepareODM` or open normal MM6 SaveLoad on this evidence alone.

The next pure projection adds flattened `Vec3f` model vertices and bounded runtime `SpawnPoint` values to the same detached plan. Vertex conversion is arithmetic only; after the existing type check, `reconstruct(SpawnPoint_MM7, SpawnPoint*)` writes only its explicit destination. The synthetic triangle now carries nonzero positions and one actor spawn, testing flattened offsets, position/radius/type/monster index and a late invalid spawn type. The private headless save check requires nonempty prepared vertices and matching spawn counts. This still does not prepare actor encounters, treasure RNG, terrain tile lookup, decoration descriptors, face texture handles or any global publication.
