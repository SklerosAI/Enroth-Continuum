# MM6 interface screen audit (F2)

Status: **source inventory and implementation contract, 2026-11-05**. No MM6 screen has been validated beyond the previously observed title/party screens. This packet maps every named screen family in the current C++ enum to an MM6-specific question and a visible acceptance check. Enum coverage is confirmed; original MM6 appearance and behavior remain uncertain until the F3 resource reconciliation and F5 play checks.

## Current screen register

`src/GUI/GUIEnums.h` declares screens 0–28, four special numeric screens (0x63, 0x64, 0x67, 0x68), and debug screen 999. The numeric register is a C++ routing inventory, **not** proof that every screen is used by MM6. Reserved names `SCREEN_6`, `SCREEN_20`, `SCREEN_24`, `SCREEN_19`, `SCREEN_1B`, `SCREEN_63`, `SCREEN_64`, and `SCREEN_67` need call-site classification before they are treated as MM6 content. ## Source-located conflicts and F3 questions

1. **Save menu and finale output:** `UISaveLoad.cpp` uses an MM7-only suffix and `SaveGameLite_MM7`; `GameOver.cpp` uses good/evil MM7 ending selection and the `MM7_Win.Pcx` filename. F4 must branch before loading/writing title state. F3 should identify MM6 ending assets and messages, not infer them from MM7 localization.
2. **Paperdoll and decoration text:** `UICharacter.cpp` has explicit MM6 artifact comments alongside `assert(false)` branches, while `UIGame.cpp` uses a hard-coded MM7 decoration-topic base of 380. F3 should check relevant MM6 item IDs, portrait/paperdoll resources, decoration references and topic ranges against original bytes. These are deterministic source hazards; no live MM6 crash is claimed.
3. **Books and status panels:** F2 has table and event-bit counts but no complete title-aware UI join for quests, autonotes, awards, map annotations or quick-reference formulas. F3 should verify owned table IDs, icons and any executable-only rule leads; F4/F5 must prove the displayed values after state changes.
4. **Reserved IDs and visual layout:** F3 should reconcile resource families (icons, fonts, bitmaps, movies) with named screens and classify missing/unused resources. A live screenshot is required for spatial layout and legibility; source/index name matches do not establish rendering.

This screen matrix is a checklist boundary, not an instruction to reuse MM7 layout. It should be extended with the direct MM6 manual/guide service notes and F3 results before F4 implementation.
