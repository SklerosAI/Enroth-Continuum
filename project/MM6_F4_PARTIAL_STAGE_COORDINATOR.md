# MM6 detached known-save stage coordinator — F4

Status: **offline partial owner stage; no live SaveLoad entry or commit** (2026-11-06).

`stageKnownWorldAndVisuals()` accepts a title-specific `.ec6` byte candidate, the locally verified 67-name manifest, a trusted MM6 base-map reader, a loaded MM6 item-template verifier, current NPC/timer/overlay owners, and the loaded overlay-table size. It first decodes all sixteen currently required sections and checks their cross-field clocks, active-character selection and active map companion. It then decodes every MM6 base/delta pair and verifies nonempty ground and positive chest item template references; the six chest random-item markers remain a separate accepted identity class. The active map's decoded base and delta are retained as an owned, typed indoor or outdoor candidate from that same pass. Only after all 67 pass does it copy-stage NPC records/groups and map buffers, followed by a paused simulation timer and 50 overlays. A failure at any point returns no staged result and assigns no caller-owned state. The caller supplies a trusted source; this function does not read files or select a save slot.

The result deliberately contains the validated `KnownSaveFields` value, the owned typed active-map candidate, and staged NPC/map and timer/overlay copies. This is an intermediate transaction boundary, not a complete session. In particular, it does **not** construct or stage `Party`, check the `HEAD` map against a loaded MM6 table/archive, instantiate the active indoor/outdoor world, rebind overlay PIDs to reconstructed actors/objects, re-create the held-item cursor, clear pending actions, or perform a no-throw global swap. The eight private Character bonus bytes, Lloyd beacons, MM6-keyed shop/bounty state, generated artifacts, movement/flight state and live changed-chest-grid projection remain outside the current transaction. Live `SaveLoad.cpp` must keep rejecting MM6.
