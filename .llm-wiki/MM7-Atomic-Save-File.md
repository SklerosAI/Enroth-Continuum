# MM7 Atomic Save File

An isolated MM7 native-slot helper stages complete bytes beside the destination and retains one valid previous primary as a backup.

The [source](../src/Engine/MM7/MM7AtomicSaveFile.cpp) and [focused tests](../src/Engine/MM7/Tests/MM7AtomicSaveFile_ut.cpp) are integrated in the main tree. The helper requires a caller-supplied full-content validator; its own checks reject unsafe slot names, symlinked save paths, oversized files, invalid existing primary or backup files, and backup-only overwrite. Read-only preflight can return a valid backup without repairing the slot. Writes sync temporary file contents, sync the newly created `saves` directory entry through the profile root, rotate the validated primary to `.bak`, replace the primary, and sync the saves directory. A failure after primary rename remains an uncertain result.

Seven synthetic, isolated test bodies passed under network denial, including overwrite rotation, read-only backup selection, corrupt candidates, unsafe paths, and faults before and after replacement. The normal [MM7 SaveLoad](MM7-Disposable-Save-Reload.md) and menu paths still use the inherited writer. Claude's MM6 Save/Load lane has since merged, but the MM7 helper has not been connected to those shared paths. It does not yet make live saves atomic or prevent the existing corrupt-body load crash. Full semantic validation, admission of the native root into SaveLoad, capture-side effects, visible save/reload, and a restore decision remain open.

The integrated startup context hands the resolved MM7 user path to the atomic helper after the user filesystem is initialized. A read-only optional accessor yields a canonical absolute native directory only while it remains valid. RAM and other-title starts clear the context; a relative path or direct root symlink is refused, and a removed directory or symlink replacement stops being returned. Canonicalization permits a legitimate symlink ancestor such as macOS `/var`. A native disposable writer test failed when only the startup handoff was omitted, then its writer and fresh-process reader passed with the handoff; ten MM7 atomic/root tests and the MM6 startup control passed under network denial. On the combined source, the full MM6 first-map gate passed all 25 child checks and the full MM7 headless suite passed 474 tests with 2 skipped out of 476. The context still has pathname race limits; it does not connect production SaveLoad or claim live atomic writes.

A later integrated candidate adds [bounded structural preflight](../src/Engine/MM7/MM7SaveValidation.cpp) for native-save framing, decompression, map deltas and PCX payloads, plus selected inventory, sprite, actor and door references. It bounds Party alignment, arena state, character class, sex, portrait/voice, spellbook page and quick spell, active beacon map indices, and selected actor monster/name/hostility IDs. Thirteen initial focused tests, a disposable fresh-save writer and reader, and an earlier 25-test MM7 GameTest batch passed under network denial; four PCX decoder units passed. The preflight remains detached from production loading.

Fresh saves can contain stale item IDs in unreferenced chest records. The shared [chest reconstruction guard](../src/Engine/Snapshots/EntitySnapshots.cpp) now drops invalid raw IDs while preserving valid random-loot markers, and checks oversized active grid references before indexing an item record. A synthetic MM7 chest unit, the MM6 first-map chest route and a fresh disposable MM7 writer/reader passed. The integrated branch also passed the full MM6 first-map chain, all three retry faults, paperdoll and normal Save/Load children, and MM7 control. The detached preflight still omits other semantic owners, archive identity and legacy-save compatibility. It is not ready to serve as the atomic helper's production validator. Claude's MM6 production load lane still owns the shared SaveLoad seam.

A later bound checks the held item, active shop and guild stock cells, and actor carried/loot item slots that reach the item table. It skips unused MM7 shop houses, weapon and armor tail slots, and the actor item slot without a saved loot read. Two synthetic cases failed before the change, then the 22-test validator/atomic batch and fresh disposable writer/reader passed. The preflight now accepts a malformed thumbnail, which the load menu tolerates, and ignores malformed images in inactive beacon slots; a fresh-save mutation test failed for each before the correction and passed after it. This is compatibility with the current source behavior, not proof for every legacy save or mod-opened unused house. Production loading remains unwired.
