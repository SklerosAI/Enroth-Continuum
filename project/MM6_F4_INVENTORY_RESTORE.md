# MM6 `.ec6` character inventory staging — F4 offline progress

Status: **checked nonempty inventory staging on a party copy, 2026-11-06; live SaveLoad remains disabled**.

The retained MM6 `items.txt` contains 580 numbered rows. The offline [footprint check](../scripts/mm6_f4_check_item_footprints.py) found 578 usable item icons and two blank placeholder rows; every usable retained PNG yields a footprint within the 14×9 character grid under the exact `GetSizeInInventorySlots` formula. This uses the retained, ignored F3-matched installation snapshot, not another original-installation read. At runtime, `ItemTable::InitializeMm6` reads the MM6 item rows, and `LoadItemSizes` derives slot sizes from the current title's `icons.lod` image headers. For MM6, a preflight now requires every nonempty template icon name to exist in that LOD before writing any item footprint. A missing icon causes a startup error that identifies the numeric item ID rather than silently assigning 1×1. The two empty placeholder templates retain their existing handling. An icon changed by a private mod is accepted only if its new footprint still fits the saved placement.

The inventory container now offers `tryRestoreAt` for a checked explicit record index, grid position or equipment slot. It rejects invalid indexes, duplicate occupied records, overlapping/out-of-grid footprints and occupied equipment slots before calling the existing placement primitives. The explicit index matters because ordinary `add`/`equip` chooses the first free record, which could shift references after a save load. Existing add/equip behavior is unchanged.

`stageDurableParty` first validates the whole title-tagged `.ec6` container and the durable sections, and requires the active engine title to be MM6. It copies the party, applies quest/award/event bits and condition clocks to that copy, then clears and rebuilds each copied character inventory at its saved indexes. Each item is reconstructed from the logical `.ec6` fields without using MM7 item-category predicates. It requires a loaded MM6 item table and a nonempty template icon name, checks the supported shipped item and enchantment ranges, and rejects any failed placement. A failed stage does not change the caller's party. The earlier `stageDurablePartyWithoutItems` remains available for narrow fixtures and still rejects nonempty item sections. This copy-stage path cannot recover native MM6 bytes omitted by the provisional `ITEM` v1 schema; see the [raw item authority decision](MM6_F4_RAW_ITEM_AUTHORITY.md).

Offline checks: the footprint script passed against the retained private extract, reporting 578 usable icons, two blank rows and a maximum 4×9-slot footprint. The icon guard and inventory unit cases passed in the integrated arm64 unit target. A complete party stage with actual gameplay inventory has not been run. No MM6 game was launched.

The icon preflight checks presence, not the rendered result of private mods; F5 still needs visual and save/reload checks. The title's item-use and category consumers still need MM6 semantics. All other `.ec6` families, atomic writes, slot UI and graphical save/quit/relaunch/load remain separate F4/F5 gates.
