# MM6 offline implementation build graph (draft)

Status: **[F3 gate accepted](MM6_F3_GATE_REVIEW.md); F4 offline implementation in progress, 2026-11-06**. This graph turns the [MM6 implementation checklist](MM6_IMPLEMENTATION_CHECKLIST.md) and focused packets into ordered code seams for the full offline MM6 build. The installed MM7 app, MM7 source worktree and its saves remain the protected control case; MM8 remains a separate reserved title.

The implementation should use the retained ignored reference set and private F3 reconciliation report. A module is ready for integration only when its active MM6 IDs/records have a typed path, malformed/unknown handling, a title-isolation check and a focused offline scenario. A title screen, successful archive parse or compile does not satisfy F4.

The ordering is a dependency graph, not eight mandatory serial coding teams. Resource readers and title IDs unblock world, rules and presentation work in parallel; event execution needs the MM6 model and world state; `.ec6` needs stable runtime fields; the integrated scenario harness is the final offline join. Use separate agent-owned branches/files for concurrent implementation, with one integrator owning shared dispatch and the checklist. Do not merge a half-implemented MM6 path into the MM7 runtime or install a new Atlas helper during an intermediate seam.
