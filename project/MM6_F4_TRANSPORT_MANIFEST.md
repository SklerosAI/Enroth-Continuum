# MM6 transport constants — private F4 manifest

Status: **F3-derived private descriptor consumed by a guarded MM6 menu; departure remains disabled** (2026-11-06). The MM7 `Transport.cpp` static schedule and house-index array are not MM6 rules. Six MM6 stable IDs fall outside that inherited array. The MM6 branch never indexes those tables.

Update, 2026-11-07: **the menu described below is never built for MM6.** `createHouseUI` sends every MM6 house to the MM6 house screen ([`MM6House.cpp`](../src/GUI/UI/Houses/MM6House.cpp)), which lists no transport routes, so the MM6 branch of `Transport.cpp` and `selectTransportMenu` have no reachable caller. The manifest and its loader are unchanged. Building the MM6 transport menu waits on the [transition wiring](MM6_TRANSITION_WIRING_PLAN.md).

`scripts/mm6_f4_export_transport_rules.py` reads only the ignored, corrected F3 PE v2 report after checking its SHA-256 against the F3 gate hash registry. It writes a mode-0600 `rules/transport.json` under the MM6 user profile and refuses overwrite. No executable bytes, route constants, destination names or asset inventories are copied into Git. The exporter checked **36 travel descriptors**, **21 houses × three slots**, and **37 populated source cells**. It retains original one-based Games LOD destination indices for `MapTable::GetMM6TransportMapInfo`, seven executable weekday flags, duration, arrival position/yaw and quest-bit candidate. Blank slots remain marked blank rather than treated as valid travel just because the executable index table has a value.

The 37 populated cells comprise 34 regular schedule candidates, one weekday-token ambiguity and two opaque specials. The manifest marks these categories explicitly. The static executable mask agrees with the retained regular weekday text in 33 of 34 cases; the remaining regular mismatch and two guide-duration disagreements remain F5 policy checks. The `S` token has a Saturday-consistent static reading, not observed behavior. Fare, quest gating and the one indoor destination need runtime verification. The UI must leave special cells disabled until their original effect is established.

The MM6 transport path now lazily loads `rules/transport.json` from the private user filesystem, validates 36 route and 21 house records, and renders three scheduled choices using the checked one-based Games LOD map lookup. The ambiguous weekday and two special slots remain hidden. Nonzero quest-bit candidates remain hidden until the gating semantics are verified. Selecting a displayed option does not charge gold, move the party or autosave; it reports that travel is unavailable. This explicit guard also prevents the inherited MM7 departure path from handling MM6 IDs. Two focused native tests cover all houses, slot categories, weekdays and quest predicates, plus corrupt manifest rejection. The integrated 31-test MM6-focused suite passed.
