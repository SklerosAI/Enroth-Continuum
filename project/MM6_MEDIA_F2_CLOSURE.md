# MM6 presentation and media F2 closure packet

Status: **source and retained-index audit, 2026-11-05; no MM6 playback or complete UI verified**. This packet supplements [MM6_MEDIA_UI_SPEC.md](MM6_MEDIA_UI_SPEC.md). It uses the retained ignored indexes and current C++ source, not a new read of original VID/SND archives or a launch of the partial MM6 game. Exact resource names, potential voice sound IDs, source hashes and absence lists stay in ignored `local-game-data/mm6/research-2026-11-05/media-consumer-probe.json` and `media-reference-probe.json`.

## Reproducible source/index check

`scripts/mm6_probe_media_consumers.py` joins the retained MM6 icon index and `dsounds.bin` IDs to the inherited portrait, creation icon, font and reaction-sound code. It confirms:

- The current party-creation screen requests nine class icons, of which five have names in the retained MM6 icon index. Across its 19 distinct literal icon requests, 13 names are present. Its 38 generated arrow names are all present.
- None of the inherited first-frame names for the 22 offered portraits is in that retained icon index. None of the 1,232 inherited 22-by-56 runtime portrait-frame names is present either. This is a **name-index mismatch** in the retained four-archive reference set, not proof that the original MM6 installation has no usable portraits or that a different archive cannot supply them.
- All 12 distinct literal `LoadFont` requests found in C++ have matching retained MM6 font entries. Two of the 14 retained font entries have no literal `LoadFont` call. The older width-only font still needs a title-specific use or an explicit unused classification; presence does not prove rendered text is correct.
- The inherited reaction code has 41 nonzero speech-variant IDs and generates 1,424 *possible* sound IDs for the 22 voice slots offered by the current creation screen. Only 513 of those possible IDs occur in the retained MM6 `dsounds.bin` table. The other 911 are a source/table mismatch upper-bound check, not a count of reactions a real MM6 party would trigger. The correct MM6 voice set and variant logic remain unknown.

The probe validates the inherited table widths and source formulas before making these counts and writes exact details only locally. It does not decode pictures, hear samples, or establish active original MM6 resources. Use the owner's manual PDF pp. 17–26 and reference card pp. 2–5 as UI behavior/layout targets, then verify the actual shipped images and sound behavior in F3/F5.

## Boundaries before implementation lock

1. The F2 media map remains incomplete for dynamic icon names, paper-doll pieces, face/voice metadata and exact MM6 house movie descriptors. The new probe closes only the inherited literal/constructed name comparison above.
2. F3 must check the owner's original VID/SND directories and any separate face archive once in the consolidated preflight. If the retained indexes normalized names or missed a resource family, correct the private report and public conclusion before code is frozen.
3. F4 should make media routing data-driven by title and fail clearly on missing required names or ambiguous duplicate IDs, while preserving MM7's verified path. Cover all active references offline before F5.
4. F5 needs direct visual and audible observations: first-frame portraits and expressions, all six class choices, house video/background, opening/loss/ending, map music, voice reactions, spell/house effects and settings. Keep screenshots, audio samples, saves and logs private. The installed Atlas must use the correct title helper/profile in F6.
