# Read-only MM7 atomic save wiring map

Codex review at main `87add3d2e` on 2026-11-08. This is a future integration map after Claude's MM6 Lane B releases the shared save/UI files; no production wiring was changed here.

1. **Native root.** `GameStarter.cpp` resolves the user path and `FileSystemStarter.cpp` chooses native or memory storage. `ufs->displayPath("")` alone does not prove a native profile root. The MM7 atomic helper needs an explicit checked native-root context; RAM GameTests need a separate in-memory path.
2. **Validator.** `MM7AtomicSaveFile` uses the same complete, side-effect-free byte validator for new data, prior primary/backup, temp readback and read selection. The detached `MM7SaveValidation` candidate checks structure and selected references only. Chest reconstruction, other semantic references, legacy thumbnail compatibility and the selected MM7 Games archive remain open before it can be supplied to the helper.
3. **Write.** In `SaveLoad.cpp`, the normal MM7 `ufs->write` call is the replacement seam. Validate a `saves/<name>.mm7` relative slot and supply the checked native root. The menu's next numbered slot must reserve both primary and `.bak`; manual, quick, auto and new-game save callers should report success only for a confirmed write. `createSaveData` currently mutates live timestamps, items and map deltas before writing, so capture-side rollback or isolation is a separate gate.
4. **Read.** `loadGame` and `UISaveLoad` currently consider only primaries. Listing and QuickLoad need backup-aware deduplication, while read preflight should select valid primary then backup without repairing either file. Deserialize into detached state before live publication, and update the last-loaded name only after success. Main-menu, load-slot and game-menu callers must stay in their prior state when neither candidate is valid; a corrupt body must not cause a false load transition or an unhandled process exit.

The atomic helper refuses corrupt prior candidates and backup-only overwrite. An error after primary rename has an indeterminate durable outcome; never report it as confirmed success. Recheck all line locations after Lane B merges. No private game data or saves are included.
