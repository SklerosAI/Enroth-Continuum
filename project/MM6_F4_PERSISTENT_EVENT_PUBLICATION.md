# MM6 v2 persistent event owner handoff

Status, 2026-11-06: test-only fresh-child zero-owner publication and read-only post-map refusal gate. The normal SaveLoad and Atlas routes remain closed.

The accepted MM6 EVT IDs 105–175 use bytes 0–70 of the 200-byte persistent section retained in the active DLV/DDM sidecar. `stagePersistentEventBoundary` already rejects any nonzero byte at 71–199 and gives the inherited generic owner zeroed 75-byte map and 125-byte decoration arrays. The equality of those widths to 200 does not establish a mapping. The map loader stores the decoded delta in `pIndoor->mm6DeltaBytes` or `pOutdoor->mm6DeltaBytes`; `MM6MapByteState` addresses the persistent section 256 bytes from its end. `DoPrepareWorld(true)` performs map reconstruction and then `onMapLoad()`, whose events can change both the sidecar and generic arrays. See [the detached boundary](MM6_F4_PERSISTENT_EVENT_BOUNDARY.md).

`publishFreshChildPersistentEventZeros` validates the detached boundary with its capture check, then assigns only its zero generic owner to an explicit destination. It does not copy raw sidecar bytes into generic arrays or mutate the map. Run it only after staging the selected active DLV/DDM and before `DoPrepareWorld(true)` in a disposable MM6 child. A validation failure leaves the destination unchanged.

`requirePostMapPersistentEvents` reads the reloaded delta sidecar after `DoPrepareWorld(true)` and compares its 200-byte persistent section to the staged 71 proved bytes plus 129 zero bytes. It also requires both generic arrays to remain zero. It is title-locked and does not mutate either owner. Any `OnMapReload` event that legitimately changes a proved byte is conservatively rejected until a versioned replay and save-capture policy is established. This check alone does not verify map identity, whole-delta equality, selected-delta provenance, event trigger lists, Party/world effects, or active VISU identity. Those remain independent fresh-child admission gates.

Two linked synthetic tests passed for zero publication and late refusal on changed proved/unsupported sidecar bytes, generic map/decor writes, wrong title and a short sidecar. No private game bytes are in the tests or Git. A fresh-child v2 coordinator should keep events blocked until it calls both phases with the selected staged boundary and the actual post-map sidecar, then validates every other owner before enabling controls.
