# MM6 item value provenance carrier — F4

Status, 2026-11-06: `Item::mm6RawRecord` is an optional 28-byte source record carried by value through the shared `Item` copy paths. The bounded common-rarity plain/gold and standard-enchanted equipment adapters initialize it from the original MM6 record. Their capture methods require the carrier to equal that original record before writing mapped field changes; a missing or substituted carrier rejects. `Item::Reset()` clears it, and MM7 item reconstruction explicitly clears it before restoring MM7 wire fields.

The carrier addresses one concrete live-owner obstacle: `Inventory::take`, `addAt` and `equipAt`, and the Party cursor operations copy `Item` values. A slot-keyed raw sidecar alone would lose the source record when the item moves. This value field lets a source-backed item retain its record through an inventory-to-inventory or equipped-item copy. It does not track a unique item identity, native clearing of vacated physical records, transfers among all owners, or the exact MM6 save layout. The detached bounded inventory capture still rejects creation/removal and equipment changes, and no live MM6 item producer or SaveLoad path consumes this field yet.

The shared `Item` runtime size changes; the MM7 `Item_MM7` wire struct remains separately defined and its serializer reconstructs without MM6 provenance. Linked item/inventory checks passed **13/13**, the rebuilt non-MM6 unit suite **438/438**, an MM7 headless save/load control **1/1** over 45 monitor samples, and two MM6 loaded-table headless checks **2/2** over 17 samples. Both monitored runs had no on-screen window or focus change. A private local search found no authentic nonzero MM6 save sample, so native record mutation remains unverified.
