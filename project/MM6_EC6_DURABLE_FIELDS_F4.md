# MM6 `.ec6` durable state fields — F4 offline progress

Status: **bounded `QEST`/`EFFT`/`ITEM` v1 codecs and limited staging, 2026-11-06; no live save/load path**.

The existing title-tagged `.ec6` container now has candidate required payloads for three more state families. `QEST` stores the current runtime's 512 party quest bits, 208 autonote bits, four 512-bit award sets and four 512-bit character-event sets without interpreting individual MM6 IDs. `EFFT` stores four sets of nineteen current-runtime condition timestamps. These arrays preserve the current clock values, but do not settle the MM6 event-condition ID mapping or resistance/buff semantics. Each payload has a version byte and exact size; decoded negative condition times are rejected.

`ITEM` stores at most 126 logical item records per character, with original record index, grid position or equipment slot, numeric item ID, potion/gold amounts, enchantment fields, charge fields, flags and expiration time. It rejects duplicate record indexes and equipment slots, invalid locations, out-of-range counts and malformed values. The codec does not call MM7 item type predicates or infer item footprints. This is a **provisional current-runtime logical schema**, not a native MM6 item record. It omits native MM6 raw bytes 26–27, synthesizes an expiration field absent from the original 28-byte record, and presently covers character-held items only. The [raw item authority decision](MM6_F4_RAW_ITEM_AUTHORITY.md) requires a revised byte-preserving final manifest before live admission.

The capture adapter reads these fields from the four-character runtime and requires `GameTitle::MM6`. The decode path validates the whole container and all three payloads into a temporary value before assigning a destination. `stageDurablePartyWithoutItems` remains a narrow bits/conditions fixture that rejects nonempty inventory. The [inventory staging packet](MM6_F4_INVENTORY_RESTORE.md) adds a checked `stageDurableParty` path for nonempty character inventory, using MM6 item icon footprints and explicit record-index placement on a **copy** of the party. It never mutates the caller's party. Neither adapter is wired into `SaveLoad.cpp` or the load UI.

Offline evidence at the original seam: the codec, runtime adapter and new unit source passed C++23 syntax checks under the project compile flags. A compiled standalone harness round-tripped nonzero quest, award, condition and equipped-item logical fields; malformed item count with a valid container checksum and wrong-title signature were rejected without changing the destination. Later integrated unit and private-backed gates have run, most recently 345/345 after adding the raw item value type. These tests validate the current-runtime logical fields, not native MM6 item-byte fidelity. No MM6 game or original installation was opened for this update.

Remaining save fields include MM6 resistance channels, character and party buffs with durations, temporary stat/resistance modifiers, held item, shop/guild stock and refresh state, hirelings and NPC topics, party timers/calendar/rest state, quest ID semantics, overlays/beacons/thumbnail, all 67 map deltas, weather and active map mutations. Nonempty character inventory now has a checked copy-staging path, but it has not passed a live MM6 item/character save cycle. A complete mandatory-section manifest and all-family transaction must precede a live load. Manual/autosave/quicksave still need an atomic writer, backup recovery and slot listing; F5 requires graphical save/quit/relaunch/load with MM7 isolation. See the [whole-save register](MM6_SAVE_FIELD_REGISTER_F2.md).
