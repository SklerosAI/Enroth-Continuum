The [rollback audit](../project/MM6_F4_FIRST_MAP_WORLD_ROLLBACK_AUDIT.md) enumerates owners changed by `loadAndPrepareODM` and `DoPrepareWorld`. The monitored save callback already restores the exact primary/backup slot pair, 67-map cache and CHST owner after failure. It has not run the full outdoor loader.

`ScopedFirstMapWorldCollections` swaps the prior actor, sprite, chest and decoration containers into private storage and exposes empty scratch containers. It restores all four after a late synthetic fault, or keeps the new collections on explicit commit. This is the bounded safe subset. `pOutdoor` itself registers a season listener and owns terrain/resource pointers; Party placement, engine transition/event state, weather/camera/UI/audio and spawn/reload effects also lack a complete rollback. Do not call `loadAndPrepareODM` through the scoped save callback as an atomic transaction until those owners have a staged or snapshot policy and monitored failure tests. Normal MM6 SaveLoad remains guarded.

`ScopedFirstMapPlacementAndEvents` now protects the first-map Party placement/movement fields and local engine transition/event owners. It installs the staged New Sorpigal position and a validated pending destination, swaps local EVT program/strings, and snapshots map/type, engine flags, transient bytes and last-save selection. A late fault test restores them exactly. Persistent event variables, other Party action fields, the outdoor object and resource/UI effects remain outside this scope, so it still does not justify a full loader callback or opening SaveLoad.

The deeper outdoor-object audit found a hard prerequisite before any whole-object swap. `Engine::_outdoor` owns the object and global `pOutdoor` aliases it; the constructor immediately registers a season listener capturing its address and the destructor removes it. `Initialize/Load` releases renderer terrain and the global minimap, acquires minimap/sky image handles, reconstructs decorations/actors/sprites/chests into global collections, and calls global `pOutdoor` for season change even if a different object receives `Load`. Faces and sky carry raw image handles. Thus a speculative `OutdoorLocation` is observable before commit, and a pointer swap would not roll back resource/global effects. The [audit packet](../project/MM6_F4_FIRST_MAP_WORLD_ROLLBACK_AUDIT.md) names the smallest prerequisite: an MM6-only inert, target-explicit prepare from the validated typed active map and DDM into detached geometry plus world collections, followed by a separately proved no-throw publication/listener/asset ownership step. No whole-object rollback helper was added, and the live guard remains closed.

The first part of that prerequisite is implemented as `prepareDetachedOutdoorWorldPlan()`. Given a staged MM6 outdoor candidate, it owns the decoded base snapshot, saved delta, raw active CHST sidecar projection and flattened model face vertex references. It checks map/sidecar identity, model/decorations/spawn/record counts, face-local vertex bounds and runtime-supported spawn types without constructing an `OutdoorLocation` or touching renderer, assets, listener or globals. A synthetic triangle test injects a late invalid face reference and proves the prior detached plan remains intact; the private headless save test also requests a plan for New Sorpigal. A local aggregate read found no topology violations across the 15 retained outdoor bases. The linked world-save suite passed 8/8 and monitored private save GameTest passed 1/1 after this first plan integration. Terrain tile-table projection, texture ownership, BSP/decoration/encounter reconstruction, listener publication, collection handoff and rollback remain open.

The next bounded addition prepares flattened runtime vertex positions and `SpawnPoint` values from that same owned snapshot. The actor/sprite spawn type is checked before the target-only conversion; synthetic data now verifies nonzero vertex positions and one actor spawn's position, radius and monster index, with an invalid-type late fault. The private headless save check also requires nonempty vertices and matched spawn counts. Encounter/treasure execution, decoration descriptors, textures, terrain projection and global publication remain outside this pure plan.
