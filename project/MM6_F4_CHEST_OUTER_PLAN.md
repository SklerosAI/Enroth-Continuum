# MM6 chest outer loop — F4 detached plan

Status: **accepted original-PE source order modeled offline, 2026-11-06**. The plan stages only item IDs, newly generated gold amounts and RNG. It does not change live chests, party artifact state or saves.

The accepted original trace visits exactly 20 chests and 140 item slots per chest. It consumes one `RNG % 100` draw at function entry even when every chest has no random marker. Each negative marker then draws an attempt count from 1–5 and one remapped treasure tier. For tiers 1–6, the saved probability selects empty, gold or ANY for the marker slot; additional attempts search the first empty slot and draw a new probability only if one exists. The last additional probability carries into the **next marker's first attempt**. A tier-seven marker takes a separate direct-artifact branch. This ordering differs from a fresh probability draw per marker.

`mm6::stageChestOuterIds` validates all 20×140 input IDs and the MM6 map level before copying input. It stages the accepted outer draws, uses the earlier title-specific remap and gold rules, and calls caller-supplied detached pickers for ANY and direct artifacts. A missing, invalid or unproved picker result rejects the whole staged result without changing the caller. It does not represent the complete 28-byte item fields, artifact ownership, chest grid or live RNG commit. Its generated-gold amount array covers only gold created in this pass; fixed source item fields remain outside this model.

Five linked native tests cover a marker-free entry draw, two markers sharing the first probability, first-attempt gold, a filled chest stopping before the next probability draw, and malformed/foreign-title rejection. The seeded expectations were derived from the accepted original 15-bit LCG and bounded branch trace; they are not a graphical game observation. The `OpenEnroth_UnitTest` arm64 target linked and all five focused cases passed.
