# MM6 house presentation path

Status: F4 display-only MM6 house route, 2026-11-06. The path is compiled and offline-tested; no MM6 process or house screen has been visually observed.

The accepted 119-room MM6 descriptor includes an `npc_picture` field. The retained F3-matched 557-row house table references 116 room descriptors. Fifty-one of those referenced descriptors have a nonzero picture ID, and every one resolves to an `npc` icon name in the retained MM6 icons directory using the engine's existing minimum-three-digit name convention. One unreferenced descriptor has a candidate icon name absent from the retained index; it is not on a table-backed entry route. The active `SpeakInHouse` ledger contains 282 instructions whose room has a proprietor picture and 389 table-backed instructions whose room does not.

`planHouseEntry` carries an optional title-specific proprietor icon name from the MM6 room descriptor. It never substitutes an MM7 room or NPC ID. The MM6 `enterHouse` branch checks icon metadata and movie payload availability before any inherited house state. A missing icon or movie rejects; a zero picture ID has no proprietor icon request. The display-only window now loads and draws the proprietor icon when one exists.

The validated room's `videoName` reaches the existing title-aware movie loader. For MM6, that path resolves an extensionless Smacker entry from exactly one of `Anims1.vid` or `Anims2.vid`; missing or malformed payloads reject before inherited house state. For table-backed entries, `tryOpenHouseMovie` can start the existing house movie loop. If video is disabled or decoding fails, a room with a proprietor icon can still open as a static portrait view; a room with neither display rejects. Blank and terminal plans remain unavailable. The inherited MM7 `pAnimatedRooms` field is not used for the MM6 preview.

The tracked [retained checker](../scripts/mm6_f4_check_house_presentation.py) verifies the private icon index against its frozen media probe hash, the house table against its format-2 probe, and the owner-only room manifest against the house table. It now also checks that the staged owner-local `icons.lod` matches the accepted F3 identity report, whose hash is pinned in the F3 gate registry. It prints aggregates only and runs in the one-command offline gate. A private-backed native test checks each active entry plan's icon name against the retained index and the 282/389 split. A second test reads the staged archive through `LodReader` and decodes all 45 distinct proprietor images referenced by the 557-row house table. Each image has positive dimensions at most 1024 by 1024, and decoded pixel count agrees with its header. This proves the selected icon payloads can be decoded by the existing engine; it does not place them on screen. The arm64 MM6/OpenEnroth/unit targets built and the focused decode test passed. The integrated offline gate passed 183/183 from 57 suites without skips (`/tmp/enroth-mm6-f4-house-icon-decode-offline-final.log`); the general suite passed 438/438 (`/tmp/enroth-mm6-f4-house-icon-decode-general-final.log`).

The MM6-only `GUIWindow_MM6HousePresentation` draws a staged MM6 panel and exit icon and, when available, the decoded proprietor icon. It installs only an exit button. It does not build inherited shop/guild/transport windows, NPC dialogue buttons, stock, payment or travel actions. The `SCREEN_HOUSE` escape route bypasses inherited dialogue and room sound, preserves the active character, unloads movie playback and closes the window. The entry event also skips inherited house-entry sound for MM6. All other titles retain their prior house path.

The owner-local preflight now checks both staged MM6 VID archives against their accepted F3 identity records before native tests read them. The native room test resolves every distinct movie referenced by the 557-row house table through the same `lookupMovieBlob` path as `MPlayer::LoadMovie`, verifies an extensionless Smacker payload, and rejects missing/duplicate names through the existing lookup contract. This proves media routing and payload presence, not movie frame decoding or rendering.

The arm64 MM6/OpenEnroth/unit targets built with this media preflight. The integrated offline gate passed 185/185 tests from 57 suites without skips (`/tmp/enroth-mm6-f4-house-movie-offline.log`), and the general suite passed 438/438 (`/tmp/enroth-mm6-f4-house-movie-general.log`). No MM6 process or original installation was opened.

The display-only path adds a native activation test for all 557 retained MM6 table rows: 526 file-backed rooms can create a presentation state, 31 blank or unused rows reject, terminal IDs 600/601 reject, and MM7 rejects every MM6 presentation request.
