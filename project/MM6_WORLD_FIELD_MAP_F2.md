# MM6 world field map: F2 evidence and gaps

Status: **bounded retained-delta parsing plus source hypotheses, not confirmed runtime semantics** (2026-11-05). The companion report is ignored at `local-game-data/mm6/research-2026-11-05/world-field-probe.json`. It holds per-map fingerprints and counts; this document deliberately includes no map names, decoded rows, or game assets. No original archive was reopened and no partial MM6 runtime was launched. This evidence **corrects the earlier 14×10 delta-grid assertion**, now reflected in `MM6_WORLD_F2_CLOSURE.md`: 14×10 is currently an unproven delta interpretation, not a verified format.

## Delta sections and current consumers

| Region, decoded order | Source-derived mapping and retained evidence | C++ consumer and required MM6 work |
| --- | --- | --- |
| Reset header, 8 bytes | Two 32-bit fields at 0 and 4 are labeled reset count and last reset day. All 67 retained baselines are zero. MM6 lacks the following 32-byte MM7 header extension. | `src/Engine/Graphics/Indoor.cpp` and `Outdoor.cpp` use MM7 delta/respawn paths. Establish MM6 first-entry and timed-reset behavior with nonzero state before translating. |
| Visibility | Indoor 875 bytes; outdoor two 88×11 byte arrays. These lengths are bounded, but bit orientation and persistence rules are not yet confirmed. | `src/Engine/Snapshots/CompositeSnapshots.cpp` reconstructs MM7 visibility. MM6 needs title-specific bit translation and map-view checks after exit/re-entry and reload. |
| Creatures | Little-endian 32-bit count followed by 548-byte records. All 342 retained creature records have nonzero bytes. See offsets below. | `src/Engine/Snapshots/EntitySnapshots.h` defines `Actor_MM7` at 836 bytes; `CompositeSnapshots.cpp` reconstructs MM7 actors. A byte cast or zero-fill would lose MM6 state. |
| Ground objects | Count then 100-byte records; all 348 retained records have nonzero bytes. See offsets below. | `SpriteObject_MM7` is 112 bytes. Convert MM6 fields explicitly, retain unknown bytes, and test pickup/drop and transition persistence. |
| Chests | Count then 4,204-byte records; exactly 20 per map, 1,340 total. The 4-byte header is nonzero in 1,218 records, item region in 360, and both possible grid subregions in **zero** records. See ambiguity below. | `Chest_MM7` has 140 MM7 items and 140 matrix shorts, but MM6 items are 28 bytes, not MM7's 36. MM7's chest display uses its own layout. Implement MM6 chest storage only after distinguishing inventory grid semantics. |
| Indoor doors | Exactly 200 fixed 80-byte records plus a variable array span declared by the paired base-map header. All 10,400 fixed records have nonzero bytes; 42 of 52 maps have nonzero variable-array bytes. Count-derived span equals the header span on every checked map. | `BLVDoor_MM7` is also 80 bytes, but equal width is insufficient proof of equivalent field and pointer meaning. Bound targets, reconstruct links against the MM6 base geometry, and test moving doors after reload. |
| Persistent map region | Exactly 200 bytes, uniformly zero in the shipped baseline. The editor calls this map bits, but its constructor does not actually copy the bytes: it mistakenly reads an integer there into `mapResetCount` and skips 200. Its map-bit getters therefore cannot validate the wire meaning. | `CompositeSnapshots.cpp` maps MM7 event variables through its title-specific schema. Preserve the MM6 200 bytes verbatim until event-variable IDs and nonzero state establish their layout; never assume MM7's 75/125 split. |
| Tail | Exactly 56 bytes, uniformly zero. Editor labels relative offsets 0–7 visit time, 8–19 sky name, 20–23 day attributes, 24–27 and 28–31 fog ranges, 32–35 attributes, 36–39 ceiling, 40–55 remaining bytes. It labels attributes/ceiling as MM8; MM6 semantics are open. | MM7 `MapWeather_MM7` is not a substitute. Preserve all 56 bytes, then validate nonzero weather/time state and save/reload behavior. |

For every count, check `count <= remaining // record_width` before multiplication or allocation, require the exact expected section end, and reject short or extra bytes. For doors, validate each signed count is nonnegative; the eight 16-bit arrays contribute `2 × (vertices + 3×faces + rooms + 3×offsets)` bytes per door. A 32-bit stored offset in a fixed door record is a source-file pointer/offset hypothesis, never a process pointer. Validate references against the paired base-map counts before reconstructing geometry.

| Record | Candidate offsets from the pinned editor | Confidence limit and acceptance |
| --- | --- | --- |

Compare nonzero actor changes after combat, movement, death and reset, then round-trip unknown bytes. |
| Ground object, 100 bytes | Type and object ID 0–3; signed 32-bit position 4–15; 16-bit velocity/facing/sound/flags/sector/age/light fields 16–35; 28-byte contained item 36–63; spell/caster/target fields 64–85; pad 86–87; origin position 88–99. | The editor's MM7 variant inserts an 8-byte timestamp at 64 and is 112 bytes. Its accessor for the 2-byte ID appears to use a 4-byte integer read, so trust the field declaration and bounded wire shape only provisionally. Verify item and projectile behavior before conversion. |
| Chest, 4,204 bytes | Header ID 0–1 and status/flags 2–3; 140 contained 28-byte items 4–3923; undifferentiated 280-byte region 3924–4203. The editor treats 3924–4085 as 81 signed 16-bit grid cells and 4086–4203 as 118 opaque bytes. An alternative 140-cell interpretation uses all 280 bytes. | **Both interpretations fit and both subregions are all zero across 1,340 shipped records.** `dchest.bin` metadata declaring 14×10 does not prove that the delta record uses 140 live cells; the editor's 9×9 model does not prove that the last 118 bytes are reserved. Preserve the entire 280-byte region without reinterpretation until a nonzero chest or controlled original-game change distinguishes them. The first 81 shorts do align immediately after the 140 item records, but contain no discriminating values here. |
| Door, 80 bytes | Attributes 0–3, ID 4–7, trigger timer 8–11, direction 12–23, travel 24–27, opening/closing rates 28–35; eight 32-bit variable-array offsets 36–67; four 16-bit counts 68–75; state 76–77 and pad 78–79. Editor state labels are open 0, closing 1, closed 2, opening 3. | Confirm pointer base, signedness, state values and target references with a changed door. MM7 shares the fixed width but must remain isolated. |

The item-region split is supported by the editor's `ItemContainer` record arithmetic and the observed 4,204-byte chest stride, not by a game-play test. The uniformly zero grid region is precisely why neither 9×9 nor 14×10 can be promoted to established semantics.

**F4 update:** A bounded original-MM6 PE placement trace proved that the **in-memory** chest addresses all 280 final bytes as 140 signed 16-bit grid cells; a subsequent [original save-path trace](MM6_F4_CHEST_GRID_WIRE.md) proves both map families copy the complete 4,204-byte record into serialized delta output. This supersedes the F2 81-cell-plus-tail wire hypothesis. The retained zero-filled grids still provide no changed original-save fixture, and live save/reload remains guarded.

## F3/F4 handoff

At the planned one-time F3 original-data reconciliation, compare these expected widths and offsets with original entry framing and inventory metadata; keep exact bytes, map names, hashes and any changed-state captures private. Record any disagreement before freezing the decoder. F4 must implement a title-tagged MM6 lossless sidecar or dedicated snapshot so untouched actor, item, chest, door, persistent and tail bytes survive decode → runtime mutation → encode. Add strict malformed-input rejection and cross-title rejection before state mutation. F5 should observe moving/dead actors, picked-up objects, opened/looted chests, moving doors, map event flags, weather and timed resets in the graphical game, then save/reload and compare; a byte-exact Python split alone does not establish playability.

The probe result is an **inventory and parse** result. The chest grid, persistent bits, reset state and tail remain **semantic gaps**. This packet leaves the MM7 and reserved MM8 runtimes untouched.
