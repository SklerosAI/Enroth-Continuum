# MM6 map-byte dispatch — F4 evidence boundary

Status: **bounded active-range runtime dispatch, offline verification only, 2026-11-06**. This audit used the F3-matched retained EVT and map reports and public source at fixed revisions. It did not reread the original installation or launch MM6. The 200-byte DDM/DLV section is retained byte-for-byte outside the active range.

## Operation and state decision

[MMExtension's command reference](https://grayface.github.io/mm/ext/ref/) describes `evt.Cmp` as *usually* `Variable >= Value` and gives an MM6 example that increments `MapVar0` until a comparison against four succeeds. It defines Add, Subtract and Set with signed 32-bit operands in `evt.lua`, but does not state MM6 map-byte overflow, underflow or write narrowing. The inherited [MM7 executor](../src/Engine/Evt/EvtVariables.cpp) saturates positive adds at 255, subtracts from a byte without an underflow guard and narrows Set to a byte. That implementation is a comparison target, **not MM6 evidence**. The MM6 command's target selector may also cause repeated map writes if it follows the inherited per-character loop; this must be checked before enabling a title-specific branch.

The F4 interpreter now handles shipped active IDs **105–175** as one map operation per event, using byte indices 0–70 in the current map's validated DDM/DLV sidecar. Compare uses unsigned `>=`; Set, Add and Subtract accept operands 0–255. Add overflow and Subtract underflow raise a title-specific error rather than assert an unproved MM6 wrap or saturation rule. IDs 176–204, negative/out-of-byte operands, and other title-specific variable families remain fail-closed. The live path does not use the inherited MM7 per-character map-variable executor. An offline synthetic test verifies nonzero updates, endpoint IDs, bounds, and preservation of bytes 71–199 and the 56-byte tail. The [private-report verifier](../scripts/mm6_verify_map_byte_dispatch.py) confirms all 1,240 F3-matched shipped map-variable operands lie inside these bounds, but cannot prove that a particular in-game sequence never reaches overflow or underflow.

This dispatch is **provisional**, because the first-75-byte address mapping and `>=` relation are strong source-backed candidates, not a direct MM6 executable trace. It mutates the retained in-memory sidecar; changed-state encoding, map leave/re-entry, timed reset, save/reload, and a live campaign remain separate F4/F5 obligations. Exact behavior for IDs 176–204 and out-of-range arithmetic still needs executable or changed-state evidence. A synthetic mutation tests our codec and bounds; it cannot by itself establish the original game's rule.
