# MM6 award table and display boundary

Status: bounded F4 text loader, 2026-11-06. This packet uses the F3-matched retained `awards.txt` copy and current C++ consumers; it does not establish the original award display order or a live MM6 screen.

The shipped table has 100 unique numbered rows in the range 1–100. Eighty-six have nonempty text, and every priority cell is blank. The inherited MM7 loader skipped every row because it required a priority value. `initializeAwards` now receives the game title. For MM6 it validates the complete row set and widths, rejects duplicates, out-of-range IDs and any nonempty priority, then replaces the award table only after all rows pass. Text is preserved under its numeric ID; priority remains the neutral zero storage value. MM7 retains its prior parser.

This enables award text lookup and the existing event/character award-bit consumers to find the nonempty MM6 entries. It does not prove the MM6 award event semantics, color, order or formatting. The inherited character award pane uses MM7 numeric counters for some IDs. Seven nonempty MM6 rows contain formatting tokens whose corresponding counters have not been mapped. The MM6 pane excludes these rows, and its string formatter has a second guard, so they cannot enter inherited MM7 formatting. Other nonempty rows remain available, with provisional equal-priority sorting and color. A later title-specific display model must resolve all seven counters and the actual priority/order policy before F5 acceptance.

The native tests cover a complete synthetic table, transactional rejection of missing rows and invented priorities, the MM7 priority path, and the F3-matched retained 100-row source. The private test checks the aggregate 86 nonempty and seven deferred-format rows without recording text in Git. Exact source fingerprints and per-ID evidence stay in ignored local data. No original installation or MM6 process was opened for this change.
