# MM6 F4 changed chest-grid wire

Status: **original-executable save-path proof and detached synthetic round-trip, 2026-11-06; live MM6 load/generation/save guards remain closed**. Exact instruction locations and owner-local data are in the ignored private companion. The accepted F3 staged executable identity was rechecked; the original installation and game were not opened.

The earlier [placement audit](MM6_F4_CHEST_PLACEMENT.md) established an in-memory chest of 4 header bytes, 140 consecutive 28-byte item slots and 140 signed 16-bit grid cells. The remaining question was whether a changed indoor/outdoor delta writes all 280 grid bytes or only an 81-cell prefix. The original map archive writer has two map-type branches; both copy **4,204 bytes per chest** contiguously from the runtime chest array into the map delta buffer. Separate map file-writing paths also pass the runtime chest array with a 4,204-byte record size. There is no field-level split or grid truncation in those bounded copies. Thus the serialized changed-state region after the item slots is **140 little-endian signed grid cells**, including cells 81–139. The pinned editor's 81-cell-plus-tail reading is superseded for this MM6 executable. All 1,340 retained shipped delta chests still have a zero grid, so this conclusion rests on the original executable path rather than a changed original-save sample.

The detached [wire helper](../src/Engine/MM6/MM6ChestGridWire.h) reads or replaces precisely those 140 signed cells in an exact-width MM6 record while preserving the preceding 3,924 bytes. It rejects MM7 and wrong-length records. It intentionally accepts any signed 16-bit cell value for lossless wire preservation; placement semantics and grid consistency are a separate validation step. Three focused native tests passed: nonzero signed cells at both sides of the old 81-cell boundary and at the last cell, malformed/title rejection, and a synthetic changed record retained byte-for-byte through `.ec6` `MAPS` section encode/decode.

A later [bounded runtime projection](MM6_F4_CHEST_RUNTIME_PROJECTION.md) now stages one resolved MM6 record through `ChestInventory`/`Item`, checks exact active-grid and supported-item round trips, and preserves opaque item bytes in a sidecar. Indoor/outdoor snapshot writers now encode changed grids across all 140 signed cells, with active-reference validation. This does **not** prove original-game changed-save equivalence, chest UI interaction or `.ec6` persistence. The global MM6 chest generation guard remains closed. Next work must join all twenty generated records to map reset, live RNG/artifact state and save–quit–load before any live gate change.
