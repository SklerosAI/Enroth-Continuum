# MM6 `.ec6` map-delta fields — F4 offline progress

Status: **bounded `MAPS` v1 section codec; live SaveLoad remains disabled** (2026-11-06).

The `MAPS` section records a name and opaque byte payload for each MM6 `.dlv` or `.ddm` delta. Names are lowercase basenames with no path components; duplicates, empty payloads, more than 67 entries, oversized individual payloads and a section above 32 MiB reject. The title-tagged container checks the section CRC before `loadMapFieldsBeforeMutation` assigns a decoded candidate to its caller. The codec does not interpret proprietary map content or publish it.

This representation accepts either an original archive wrapper or decoded MM6 delta wire. The existing MM6 loaders call `decodeMM6ArchiveEntry`, which accepts both, but the eventual save transaction must validate **each** decoded delta against its base map before replacing `pMapDeltas`. The transaction must also require all 67 expected map names, capture the current map through the bounded indoor/outdoor changed-state encoders, and leave prior map bytes and live state untouched if any validation or write fails. These requirements are not met by the section codec alone.

Focused checks cover synthetic round-trip, duplicate/path/empty rejection, corrupt-container rejection before destination mutation, and a byte-exact 67-delta round-trip from ignored F3-matched decoded fixtures. No original installation or MM6 process was opened for this F4 work. See the [save specification](MM6_SAVE_SPEC.md), [container packet](MM6_EC6_CONTAINER_F4.md) and [F4 build graph](MM6_F4_BUILD_GRAPH.md).

## F3 expected-name lock

`tools/mm6_map_name_manifest.py --research <ignored F3 research directory>` derives a **private**, ignored, mode-0600 `MM6_EC6_MAP_NAME_MANIFEST_F4.json`. It checks the F3 gate hashes for capture, reconciliation and schema signoff, their linked hashes, all 134 signed map rows, the paired 52 indoor and 15 outdoor map deltas, and SHA-256 of every retained decoded delta. It reports only aggregate results. Repeating the command recomputes the evidence and rejects a changed private manifest. `--check-names <JSON array>` additionally validates an offline candidate name set against the private manifest; it also rejects an extra, missing or duplicate name. Neither the manifest nor candidate list belongs in Git.

The C++ `validateExpectedMapNames` and three-argument `loadMapFieldsBeforeMutation` require exactly those 67 expected names, with exact spelling, before assigning a decoded candidate. The caller must load the private manifest through a trusted native profile boundary, verify it against retained F3 evidence or a pinned local digest, and invoke this overload **before any whole-save or live-world mutation**. The two-argument legacy staging helper still checks wire shape only; it is insufficient for whole-save restore. SaveLoad and the known-section assembly remain unwired. Full base-map semantic checks and active-map changed-state capture remain separate required gates.

## Known-save map/base validation seam

`MM6MapSaveValidation` adds an MM6-only pass after decoding all sixteen currently known `.ec6` sections. The caller supplies the verified 67-name private manifest and a reader for the corresponding `.blv`/`.odm` base entries. The pass checks the exact delta set, decodes archive wrappers, parses every base and delta, and returns or assigns a candidate only after all 67 pass. Indoor delta parsing uses its base snapshot to check door-array and record bounds. Outdoor base and delta parsers are separately bounded; a content-level relation between them is not yet established. A missing or malformed base, malformed delta, or name-set difference rejects the entire candidate. The reader is a trusted MM6 content boundary, so it must not be pointed at MM7 or arbitrary filesystem data.

This validates the known-section candidate, not a complete live session. SaveLoad and native-profile integration remain disabled. The runtime must still prove an outdoor base/delta content relation if needed, validate unresolved campaign state, capture the active map, and commit file and live state atomically. The retained offline check parses all 67 base/delta pairs without rereading the original installation.

## Trusted native private source

`PrivateMapSource` accepts an explicit absolute research directory; it is not selected from a user-provided save filename. It reads only seven fixed report/manifest basenames and the 67 validated base-map basenames in the two decoded fixture directories. Each member must be a bounded regular file whose canonical path remains beneath the canonical root; file symlinks and directory escapes fail. The manifest must have no group or other permissions. The reader checks SHA-256 links from the F3 gate through identity, capture, reconciliation, schema signoff and map probe; it checks all 134 signed map rows, the 67 sorted manifest entries, the name-set digest, and each decoded base against its F3 recorded hash when loaded. Private names and hashes remain in ignored data, not source or wiki.

`loadKnownSaveWithPrivateMapsBeforeMutation` constructs this reader, decodes the known `.ec6` sections, and stages only after the exact name and 67 base/delta parsing pass. Failed identity, manifest, path, base or delta checks leave the destination untouched. This is an offline native boundary over retained copies, not the installed game-data or profile loader. A future live adapter must choose a title-specific trusted source, apply the same identity and containment rules, then complete the atomic save/live-world transaction.
