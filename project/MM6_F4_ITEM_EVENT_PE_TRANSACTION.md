The original Subtract dispatcher invokes the item removal for the selected character; party selection invokes it for all four characters. Within one character, it scans the **126 backpack grid cells**, removes a matching grid item first, otherwise removes a matching held cursor item, and otherwise leaves state unchanged. It does not stop the event on a miss. This differs from the inherited MM7 party-wide workaround, which ignores the selector. The current MM6 implementation collects the selected characters, preflights their grid/cursor sources, and applies removals only after the entire selection is valid. It rejects multiple matching backpack items for one character because the precise original slot priority and enchantment-preserving outcome have not been proved. Equipped items are not a Subtract source. For party selection, a held item can be consumed only once, while each character may independently lose one backpack item.

The bounded Add uses a zeroed identified item only if the cursor is empty, the event targets one character and the ID is outside 400–429. `Party::setHoldingItem` then sets the cursor without relocation. The retained 290 Add instructions include **one generated-artifact-band operand** and **one explicit party-selected Add**; these are distinct sites. Thus 288 retained Add sites have eligible static operands/selector, but actual execution also depends on an empty cursor. The 156 Subtract sites have eligible static operands; runtime duplicate backpack matches are guarded. MM6 Set ID 17 remains guarded because it has no active retained use.
