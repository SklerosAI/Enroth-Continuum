# MM6 F3 original-file capture runbook

Status: **bounded capture executed during F3, begun 2026-11-05; [full F3 gate accepted](MM6_F3_GATE_REVIEW.md) on 2026-11-06**. This runbook records the ordered read-only [F3 preflight](MM6_F3_PREFLIGHT_MATRIX.md). The identity and capture helpers ran against the frozen source and ignored derived reports; their outputs remain local and Git ignored. The owner's original data was read without modification.

## Session order

1. In the active MM6 checkout, check the branch, clean source tree, current commit, ignored `local-game-data/mm6/research-2026-11-05/F2_FREEZE_MANIFEST.json`, and the frozen F2 report hashes. Confirm the original extracted MM6 `app` root is separate from the retained reference directory. Use the same root and reference paths for every step; record them only in the private `local-game-data/private-wiki/mm6/F3_PREFLIGHT_REPORT_TEMPLATE.md`.
2. Run `scripts/mm6_f3_identity_preflight.py ORIGINAL_APP_ROOT REFERENCE PRIVATE_IDENTITY_JSON`. It checks the four LODs, two VIDs, SND and executable against the two retained F1 ledgers, plus all 15 soundtrack tracks against `music-manifest.json`. Require 23 matches before moving on. The output path must be new and ignored.
3. Run `scripts/mm6_f3_capture_snapshot.py ORIGINAL_APP_ROOT REFERENCE PRIVATE_IDENTITY_JSON PRIVATE_CAPTURE_JSON`. It repeats the frozen-source and identity gates, reads the eight named inputs and 15 numbered MP3s without modifying them, and writes one private JSON inventory. Require `status: pass` or resolve every recorded discrepancy before treating the retained F2 copies as the same installation.
4. Run `scripts/mm6_f3_pe_tables.py ORIGINAL_APP_ROOT/MM6.exe REFERENCE PRIVATE_IDENTITY_JSON PRIVATE_PE_JSON`. It captures version-sensitive creation, spell, house-movie and opaque transport candidate spans after rehashing the executable. A partial result is retained if one candidate cannot be mapped; adjudicate it without claiming a verified table.
5. In the same planned F3 session, complete every row of the [F3 preflight matrix](MM6_F3_PREFLIGHT_MATRIX.md) and its private template from the captured inventories, retained extracts, original bytes where a targeted schema/spot sample is required, and the PE report. Keep exact members, offsets, per-ID rows, observations and screenshots in the ignored report. Compare each family with the frozen F2 expectation; label confirmed, corrected or an explicit ambiguity with its F4/F5 route. Zero unexplained content gaps is the F3 exit check.

These steps are an ordered session, not a claim that a file can never be read twice. The plan allows a targeted later recheck when evidence warrants one. Do not use a partial MM6 launch as a substitute for F3 content reconciliation, and do not change the MM7 app/profile or the reserved MM8 checkout.

## What the capture helper records

| Original input | Bounded observation in the private capture | Retained comparison and limit |
| --- | --- | --- |
| Four MM6 LODs | Whole-file size/SHA-256, 256-byte header/root metadata, each 32-byte member name, offset, stored length and raw stored SHA-256; duplicate case-insensitive names and declared-root bounds. | Compare whole-file SHA with F1 ledgers and member-name multisets with the four `.entries` indexes. Cross-check the 30 catalog text-table names and `Games.lod` member names against the 134 retained map/delta probe rows. A stored member hash may differ from an extracted or decoded file hash; the capture alone does not validate decompression, a map wire field or image pixels. |
| Two MM6 VIDs | Whole-file identity and all 44-byte name/offset records, each bounded region's stored length/hash, duplicate names and final four bytes as a possible trailer lead. | Compare name multisets with `Anims1.entries` and `Anims2.entries`. The final four bytes are recorded, not interpreted as a proven size trailer. Codec, frame timing and playback remain F3/F5 work. |
| MM6 SND | Whole-file identity and all 52-byte name/offset/stored/declared-decoded-size records with bounded payload hashes. | Compare names with `Audio.entries`. Payload compression, waveform correctness and audible use are not proven by directory bounds. |
| MM6 executable | Whole-file size and F1 SHA-256 only in this helper. | Use the separate guarded PE-table helper for candidate arrays. Original instruction dispatch, class/spell effects and all other code semantics require specific F3 evidence or a named ambiguity. |
| Numbered music files | Size and SHA-256 for all 15 entries in the retained `music-manifest.json`, checked against original `Sounds` files. | This extends the eight-file F1 ledgers and rechecks the soundtrack files that the 67 map rows reference. Hash presence does not prove track selection, decoding, looping or audibility. |

The capture report's exact names, hashes and offsets are **private**. Its console output gives only counts and pass/needs-reconciliation status. It does not write archive members, sounds, movies, executable bytes, raw game tables or guide passages into Git. It refuses an existing output file and a path outside the ignored reference directory. The helper parses one archive at a time; a malformed member is recorded as an inventory problem while other original inputs can still be inspected in that session. If an original file is missing or the soundtrack differs, the private report retains that result and F3 cannot pass on the retained snapshot.
