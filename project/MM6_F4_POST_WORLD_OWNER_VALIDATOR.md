# MM6 v2 post-world owner validator

Status, 2026-11-07: read-only, title-locked validator for the one-shot test hook, with three linked synthetic tests. It is not wired to GameTest or normal SaveLoad and cannot admit game-loop input by itself.

`requireRawV2PostWorldOwnerAgreement` takes a detached `StagedRawSessionFields` selected by native v2 preflight and an explicit view of the **final** map ID/type, MM6 map and item tables, actor/sprite/chest arrays, decoded active delta sidecar, generic persistent arrays and title-local chest state. It checks the loaded map-table name against HEAD, the active indoor/outdoor plan and CHST `.dlv`/`.ddm` name. It re-runs the inactive-VISU policy and the existing post-rebuild actor/sprite slot-anchor check. Those anchors compare counts and source-backed stable fields; equality still does not establish which delta the live loader selected or prove no actor slot was reused.

The validator then runs `requirePostMapPersistentEvents` on the final sidecar and generic arrays. Proved MM6 MapVar bytes 0–70 must equal the staged values; unproved bytes 71–199 and inherited 75/125 generic arrays must remain zero. Legitimate `OnMapReload` writes can therefore cause a conservative refusal until event replay has a versioned title-local policy.

For CHST, the validator first rechecks the saved raw active delta, LCG and artifact ledger against the staged owner. It decodes the twenty original chest records, reconstructs a detached pre-generation chest vector, and reruns the same bounded MM6 chest generation and item projection used by the scoped map-load adapter. It compares the complete expected post-generation sidecar bytes, resulting LCG and artifact flags with the final owners. Each live chest is replayed against its post-generation raw 4,204-byte record through `stageChestRuntimeRecord`, including the 28-byte provenance on occupied items and the 140-cell grid. Chest position is excluded because `UpdateChestPositions` runs before this hook. This check reads final owners without changing them; it requires the process `pItemTable` to be the supplied MM6 table, as the existing chest projection does.

Three linked synthetic tests cover generated outdoor and indoor chest states, a simulated post-load position update, wrong title/map/CHST name, changed generic event bytes, a late chest mutation, wrong chest LCG, changed sidecar tail and an actor-count mismatch. The source objects remain unchanged after refusal. No private game bytes, saves or captures are in Git.

Call this validator from an armed MM6 post-world test callback **after** `DoPrepareWorld(true)` and before timer unpause or `MessageLoopWithWait`. Pass the actual process owners, not copies from before map load. A successful return is only one gate: MM6 NPC static topics/generated records, renderer and cursor images, BEAC/IFOV policy, complete Party/UI/actions and save slot recovery still need separate admission. The existing active VISU prohibition remains in force. A fresh-child failure must abort before input; normal SaveLoad and Atlas Play remain guarded.
