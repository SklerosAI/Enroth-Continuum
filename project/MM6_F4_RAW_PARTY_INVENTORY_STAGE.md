# MM6 `INVR` to detached Party inventory — F4

Status: **bounded raw-to-runtime candidate, not a complete save restore** (2026-11-06). `MM6RawPartyInventoryStage` joins the EC6 v2 `INVR` physical owner to fresh `CharacterInventory` values on a copied `Party`. It does not edit the live Party, open `SaveLoad.cpp` or publish a saved session.

The stage requires explicit MM6 title selection, the active item table and four ready raw inventories. Each referenced 28-byte record must pass the source-typed `PlainItemProjection` or `StandardItemProjection`, occupy its saved record index and grid/equipment placement, and replay byte-exactly through bounded capture. The resulting four inventories have 138 physical record slots. The copy retains unrelated Party fields from its supplied baseline. Capture repeats the projection and overlays edits from the detached Party, rejecting record creation/removal, changed placement, missing raw provenance or an unsupported field change before it returns a new `RawInventoryFields` value.

The synthetic fixture exercises all **21** MM6 `ItemType` values from the title-specific table parser with common-rarity plain records and zero bonus unions, including a source-typed scroll at a numeric ID used for potions by the inherited MM7 snapshot. It also exercises a common armor record with a mapped positive standard bonus. Gold value, wand charges, skipped owner/padding bytes and unreferenced raw records survive stage and capture. These tests describe the supported representation, not a claim that all native saved items are plain or that every item type's use effect is implemented.

The pinned [MMExtension item layout](https://github.com/GrayFace/MMExtension/blob/9d73c0ff0482bd231ea522f752f4fe9b26640925/Scripts/Structs/01%20common%20structs.lua#L503-L529) confirms the 28-byte MM6 structure and category-dependent words. The existing original-executable picker trace supports standard equipment bonus indices and positive strength, and records separate special-bonus writes. Current adapters intentionally reject nonzero potion-power unions, special enchantments and artifact/relic templates because their full MM6 runtime effects and reversible shared-`Item` mapping are unresolved. They also reject missing templates and malformed footprints. This is safer than a partial `Item_MM7` reinterpretation of the source record.

The changed source and test compiled with the current arm64 integration flags. A focused linked harness passed **3/3** new tests covering all four characters and 21 source types, standard armor edit, retained native tails, unsupported late records, foreign title/table, missing carrier and deletion. No private game files were read for this patch; no private rows or saves entered Git. The next gate is verified handling of special and potion unions, artifacts and source-specific item actions, followed by a complete v2 owner transaction and fresh-process reload.
