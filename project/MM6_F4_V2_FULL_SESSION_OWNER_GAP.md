# MM6 v2 full-session owner gap and commit order

Source checkpoint: integration `60ad6f50e`, reconciled after the decoded Party adapters and v2 world/visual stage. This packet describes the gap after `preflightStagedRawSaveSlot()`, `stageRawPartyRepresentedFields()` and `stageRawWorldAndVisuals()`; it does not admit an `.ec6` slot to the game menu or open production SaveLoad.

## What the two joined stages actually own

`preflightStagedRawSaveSlot()` selects a native v2 primary or backup and calls `stageRawTitleOwners()` as its semantic validator ([MM6RawSaveRuntime.cpp](../src/Engine/MM6/MM6RawSaveRuntime.cpp)). The returned `StagedRawTitleOwners` holds the decoded nineteen-section `RawSaveFields`, separately ready physical inventory, raw held-cursor and SHOP/SCLK owners, typed active map and saved actor/sprite/chest counts. The map validator checks all 67 deltas against MM6 bases, active-map/CHST identity and saved record/item bounds ([MM6MapSaveValidation.cpp](../src/Engine/MM6/MM6MapSaveValidation.cpp)). The preflight does not repair disk or assign globals. `stageRawPartyRepresentedFields()` composes core, quest/effect progress, supported raw inventories, `RSTS`, `BUFF`, `HIRE` and `RCVR` on one detached `Party`; it rejects disagreement between saved and staged inventory images. `stageRawWorldAndVisuals()` separately copies NPC/map buffers, timer/overlays and CHST state. Neither publishes a live session.

## Dependency and publication order

1. **Finalize the format and read-only gate.** Define BEAC/IFOV admission and any remaining mandatory fields, then validate the same complete schema in the native writer, primary/backup selector and menu lister. A structurally valid v2 slot is not yet a playable slot. Keep backup repair deferred until the selected full session is accepted.
2. **Stage without live mutation.** Starting from freshly initialized MM6 tables, compose the complete Party plus raw inventory/cursor/shop owners, mutable NPCs, 67 map blobs, timer/overlays, CHST, and saved-map identity. Prepare BEAC CPU images and IFOV base checks if admitted. Reconcile HEAD/PART/TIME and all cross-owner item/PID references. No adapter should consume an unrelated active Party as its implicit baseline.
3. **Prepare the active world and late references.** Both indoor and outdoor v2 slots now produce detached CPU map plans before selection, including bounded indoor door references or outdoor geometry/terrain/spawns. Build the selected live indoor/outdoor map, actors, sprites and all chests from that plan and matching CHST sidecar; prove overlay/PID targets against those final instances. Resolve resource and texture identities before exposing controls. For indoor maps, apply IFOV only after the reconstructed map's `OnMapReload` effects, as its codec contract requires.
4. **Publish to a fresh MM6 child and enter `gameLoop()`.** Assign the complete staged owners, then set paused real-time timer, saved map transition, MM6 title/resource state, load flags and post-load UI/cursor state. `Game::gameLoop()` calls `DoPrepareWorld(true)` and sets the input skip ([Game.cpp](../src/Application/Game.cpp)). If any late world/resource step fails, the dedicated child must exit before becoming interactive; process isolation cannot repair a disk slot or make missing fields harmless. In-game reload must start another child to avoid corrupting a prior live session.
5. **Accept only after observed continuation.** Run a fresh-process save/quit/relaunch/load test through the actual Main Menu Load branch, including map events, two skip gates, movement, visible frame and native disk recovery. The current monitored v1 callback proves this control route only ([handoff audit](MM6_F4_CHILD_PROCESS_GAME_LOOP_HANDOFF.md)); it does not make v2 complete.

The first **detached v2 session-field coordinator** now exists: `preflightStagedRawSessionFields()` selects a primary or backup only after the represented Party, fresh MM6 static NPC tables, NPC/map/timer/CHST fields and HELD/SHOP/SCLK equality succeed on copies. It also prepares checked indoor or outdoor CPU plans from the validated active map before slot selection. Linked synthetic tests prove backup fallback after a late unsupported item union or unusable outdoor tile selectors, with both disk files untouched. It still lacks global NPC topic/dialogue ownership, live cursor/shop/UI publication, full BEAC/IFOV support, final actor/PID identity and live active-world construction; neither plan publishes renderer resources or a live map. The next coordinator revision must close those boundaries before changing `loadGame()` or the MM6 menu; it is not an all-owner commit candidate.
