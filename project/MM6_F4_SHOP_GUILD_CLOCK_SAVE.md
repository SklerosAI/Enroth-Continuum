# MM6 shop and spell-guild refresh clocks in `.ec6`

Status, 2026-11-06: `SCLK` v1 is the eighteenth required section of the **offline partial** `.ec6` candidate. It preserves only source-proven shop and spell-guild refresh deadlines. Stock, ban and bounty state remain unrepresented; live MM6 SaveLoad remains guarded.

The retained original-MM6 PE refresh trace and hash-matched private 557-row `2devents.txt` check prove the active house row key and 64-bit deadline words. Shop rows 1–47 and spell-guild rows 119–140 have nonzero generation intervals in the retained table. The original shop-47 deadline and guild-119 deadline formulas reach the **same physical word**. `ShopGuildClockFields` therefore has 68 unique raw 64-bit slots: 47 shop slots followed by guild rows 120–140, while guild 119 indexes shop slot 47. This models the observed alias without assigning independent values that the original address layout cannot hold. It does not assume native signedness or normalize deadline values.

`SCLK` is one version byte followed by exactly 68 little-endian 64-bit words (545 bytes total). A ready bit is required by capture/encode but is not serialized; a valid decode marks the detached owner ready. Row access rejects keys outside the proved shop and spell-guild intervals. MM6-only capture, decode and copy-stage helpers reject foreign titles and malformed section length/version before caller mutation. The known-session stage returns an owned copy alongside Party and world candidates. `captureKnownShopGuildClockFields()` overlays an explicitly ready title-local owner into an otherwise complete detached candidate. No inherited MM7 `HouseId` array is serialized. Older provisional seventeen-section `.ec6` candidates reject rather than silently losing clocks.

The original stock record addresses also alias at a family edge. The accepted trace proves two shop menu banks and a guild bank, 12-position physical stride and zero-ID display suppression, but it does **not** establish the complete 28-byte stock tuple, purchased-slot clearing, edge-row behavior or a nonzero native `party.bin` round-trip. A title-local stock owner and service writers are still required. The current fork's MM7-indexed shop/guild arrays continue to reject when nonempty; `SCLK` does not bless those arrays as MM6 state. MM6 bounty house keys, target and killed/refresh tuple are unproved, so no bounty field was added. A later schema revision must add stock and bounty only after those joins are demonstrated.

Focused evidence: the retained private table hash matched the accepted matrix; all 47 shop and 22 guild rows matched the proved type intervals and had positive refresh-day tokens. A native standalone `SCLK` suite passed 2/2 cases for boundary alias, nonzero round-trip, foreign-title/row rejection and late truncation without destination mutation. A freshly linked known-save suite passed 8/8, including old seventeen/sixteen-section rejection. Changed translation units syntax compiled with integrated arm64 flags. The parent's clean integrated rebuild is required for the world/new-game suites because `KnownSaveFields` gained a field. No game launch, native save sample or proprietary bytes entered Git.
