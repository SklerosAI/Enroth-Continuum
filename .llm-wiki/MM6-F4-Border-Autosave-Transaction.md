# MM6 F4 Border Autosave Transaction

The [source audit](../project/MM6_F4_BORDER_AUTOSAVE_TRANSACTION.md) defines what must be durable before MM6 can cross an outdoor border.

The current no-write location-change test proves that a loaded first-map session can switch to a second outdoor world and accept bounded input. A one-shot test intercept bypasses the old-map autosave; the old-map cache delta remains unchanged. It does not prove persistence or same-session return. `startMapTransition` and the foot-travel confirmation also call autosave through different paths, while normal MM6 `saveGame` is guarded. The MM7 `autoSave` contract cannot report durable success and its save preparation mutates map/cache state. The existing atomic v5 writer is limited to disposable candidate slots.

The new detached [Party stage](../src/Engine/MM6/MM6OutdoorBorderPrecommit.h) copies the live MM6 Party for a cardinal geometric candidate and clamps only the copy's X/Y coordinates to the original border bounds. It refuses invalid routes, disallowed Party flags, flying and unverified corners. It always reports that a checkpoint cannot be written: archive/terrain agreement, complete active and visited-map owners and a durable write result remain missing. The rebuilt integration unit target passed all 11 focused border checks, including three new precommit cases and eight existing route/eligibility controls.

The [later-outdoor writer](../test/Bin/GameTest/GameTests_MM6V5LaterOutdoorCandidate.cpp) now adds a no-write, in-memory checkpoint probe on a loaded second outdoor map. A synthetic out-of-bounds Party copy becomes an in-bounds old-map copy; source/destination base lookup, exact active-map identity, v5 semantic preflight, live represented owner agreement and unchanged live Party core and disposable slots are checked. Fresh v2 seed, v4 baseline and modified writer each passed 1/1 headlessly. The border candidate was neither written nor reloaded. Terrain safety at the clamped point, visited-map runtime owners and durable-write policy remain open, so the fail-closed checkpoint flag is unchanged.

A detached [visited outdoor runtime owner](../src/Engine/MM6/MM6VisitedOutdoorRuntimeOwner.h) now retains the first map's native delta/chest, actor anchor and runtime, generated NPC rows, sprite and decoration runtime, and event entry from a source-backed v5 preflight. Exact map identity, MAPS/CHST bytes, actor/sprite anchors and base decoration bindings are rechecked. The no-write [location-change fixture](../test/Bin/GameTest/GameTests_MM6LocationChangeLifecycle.cpp) captured it before leaving the first map and revalidated it after the second map loaded; changed native delta, event map and sprite map each refused. Fresh v2 seed, v4 baseline and modified lifecycle processes passed 1/1 each headlessly in a disposable profile. The capsule stays in memory, has no v5 visited-map disk section, and cannot write a checkpoint. An in-session return, fresh-child old-map replay and durable result remain unproved.

The detached [outdoor v6 codec](../src/Engine/MM6/MM6V6OutdoorSaveFields.h) preserves the active v5 26-section payload and adds one required versioned `VIST` section for ordered prior-map capsules. The initial no-write fixture captured the second map just after `PrepareWorld`, before input, because an ordinary later tick made a native ACTR position too narrow to encode. It round-tripped both source-backed map capsules in `VIST`, then encoded the first as visited beside the second's active v5 and decoded it with exact active-v5 byte equivalence. Malformed version, truncation, cross-map identity and active/visited collision refused.

The [disposable outdoor v6 writer](../src/Engine/MM6/MM6AtomicSaveFile.cpp) now restricts writes to one exact owner-only temporary slot and requires a full semantic callback; its read-only preflight uses the same callback. The writer fixture refuses malformed and cross-map owners and injects a pre-primary-rename failure before writing the admitted candidate. A fresh-child fixture then stages the active map with the existing v5 replay, validates the visited map source before publication and after world rebuild, and aborts before input. A fresh five-child chain (v2 seed, v4 baseline, existing v5 control, v6 writer, v6 reader) passed 1/1 in every process. Both v6 processes checked that the pre-existing v5 slot remained byte-identical; the v2/v4 slots stayed unchanged and the disposable profile was removed. The visited owner was never published to the map cache or used for a return. The post-rename durable-result policy and live travel transaction remain open.

A read-only [visited-map return plan](../src/Engine/MM6/MM6VisitedOutdoorReturnPlan.h) now combines the visited native DDM/runtime owners with the **current active-map** global chest LCG and artifact ledger. It requires exact active/visited identities and source base, refuses missing Party arrival, and cannot publish even with a bounded proposed arrival until terrain and rollback are proved. The fresh-child reader staged it before and after rebuilding the active map, checking Party core, global chest owner and old-map cache stayed unchanged. The same five-child disposable chain passed 1/1 per process after this addition. A normal return uses `DoPrepareWorld(false)`, while current test-only EVRT/V3/V5 replay hooks are gated to fresh `DoPrepareWorld(true)` loads; a separate safe return hook is still needed. No old-map world was entered.

A [detached return-arrival stage](../src/Engine/MM6/MM6OutdoorReturnArrival.h) now reads the target ODM through the admitted MM6 `LoadedMapSource` after the exact visited-owner join. It wraps one cardinal border axis, samples the decoded target terrain with the engine's triangle interpolation, and copies position, zero velocity and fall-start height into a detached Party. Wrong map, ineligible Party, invalid geometry, unverified corners and model-floor overlap refuse; no live Party or map owner changes. Focused units passed 3/3, and the fresh-child v6 reader passed in a five-process 1/1-each chain with a synthetic eligible boundary Party and an in-bounds refusal. This supersedes the earlier statement that detached target terrain was wholly unproved. The fixture did not travel back, publish `VIST`, compare a loaded target floor or exercise rollback; `canPublish()` and `canWriteCheckpoint()` remain false.

A [no-write in-session return probe](../src/Engine/MM6/MM6VisitedReturnPreEventProbeForTest.h) now reaches `DoPrepareWorld(false)` with an intercepted return. It compares the loaded target's terrain and full floor result with the source-backed detached arrival, checks target map/timer/pending order and unchanged live Party position, then aborts before Party placement, chest generation, `_461103` and map events. This supersedes the prior missing loaded-floor comparison. The first fixture released its scope before the loading screen finished and correctly fell into the existing chest guard; retaining that one-shot scope through the screen fixed it without changing chest behavior. The scope unit passed 1/1; fresh v2 seed, v4 baseline and return-probe children passed 1/1 each in an owner-only temporary profile. The partial target is abandoned to Main Menu, not rolled back. Visited runtime/chest publication, post-event checks, failure recovery and durable travel remain open.

The [source-order replay audit](../project/MM6_F4_BORDER_AUTOSAVE_TRANSACTION.md) found no safe single `DoPrepareWorld(false)` seam for all visited owners. The active world is released at entry; the target native DDM is consumed by `OutdoorLocation::Initialize` before the post-load probe; EVRT must precede `PrepareDecorations`; actor/sprite/decoration hooks run later and only for fresh loads. The V3 hook also couples generated NPCs to the saved RNG, whereas return must retain the latest global RNG and chest/artifact ledger. The existing return plan's ledger is from the v6 active **snapshot**, and can become stale after further play; this qualifies the earlier “current active-map” wording. A safe return needs a pre-load DDM/EVRT stage, later all-owner agreement and explicit respawn policy, plus an accepted durable checkpoint or verified full rollback. Refusal after world reset currently means abort to Main Menu with input closed. No test-only or production VIST publisher was added; write and publish gates stay false.

The next transaction must capture complete old-map and visited-map owners in a detached snapshot, validate destination and MM6 eligibility, and make the disk write's durable result explicit. Only after accepted persistence may it publish the old-map cache, apply travel effects once and schedule the target. Failed capture or write must leave live Party, time, food, UI and map state unchanged. A post-rename sync error needs an explicit recovery policy because the new primary may already be present.

The current v5 schema has one active-map runtime set. Outdoor v6 now has a test-only disk round trip for active-plus-visited data but no visited-map publication. A future child must return to the old map from the v6 owner and verify all actor, sprite, chest, event and NPC families, plus an in-session return. Invalid/cancelled/flying/corner cases must perform no production write. This remains a design audit: no production MM6 travel save or gameplay admission exists.

The original confirmation trace also establishes conditional rest: any food triggers full rest/heal, insufficient food marks all four characters Weak and adds one no-rest day before food is floored at zero, and zero food skips healing. It refreshes existing Weak timestamps but plays the reaction only for newly Weak characters. It wraps each crossed coordinate and recomputes target ground height. The inherited foot handler heals even with zero food, does not refresh an existing Weak condition, and lacks MM6 coordinate wrapping. Original rejection and separate cancel both clamp coordinates, close travel UI and leave time, food, conditions and map unchanged; the inherited cancel matches those core effects. The source packet records the full transaction order before any live implementation.
