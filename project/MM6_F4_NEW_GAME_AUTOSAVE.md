# MM6 first-map `.ec6` autosave boundary — F4

Status: **offline known-field candidate and native atomic disk path; live new-game SaveLoad guard closed** (2026-11-06).

## Why the first map is blocked

`Game::loop()` completes the MM6 party-creation UI, sets a pending `oute3.odm` transition, then calls `saveNewGame()` **before** `gameLoop()` can load the first map. `saveNewGame()` rejects MM6 at its first statement, so the later New Sorpigal position/map assignment and the inherited `saveGame(true, true, ...)` are unreachable. The generic `saveGame()` and `createSaveData()` also reject MM6 before inherited MM7 `.mm7` serialization. Removing only the top guard would encounter those later guards, and removing all guards would write the wrong title format.

## Bounded offline route

`encodeOfflineNewGameAutosave()` accepts an already detached `KnownSaveFields` seed, the verified 67-name MM6 manifest, an injected reader for default `.dlv`/`.ddm` entries from a trusted MM6 Games archive, a trusted base-map reader and loaded item-template verifier. It requires explicit MM6 title, `oute3.odm` HEAD and `PART` v2 position/fall-start Z both equal to the source-backed 340 before archive reads. It replaces any stale MAPS seed with exactly the 67 default entries, derives the CHST raw sidecar from the decoded first-map default delta, encodes the current eighteen-section `.ec6` candidate, then validates every default delta against its corresponding MM6 base and item references. No map, Party, SaveLoad or global is assigned. The caller must prepare the seed through represented Party/NPC/visual capture adapters; this function does not claim that capture is complete.

`prepareOfflineNewGameSession()` adds a bounded all-represented-owner preflight. It rejects foreign titles, nonempty shop/guild deadline words and party-owned 400–429 artifacts before drawing one port-specific chest seed into a detached title owner. It then builds the 67-map candidate and calls `stageKnownSession()` to validate and copy-stage Party/Character families, NPC/map buffers, active typed map and raw sidecar, timer/overlays, CHST and SCLK. The staged world exposes all 67 detached encoded map buffers that a future `pMapDeltas` handoff would require. `writeAndStageOfflineNewGameAutosave()` performs that entire preflight before its atomic `autosave.ec6` write. Neither function assigns `pMapDeltas`, process chest state, Party, map or timer. The preflight rejects nonempty inherited commerce/beacon owners through the session stage. It does not prove that the caller's seed was freshly captured from every live owner, nor does it establish the final world reconstruction or no-throw live commit.

`captureFirstMapKnownSeed()` now reads the represented Party/Character, NPC, timer and overlay fields from explicit MM6 owners, placing the arrival coordinates on a Party copy before capture. It makes a fresh zeroed SCLK owner and CHST companion identity; MAPS and the seed's LCG are filled only in the later default-archive/port-seed step. `writeAndPublishOfflineNewGameAutosave()` runs the full detached preflight and atomic disk write, allocates its return object before disk mutation, then uses no-throw swaps to install the 67 encoded map buffers and ready CHST title owner into supplied destinations. It returns the prior cache/title values for `rollbackPublishedFirstMapCache()` if first-map entry fails before gameplay resumes. This covers only those two process owners; it does not roll back the disk slot or reconstruct Party/map globals. The helper is not connected to `SaveLoad.cpp` while its MM6 guard is closed.

The newer **test-only** `saveNewGameMM6ScopedForTest()` is a separate MM6 runtime wrapper, deliberately absent from `SaveLoad.cpp` and `Game::loop()`. It checks the current engine title and loaded Party/NPC/timer/overlay/map/item/Games owners before opening the owner-local private F3 map source. It captures the first-map seed, reads default DDM/DLV entries from the loaded MM6 Games LOD, reads hash-checked base maps through the 67-name private manifest, and checks positive item IDs against the loaded table. `runScopedFirstMapEntryForTest()` snapshots both `autosave.ec6` primary and backup bytes, performs the detached preflight, atomic write and cache/CHST publication, then invokes a bounded callback with staged Party and the published cache/title owner. If the callback throws, it swaps the prior cache/title owners back and restores the exact previous primary and backup bytes (or removes a newly created slot) before rethrowing. The callback contract forbids unrelated global mutation. This is not a playable new-game route: a real `DoPrepareWorld` can mutate additional world owners and must receive a broader rollback before the normal MM6 guard can open.

`Game::loop()` reaches `saveNewGame()` before `Outdoor::Load` reconstructs `oute3.odm`, so its default DDM and CHST sidecar must be staged from the trusted MM6 archive first. The chest agent's opt-in map-entry join runs after outdoor loading and requires a ready title owner. A future live route must transfer the preflighted title owner and staged map buffers at a verified lifecycle point and must survive a failed disk write without a half-initialized process owner. The present `SaveLoad.cpp` guard remains closed.

`writeOfflineNewGameAutosave()` performs that full **known-field** validation before calling the existing native atomic writer with fixed `autosave.ec6` under an explicit absolute MM6 profile root. The writer creates and syncs a temporary file, validates readback, and replaces the primary with backup handling. No `.mm7` slot, user filesystem abstraction or MM7 snapshot is used. This is an offline/test API and is not called by `saveNewGame()`.

Three focused native tests passed in a manually linked arm64 binary using the integrated v4 build libraries: an MM6 first-map autosave writes all 67 synthetic defaults and semantically preflights unchanged; MM7 title and wrong first map reject before delta reads or disk mutation; a malformed final default delta rejects after all 67 reads while preserving the previous autosave; and a corrupt primary selects a valid backup without mutation, then recovers the prior bytes. The existing atomic writer's fault-injection suite covers replacement failures separately. No proprietary game assets or MM6 process were opened.

## Before the live route can open

The seed still omits MM6-keyed SHOP/guild/bounty state, active beacon images/map identity, action state, full live chest seed/handoff lifecycle and other fields in the [save transaction checklist](../.llm-wiki/MM6-F4-Save-Transaction-Checklist.md). `PART` v2 now preserves the source-backed fall-start value, but first-frame movement, flight, hazard and pressure-plate behavior have not been checked after a real reload. The detached active-map candidate is not an instantiated world; loaded HEAD/resource identity, PID rebinding and no-throw all-owner commit are open. A real route must capture every mandatory owner, write and recover the native `.ec6` slot, then quit/relaunch/load into the correct rendered map without touching MM7. Keep `saveNewGame()`, `saveGame()`, `createSaveData()` and `loadGame()` guarded for MM6 until that proof exists.
