# MM6 whole-save field register (F2)

Status: **logical state-family inventory and MM7 source comparison, 2026-11-05**. This is an implementation boundary for a new versioned `.ec6` save, not a native `.mm6` layout and not a working writer. It uses current source and the retained map-delta research, without reopening original MM6 files. Exact MM6 in-memory fields and binary widths remain F3/F4 questions. See the [save specification](MM6_SAVE_SPEC.md) for the wire-delta evidence, atomic write policy and negative tests.

## Inherited container and loss points

`SaveGame_MM7` in `src/Engine/Snapshots/CompositeSnapshots.h` contains a header, `Party_MM7`, event timer, overlay list, 501 NPC records, 51 NPC groups, named map deltas, Lloyd beacon images and a thumbnail. `CompositeSnapshots.cpp` writes these into an MM7 LOD with MM7 names/version; `SaveLoad.cpp` constructs that snapshot and always uses MM7 delta types. These are **current fork fields**, not evidence of a native MM6 whole save. The MM6 `.ec6` format must have its own title/version marker and load dispatch before decoding any payload.

The current `loadGame()` changes `_lastLoadedSaveFileName`, cancels a cast, and changes turn/character UI before `SaveGame_MM7` deserialization succeeds. That ordering is unsafe for the planned MM6 wrong-title/corrupt-slot rejection: F4 must parse and validate a temporary state first, then commit it atomically to runtime globals. `createSaveData()` updates `pMapDeltas` in memory before `saveGame()` writes directly to the destination; a failed write can leave memory and disk inconsistent. The [save spec](MM6_SAVE_SPEC.md) already requires temporary-file validation, atomic replacement and prior-save recovery. These are source-level hazards, not observed MM6 data loss.

## F3/F4/F5 handoff

1. **F3 original-data preflight:** verify the retained MM6 map-delta shapes and original resource IDs. Identify whether executable or owned reference evidence settles class/skill/condition/resistance, NPC, shop, quest and timer state meanings. Keep any native-save inspection optional unless import/export becomes a goal. Record unresolved MM6 logical fields with source and acceptance, not assumed MM7 offsets.
2. **F4 implementation:** define `.ec6` version 1 as a bounded, title-tagged logical container. Write a private field manifest matching each actual MM6 runtime field to a section/encoder/decoder and a test. Require default/optional policy and maximum sizes for each section; preserve unknown map-delta bytes. Validate whole-file and section integrity before changing the live session; write via a same-directory temporary file and recoverable replacement. Keep MM7 serializers and paths separate.
3. **F5 graphical verification:** save/quit/relaunch/load after custom creation, a promotion, NPC hire/fire, a quest branch, shop/bank/rest, a changed chest/door/map byte, and a spell travel. Inspect party, inventory, books, map, services and thumbnail on screen. Repeat wrong-title, corrupt, truncated and future-version rejection with the previous valid slot intact; relaunch frozen MM7 with its existing save.

This register satisfies a **state-family inventory**; it does not claim every final `.ec6` field is known. The exact field manifest is part of the F3 reconciliation/F4 design lock. Every family above must remain explicit in the implementation checklist and agent handoff until it passes its own round-trip and visible acceptance.
