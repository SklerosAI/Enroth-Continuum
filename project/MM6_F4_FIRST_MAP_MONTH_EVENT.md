# MM6 first-map month event

Status: bounded F4 event comparison, 2026-11-06. A real click and its visible outcome remain unobserved.

The retained first outdoor EVT has one reachable interaction that starts by comparing raw variable ID 226 against month 6. The first outdoor map has four faces bound to that event ID, so it is an actual map interaction rather than an orphan script. The false branch reports status and exits; the true branch continues to existing quest-bit and character-stat operations. A separate timer checks raw ID 222 (party flying) only after a quest-bit condition; that variable remains guarded. Other first-map blockers, including cross-map saving and chest interaction, are outside this seam.

The [MM6 event editor's variable table](https://github.com/angeld29/mm8leveleditor/blob/master/src/org/gamenet/application/mm8leveleditor/data/mm6/fileFormat/EventFormatMM6.java) labels ID 226 `MONTH_OF_YEAR`. [MMExtension's event-variable reference](https://grayface.github.io/mm/ext/ref/) names it `MonthIs`. A further retained-script sweep found twelve active ID-226 comparisons spanning operands **0–11**. The F3-hash-matched original executable's Compare jump-table branch at `0x43ff21` reads the cached party month word and tests equality with the operand. Its calendar update writes a remainder modulo 12 into that word. The initial one-based interpretation was therefore superseded: this EVT variable is zero-based, even though the displayed calendar uses one-based month names. No original event UI behavior is established by that rule.

`mm6::compareMonthOfYear` checks ID 226, zero-based operand/cache range 0–11, then compares with `Party::uCurrentMonth`. Only MM6 Compare and dialogue-topic Compare dispatch through it, once for the party. The title check leaves MM7's inherited executor intact. MM6 Add, Subtract and Set for ID 226 still fail through the existing title-specific guard; all other unresolved high IDs remain guarded.

Focused offline tests cover the synthetic MM6 record shape, zero-based endpoints 0/11, adjacent false branches and malformed inputs. The earlier integrated arm64 UnitTest passed 3/3 under the superseded one-based rule; the corrected suite requires a linked rerun. A separate headless GameTest executes the parsed synthetic Compare through `EvtInterpreter::executeInstruction` with scoped cached party month, checking true and false branches without loading a world. Its linked run and a real event click remain pending. No proprietary EVT or executable bytes, private disassembly or asset index are included here.
