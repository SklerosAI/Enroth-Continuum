# MM6 world-state save adapter — F4

Status: offline runtime capture/staging adapter, 2026-11-06. The live MM6 `SaveLoad.cpp` guard remains closed.

`MM6WorldSaveRuntime` connects two actual runtime owners to the partial sixteen-section `.ec6` candidate. `captureKnownWorldFields` copies `NPCStats::pNPCData`, `pGroups` and `uNumNewNPCs` into required `RESC`, and copies the 67 `pMapDeltas` buffers into required `MAPS`. The caller must supply the current map's already encoded delta; it replaces the stale buffer for that map. The active `.blv`/`.odm` in `HEAD` determines the exact `.dlv`/`.ddm` companion that must be replaced. The expected-name list must be the private F3-verified 67-name manifest. Missing, extra, duplicate, empty or foreign map entries reject before a candidate is returned. The adapter validates the whole currently known sixteen-section assembly before returning.

`captureKnownWorldFromActiveMap` is the next adapter above that seam. It checks `GameTitle::MM6`, the active indoor/outdoor level type and the `HEAD` map extension; for indoor maps it also requires the loaded `IndoorLocation::filename` to match `HEAD`. It invokes `encodeMM6IndoorChangedState` or `encodeMM6OutdoorChangedState` directly, then overlays the returned decoded delta into the detached 67-map candidate. Those writers preserve opaque MM6 sidecar bytes and reject unsupported changed fields/counts before returning. No inherited MM7 delta serializer, actor compaction, current-location timestamp mutation or `pMapDeltas` assignment occurs.

For outdoors, `DoPrepareWorld` sets `engine->_currentLoadedMapId` before `loadAndPrepareODM`; that loader reads `pMapTable->pInfos[mapid].fileName` and passes the same name to `pOutdoor->Initialize`. The MM6-only `validateOutdoorMapIdentity` now checks the current map ID is bounded, its loaded table name is a unique `.odm` equal to `HEAD`, and the supplied F3-verified 67-name delta manifest contains exactly one `.ddm` companion. The live outdoor branch requires the loaded engine to be MM6 and performs this join **before** encoding its changed state. This removes a mismatched `HEAD`/current-map capture route. `OutdoorLocation` still stores no independent filename, so F5 must verify transition/re-entry and rendered-map identity; this source join is not proof against arbitrary stale object replacement.

`stageKnownWorldFields` decodes the full known candidate, checks its 67 names, and returns detached copies of NPC runtime records/groups and all map buffers. It retains the live `NPCStats` original tables and unrelated fields on the staged copy. Neither function writes `pNPCStats`, `pMapDeltas` or any other global, and neither uses the inherited MM7 serializer. These routines require an explicit `GameTitle::MM6` argument.

The lower-level capture remains useful only with a caller-supplied bounded active delta; the new active-map adapter supplies it directly from the title-specific writer. Before live load, run the [private map/base pass](MM6_EC6_MAP_FIELDS_F4.md) on all 67 entries and verify nonempty ground/chest item templates. The current known-save assembly is partial: party conditions, inventory and stat modifiers have separate codecs but no whole-session stage here; shop stock/refresh and ban clocks, generated artifacts, fine/bounty counters, alignment/movement flags, quick spell, beacons, transient reset policy, timer/overlay commit, NPC generation identity and the final `.ec6` mandatory-section lock remain open. The disk [preflight](MM6_ATOMIC_SAVE_F4.md) can select bytes without recovery, but no code commits a complete party/world/timer transaction or enables menu actions.

The arm64 MM6/MM7/unit targets built, and four focused world-save tests passed. They use nonzero NPC name/fame/group state and nonzero map bytes, prove that the current-map replacement reaches `.ec6` and returns from staging, and check that the original runtime inputs remain unchanged. A synthetic active indoor sidecar passes through the real changed-state writer with nonzero respawn values; the source sidecar and prior map buffer remain unchanged. The new outdoor identity test rejects mismatched or invalid current IDs, wrong `HEAD` extension, missing active companion, duplicate loaded table name and foreign title. Adjacent known-save tests passed 7/7; two map-validation tests passed while the one private fixture was skipped in a direct binary invocation without fixture directories. Outdoor writer selection compiles and is bounded by the existing writer tests, but this adapter has no standalone outdoor runtime success test because `OutdoorLocation` construction requires a running engine; F5 must inspect it. This is an offline adapter result, not save/quit/relaunch/load or campaign proof. No original installation or partial MM6 process was opened.
