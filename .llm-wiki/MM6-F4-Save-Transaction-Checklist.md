# MM6 F4 Save Transaction Checklist

The eighteen-section `.ec6` assembly is an intentionally partial candidate. Its CRC, section set, field bounds, read-only slot inventory and disk replacement do not yet provide a playable save/load path. `SaveLoad.cpp` rejects MM6 before the inherited MM7 serializer or live mutation.

The [new-game autosave seam](MM6-F4-New-Game-Autosave.md) now builds an offline `oute3.odm` candidate from the verified 67-name default-delta source, validates all base/delta pairs and atomically writes `autosave.ec6` in an explicit native MM6 profile. The live `Game::loop()` still reaches the guarded `saveNewGame()` before first-map loading; this offline route does not make the partial seed or its later reload complete.

The [CHST transaction packet](MM6-F4-Chest-EC6-Transaction.md) adds required MM6 chest LCG/artifact state and the decoded active-map raw sidecar. Old seventeen/sixteen-section candidates reject. Detached staging checks the sidecar and active changed-state delta against the same base and returns an owned title state plus sidecar; it does not reconstruct or commit `vChests`. The packet also audits first-map fall, flight and movement fields now represented in `PART` v3, with first-frame validation open.

The [metadata packet](../project/MM6_EC6_METADATA_F4.md) records the transaction ordering and exact remaining runtime owners. Current bounded pieces include detached `Party` field-family adapters, real `NPCStats` and 67-map-buffer capture, the bounded active-map changed-state writer, and a joint simulation `Timer`/50-overlay capture and copy-stage seam. The [partial coordinator](MM6-F4-Partial-Stage-Coordinator.md) validates all 67 base/delta pairs, retains an owned typed candidate for the active indoor or outdoor map, and stages NPC/map and timer/overlay copies. Its session wrapper composes the represented Party/Character adapters on one detached Party. It does not instantiate a live world, rebind overlay PIDs to reconstructed objects, or complete the missing Party fields and global commit.

The load transaction must select a semantically valid primary or backup without disk mutation, decode the **complete** mandatory manifest, validate loaded MM6 resources and all map deltas, stage every owner on copies, then commit only after no stage can throw. Standalone `SHOP` and `BEAC` are recognized by the container but currently rejected by the eighteen-section known-save decoder, as a linked before-mutation fixture confirms. Beacon GPU publication needs checked texture creation and controlled cleanup before it can enter the transaction. Only after a complete commit should the loader restore a recoverable backup or expose the MM6 menu route. The current atomic file writer protects a disk slot, not the simultaneous assignment of `Party`, timer, overlays, NPCs, map buffers and active world. F5 still requires save, quit, relaunch, load and rendered-state checks. No original installation or partial MM6 process is needed for this F4 checklist.

The [action-observation stability audit](MM6-F4-Action-Observation-Stability.md) adds a specific commit gate: the test-only scoped save observes an idle frame once, but its map-entry callback runs after disk/cache/CHST publication and can touch action owners outside rollback. A read-only recheck cannot make a full callback failure atomic. A coordinator-owned no-reentry safe point or complete staged action/UI rollback is required before opening the live route.

The complete live `SHOP`/bounty owner remains blocked. [SCLK](MM6-F4-Shop-Guild-Clock-Save.md) preserves the 68 unique proved refresh deadline words with the shared edge; it does not cover stock, bans or bounty. The detached [physical SHOP section](MM6-F4-Shop-Purchase-Write-Gate.md) retains all 1,440 raw 28-byte records and the last-shop/first-guild alias. Original purchase copies all 28 bytes and clears source bytes 0–24; the [item conversion matrix](MM6-F4-Shop-Item-Record-Conversion-Gate.md) shows why these records cannot yet be represented reversibly by inherited 36-byte `Item_MM7`. The [shared-service refresh model](MM6-F4-Shop-Shared-Edge-Refresh.md) stages stock and clock together, but indirect writers, a nonzero native save, live item projection and MM6 bounty state remain open. The partial coordinator rejects nonempty inherited MM7-indexed commerce state, including zero-ID stock slots with other payload, rather than silently omitting it. Serializing those inherited array ranges would lose MM6 spell guilds and candidate bounty houses. Live house services remain presentation-only.

Cross-map travel through `startMapTransition()` has a separate [autosave dependency](MM6-F4-Shop-Stock-Tuple-and-Autosave.md): it calls `autoSave()` before setting the pending transition, while the MM6 `saveGame()` guard throws before the write-error catch. The complete `.ec6` save route or an explicit proved transition policy is therefore required for that route; keep the guard closed meanwhile.

### `CHAR` v4 raw-bonus boundary

The [core field packet](../project/MM6_EC6_CORE_FIELDS_F4.md) names all eight current `Character` `char` members and their current readers/reset paths. The first four affect attack/damage and two affect maximum HP/SP; the two `*_related` bytes have no active non-reset gameplay reader. `CHAR` v4 explicitly preserves their raw byte values without assigning native MM6 identity or signedness. A standalone four-character codec probe passed high-bit round-trip and truncated-final-byte rejection; the integrated private-backed MM6/LOD suite now passes 327/327 after a clean arm64 rebuild. The original member/consumer and reset/lifetime policy remain open. Live SaveLoad remains guarded.
