# MM6 action-observation stability at save commit — F4

Status, 2026-11-06: **precommit callback boundary in the test seam; no live SaveLoad route**. The MM6-only scoped new-game save now finishes its caller callback and rechecks pending actions before disk or process publication. A real map entry and complete all-owner commit remain unproved.

## Current call order and evidence

1. `saveNewGameMM6ScopedForTest()` checks the live MM6 title and owner pointers, captures spell/target/turn/rest/GUI/movement/delayed-enchant activity, and rejects a non-idle `HELD` cursor plan. It then constructs the private map source, captures a fresh known-field seed and calls `runScopedFirstMapEntryForTest()`.
2. `prepareOfflineNewGameSession()` reads and validates the 67 default deltas and their bases, seeds detached CHST, encodes the known sections and stages a detached session. The scoped wrapper's concrete readers are synchronous archive/file reads and an item-table predicate. There is no explicit `MessageLoopWithWait()` or GUI dispatch in that wrapper before the write. This describes the present test path; it is not a lock or a contract for a future production caller.
3. `runScopedFirstMapEntryForTest()` now invokes `FirstMapEntryProbe` against the staged Party and candidate map/CHST owners **before** snapshotting or writing a disk slot. The MM6 scoped wrapper rechecks pending spell, target, turn, rest, GUI-message, movement and delayed-enchant state after the probe. A rejected action remains queued for normal game handling while the previous disk slot and published cache/CHST stay untouched. The existing disk snapshot/rollback still protects a later writer failure; no caller-controlled callback runs between the final action check and the write-and-swap interval.
4. `Game::gameLoop()` polls platform messages, generates keyboard actions, processes GUI messages and advances simulation as separate steps. `GUIMessageQueue` has current and next-frame queues; spell casting runs after the queue swap. `EngineControlState` prevents its game and control threads from running in parallel, but `EngineControlComponent::swapBuffers()` yields to the control thread and can run a game routine. The current test writer path has no explicit event pump or render handoff after the final check; this is a source observation, not an enforced production no-reentry lock.

## Why a second read is insufficient

The new final recheck catches an action introduced by the bounded precommit probe before publication. It cannot reserve those owners through a later callback that loads and renders a map. The scoped runner therefore has no post-write callback. A production map loader cannot simply be placed after the write: it may mutate world, action and UI owners outside the current rollback snapshot. An epoch counter has the same detect-without-recovery limitation. Read-only observation alone does not make a failure-atomic all-owner transaction.

## Smallest prerequisite

Build the real active world on detached owners before publication, then add a coordinator-owned game-thread save/entry safe point before opening normal MM6 SaveLoad. It must prevent GUI, keyboard, spell, turn, rest and event producers from running until the file and all process owners are committed, including through nested `Present`/event processing, or stage and no-throw restore every action owner and side effect touched after publication. The precommit test seam does neither for arbitrary process globals: its probe must remain detached and pure. A monitored private-data GameTest injected a next-frame GUI action during precommit and passed 1/1, verifying rejection before disk/cache/CHST publication without focus change or visible windows; the linked save/world unit suite passed 14/14. A full-world late-failure test, enforced no-reentry boundary, MM7 control and save–quit–reload verification still block the live guard.
