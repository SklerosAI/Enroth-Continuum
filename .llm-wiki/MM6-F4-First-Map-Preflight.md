# MM6 F4 First Map Preflight

The [first-map month event](MM6-F4-First-Map-Month-Event.md) now has a bounded MM6-only calendar comparison for one interactive branch. Its visible outcome and the separate party-flying timer condition still need an observed game session.

The [party-flying timer comparison](MM6-F4-First-Map-Flying-Event.md) is now backed by a locally checked original executable dispatch. Its downstream spell effect and visible timer outcome remain unverified.

The [public packet](../project/MM6_F4_FIRST_MAP_PREFLIGHT.md) traces new-game startup through the first outdoor loader and records a read-only headless resource preflight.

`Game::loop()` sets `oute3.odm` as the MM6 pending transition and calls guarded `saveNewGame()` before `gameLoop()`. The later `DoPrepareWorld()` path reads map events/strings, dispatches to the outdoor loader, reconstructs the base and a `.ddm` from `pMapDeltas`, and then reaches the still-guarded MM6 chest generator. The test checks the map-table dispatch, base/delta and event resources, the parsed reload-trigger count, minimap icon, one MM6 loading background, and a detached base-map sky field and bitmap. It does not enter the map, execute events or write a save.

The retained MM6 archive has a single full-screen loading background. `fullscreenLoadingResources` selects it only for MM6 and omits MM7's absent progress-strip texture; the MM7 variation and progress lookup remain exact. MM6's later boxed loading view has its background but no `turnhour` animation, so it skips that image rather than indexing an invalid animation ID. The sky rule here was superseded on 2026-11-11. MM6 ignores the base map's sky name and picks the sky from the visit block at the end of the map's delta: `sky01` on a first visit, the stored sky on a same-day revisit, a random `skyNN` otherwise. `mm6::outdoorSky` implements it for every MM6 outdoor map.

The first MM6 map's numeric ID aliases MM7 `MAP_SHOALS`. The inherited MM7 hireling block incorrectly hid follower UI and stopped dialogue, specialties and a spell route. All five consumers now use a title-aware helper: MM6 avoids this MM7 restriction, and MM7 retains it. Any genuine MM6-only restriction needs separate evidence.

The first-map reload program contains sprite changes. MM6 `SetSprite` addresses a zero-based decoration index, while MM7 resolves `uCog`. The MM6 MapSprite record has no MM7 cog field; the inherited setter silently missed its targets. `EvtInterpreter` now applies a bounded index change for MM6 and leaves MM7's cog route intact. The detached preflight checks original reload sprite targets against decoded map-decoration count, and a pure test checks index, visibility, replacement and title isolation. Source: [pinned GrayFace MMExtension MM6 MapSprite and `evt.SetSprite` definition](https://github.com/GrayFace/MMExtension/blob/9d73c0ff0482bd231ea522f752f4fe9b26640925/Scripts/Structs/01%20common%20structs.lua#L1943-L1981). Execution and appearance remain unaccepted until the live map gate opens.

Each reload entry compares a supported MM6 map byte or quest bit before branching to a sprite or facet change. The other reload branch uses MM6 opcode 12 as an outdoor facet texture operation. Current MM6 parsing and interpretation already use model/facet operands and a checked outdoor-face lookup; the MM7 movie path is retained only for MM7. A detached preflight checks branch shape, operand classes, target bounds in decoded first-map models/faces, and bitmap availability. It does not establish which branch fires on a fresh save or how the replacement looks.

A monitored headless map-load attempt reached `SpawnEncounter` and found an MM7-spaced name instead of an MM6 monster identity. MM6 map encounter cells can identify an internal family stem or a variant's displayed name; the retained MM6 text and binary descriptor tables use compact internal rank suffixes and aligned row IDs. `resolveEncounterMonster` now matches a compact internal rank first, then a unique displayed family, and rejects missing/ambiguous identities. `SpawnEncounter` preflights the MM6 descriptor before actor allocation; MM7's string lookup stays intact. The detached first-map test checks both encounter families and all three ranks against loaded stats/descriptors. A later retained map label differs from its unique display-family name only by word spacing; the MM6 display comparison now ignores spaces, with a detached source check. A private full-map label sweep leaves five distinct later-map labels unresolved or ambiguous, so broader encounter acceptance remains gated. No original monster roster is published here.

Two of the five later-map labels collide across multiple displayed monster families; three have no unique internal or display-table match. Fail closed on all five until their original identities are established. The explicit in-memory first-map `loadAndPrepareODM()` headless scenario now passes in the linked arm64 GameTest. It supplies `DoPrepareWorld`'s AI scratch-array precondition, drains nested loading-progress presents with a bounded test-only tick loop, and asserts the outdoor map ID/type, faces and spawnpoints. The host focus/window monitor observed 135 samples with no focus change and no on-screen process window. It does not call the guarded chest generator, execute reload events, render a graphical world frame or write a durable save. One MM6 voice-index warning was nonfatal. A broader `DoPrepareWorld()` scenario remains the next gate.

An isolated full-world GameTest uses a first-map pending transition, ready in-memory CHST state and `ScopedChestMapLoadOptIn` around `DoPrepareWorld()`. It checks the single GUI-window precondition and actor/chest/map state after a bounded loading-present drain. The linked arm64 focused run passed four world/profession tests; the host monitor observed 116 samples, no focus change, no on-screen process window and unchanged frontmost PID. The test checks outdoor map ID/type, cleared transition, nonempty faces/spawns/actors, 20 chests, one remaining GUI window, null native window and release of chest opt-in on the loading thread. A later combined MM6 suite run failed subsequent save and chest tests because world preparation left process-global state changed. Therefore `DISABLED_ScopedFirstOutdoorWorld` is disabled by default and must be run alone in a fresh GameTest process using `--gtest_also_run_disabled_tests --gtest_filter=MM6Headless.DISABLED_ScopedFirstOutdoorWorld`. The isolated rerun passed 1/1, and the normal MM6 suite passed 38/38 in a separate process, including the previously contaminated save and chest tests. Host monitors observed 44 and 1,899 samples respectively, with no focus change or on-screen process window and unchanged frontmost PID. Normal chest and save guards stay closed; this test does not make all world globals transactionally rollback-safe.

The first linked attempt found that the main-menu state owned a second GUI window outside `pGUIWindow_CurrentMenu`; deleting that raw pointer while its owner lived would be unsafe. The fixture now enters the real synthetic New Game transition and pauses at party creation, whose extra window is owned by `pGUIWindow_CurrentMenu` and can be reset by `DoPrepareWorld`. The next monitored attempt reached peasant generation but found an empty profession distribution. MM6 has no `npcdist.txt`; its retained `npcprof.txt` has a Chance field, consistent with the [MMExtension MM6 NPC profession structure](https://grayface.github.io/mm/ext/ref/). A bounded MM6-only parser now loads those weights, skips the nonnumeric terminal profession and rejects malformed, overflowing or zero-total distributions. Sampling uses the MM6 range through the last numeric Chance row; MM7 retains its existing per-map distribution and Hunter endpoint. Copying one MM6 table distribution to every map is a source-backed inference, not original-executable behavior proof. The linked rerun passed. A nonfatal party-creation art lookup warning remains for the presentation pass.

A second disabled fresh-process test, `DISABLED_FirstOutdoorSubsystemStep`, loads portraits and prepares the first map under the same scoped owners, then selects a map-byte reload branch whose target is a bounded `SetSprite`. It sets that byte, forces the decoration to opposite visibility, replays `onMapLoad()` and checks the resulting visibility. It then advances the null-platform timer, runs `onTimer()` and actor AI, queues a turn and forward action, and runs the outdoor input/update subsystem. The linked arm64 run passed 1/1: yaw and position changed, the action queue drained and the transition stayed clear. The monitor observed 123 samples, no focus change, no on-screen process window and unchanged frontmost PID. The parent game thread remains in party creation; this does not claim a `Game::gameLoop()` frame or durable save. A nonfatal sound ID 1453 had an empty table name; [AudioPlayer::loadSoundDataSource](../src/Media/Audio/AudioPlayer.cpp) reports its missing buffer, while the upstream caller and correct MM6 mapping remain open. The separate DrawGUI probe owns HUD rendering evidence.

The normal new-game save transaction must populate `pMapDeltas` before load, and the default chest path remains guarded outside the test scope. The scoped world test proves actor population, not exact actor/item placement or reload-event effects. The [outdoor tile-selector packet](MM6-F4-Outdoor-Tile-Selectors.md) supersedes the earlier tile-zero diagnosis from the hidden render and records the remaining seasonal art gap. HUD, music, first graphical frame and durable save/reload remain unaccepted; graphical play needs the later F5 pass.
