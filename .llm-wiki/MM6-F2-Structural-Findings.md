# MM6 F2 Structural Findings

The current F2 reviews identify concrete MM7-to-MM6 routing gaps, while leaving exact game behavior and the F3 original-file preflight unresolved.

| Area | Confirmed structural finding | Still unproven |
| --- | --- | --- |
| Party and potion UI | MM6 class/skill order and creation rules differ from inherited MM7 tables. The current default includes a Thief; the UI lacks a distinct MM6 Quick Start. Seven starter spellbook literals fall outside the MM6 book band and the inherited bottle ID classifies as an MM6 scroll. Potion UI uses MM7 item categories and an absent Alchemy skill; the retained matrix has no MM6 loader. The guide and table share 25 numeric-result input pairs but disagree on two results. | Exact class starting arrays, legal skills, Quick Start party and items, matrix marker/disputed-result meanings, failure effects, and live creation/use behavior. |
| Spells and spell items | The 99 retained MM6 spell IDs have source-level paths by inherited numeric IDs, but static effect data and dispatch retain MM7 meanings. MM6's 99 scrolls and 99 spellbooks lie outside the corresponding inherited item-kind mapping ranges; four inherited item-target numeric IDs have different MM6 labels. | Spell effects, target classes, mastery/cost/recovery and item learning/casting semantics; label and path presence are not live casting proof. |
| Map state and saves | Retained MM6 deltas have title-specific boundaries. An offline Python probe byte-exactly reassembled all 67 companions and preserved synthetic nonzero sentinels; a field probe bounds actor, item, chest and door records. The chest delta's final 280 bytes have **unresolved grid/tail semantics**: separate 14×10 layout metadata does not prove a 14×10 delta grid, and both candidate splits are zero in all 1,340 baseline chests. Reset, persistent and tail regions are also zero-filled. | Nonzero field meanings, changed-chest evidence, C++ reconstruction/mutation round trips, reset rules, and working versioned MM6 save/reload. Native `.mm6` compatibility is not established. |
| Events and dialogue | All 43 active opcode values are registered structurally across 68 EVT files and 14,477 records. Seven highlighted values conflict with inherited parsing/execution or have no case; variable instructions still execute through MM7 ID meanings. Some labeled NPC topics lack a handler; another 74 references fall inside an inherited teacher-special range. The structural graph and campaign-route probe expose transport-array and inherited finale seams. | Exact opcode operand meanings, Question answer/cancel branches, variable side effects and persistence, intended NPC/travel behavior, quest dependencies and ending reachability. The register and static seams are not gameplay or original-game-defect proof. |
| NPC text | The MM6 initializer leaves a dismissal-text field unset while the dialogue UI reads it. | Which MM6 table supplies the text and whether a player sees blank dismissal dialogue; source inspection alone cannot establish the original behavior. |
| Monsters and combat | Retained monster records have bounded structural coverage, but active attack, projectile, spell and special labels can silently fall through shared MM7 parsers. Family, hostility, resistance and loot paths retain title assumptions or temporary defaults. | MM6-specific taxonomy and behavior; no encounter, damage, projectile, AI or drop has been observed in MM6 play. |
| Media and presentation | Retained movie names and inherited suffix-based lookup disagree; MM7 house descriptors do not map to MM6 video names. A static house-route join finds active MM6 house type labels that the current parser silently falls back to an inherited UI type; some room IDs span different labels. Sound-table alias/missing-name policy and spell sound routing remain unresolved. Installed map music files have been found. | Intended house service and route reachability, raw VID/SND details at F3, MM6-specific mappings, any actual house UI failure, and video/audio playback at F5. |
| Portraits, icons and voices | Inherited portrait-frame names miss the retained four-archive icon index, class-icon names match only partly, and possible inherited voice reaction IDs show table gaps. Literal font requests are indexed. | Actual MM6 face archive, voice mapping, dynamic UI names, rendered frames and audible reactions; a retained-index name gap is not proof of missing original resources. |
| Text-table consumers and awards | A static scan finds direct literal C++ loads for 24 of 30 retained text-table names; a 30-family packet maps immediate parsers/consumers and selected reference-presence joins. All 100 numeric MM6 award rows have an empty priority cell, which the shared loader uses to skip every row. | Correct column semantics, full downstream use, MM6 award ordering/display and whether the six no-literal-load names have indirect consumers or are unused. No live award behavior is established. |

These are **source and retained-index findings**, not implemented fixes. The active MM6 adapter remains unplayable beyond title/party screens. [MM6 implementation checklist](../project/MM6_IMPLEMENTATION_CHECKLIST.md) is the public coverage authority; detailed per-record evidence stays in ignored local reports. Do not infer an item or event is implemented because its table row or instruction parses.
