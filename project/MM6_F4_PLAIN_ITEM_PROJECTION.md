# MM6 plain item projection — F4 bounded adapter

Status, 2026-11-06: a detached `stagePlainItem`/`capturePlainItem` pair projects only plain MM6 records and gold from an exact `ItemRecord28`. The current [bounded character-inventory stage](MM6_F4_BOUNDED_INVENTORY_PROJECTION.md) uses it alongside the standard-equipment view, but no live chest, Party, shop, cursor, ground or normal SaveLoad owner does.

The retained F3-matched MM6 item table assigns source types independently of inherited MM7 numeric ID ranges. MM6 spell scrolls overlap the MM7 potion-ID band; the [existing consumable gate](MM6_F4_POTION_MATRIX.md) already protects live item-on-item use from that collision. The inherited `Item_MM7` snapshot chooses its bonus union by numeric ID, so a successful first-24-byte round trip alone is insufficient evidence of a correct MM6 gameplay view. The pinned [MMExtension item layout](https://github.com/GrayFace/MMExtension/blob/9d73c0ff0482bd231ea522f752f4fe9b26640925/Scripts/Structs/01%20common%20structs.lua#L508-L529) also distinguishes the 28-byte MM6 tail from MM7's added expiration field.

The new adapter takes an explicit MM6 title and `ItemTable`. It requires a loaded item template, an ID in the verified 1–580 range, zero bonus and bonus-strength words, and zero second-bonus word except for source-typed gold. It stages item ID, charges, condition bits, maximum charges and gold amount into `Item`, retaining all 28 original bytes beside that view. Capture rejects changed ID, title, table type or any logical field whose MM6 wire meaning is not yet mapped. It permits changes only to identified/broken condition bits, wand charges and maximum charges, or gold value; all other raw bits remain exact. Body location, owner and skipped tail bytes are never rewritten. A caller cannot bypass the restrictions by constructing a projection directly: capture revalidates its raw source.

Synthetic unit checks cover a source-typed MM6 scroll in the inherited potion range, opaque tail preservation, supported field mutation, gold amount, foreign title and unsupported bonus unions. The focused linked unit selection passed **6/6** across raw item, raw inventory and plain projection cases. A monitored MM6 headless check used the loaded private-backed table to verify a scroll, bottle and gold category and passed **1/1** without a visible window or focus change. No private item rows or raw game bytes are tracked.

Keep the raw record with each active item through inventory transfers and context changes, and replace the inherited chest `Item_MM7` projection where it misclassifies MM6 IDs. Prove nonzero native record mutation and the complete save/reload transaction before admitting any item-bearing section to normal SaveLoad.
